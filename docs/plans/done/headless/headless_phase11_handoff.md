## Where phase 10 left things

- Power `trim` takes `floor` (`warmup`, the default, or `keepMin`; validated in the constructor after `quietWindows`, `keepMin` with `quietWindows` 0 throws before any side effect). With `keepMin` the trim pass puts its own kept rated unpinned generators into `t.back[subnet]` (slots that count for the allowance), so `#trimReeval`'s second-stop loop treats them like restarted ones: lowest-rated first, while `keptW - rating >= max(hist) × margin` and while more than `keepMin` rated unpinned generators stay (`t.kept[s] - t.pinned[s] - n > keepMin`; pinned `keep` slots do not count toward `keepMin`, as in the trim pass). Two fixes from the review landed with it: a kept or restarted generator whose script died now leaves `t.kept[s]` (it was already dropped from the rating), and a stop refused in part puts the stopped slots into the pool as a rating-0 entry, so they restart with the rest instead of staying ghosts. `restopped` counts every stop after the trim (restarted ones again, kept ones under the floor).
- A/B on 1220 (`--hours 0.67 --report-every 5 --standin power=trim,quietWindows=3,floor=keepMin`, each run alone, all on the c652412 scripts): the floor never fired. The trimmed run equals phase 9's trimmed run line for line (TP 672,392, `restarted 7, restopped 3`): the first night's windows peaked at 4,346 W where cutting the 700 W oil generator needs ≤ 3,920 W, and after the day peak the load stayed ≥ 5.0 kW where the smallest cut needs ≤ 4,739 W. A first trimmed run that accidentally carried a parallel session's uncommitted `fluid_routing.py` (`out/ab10_1220_trim_mixedlibs`, not comparable) showed the mechanism: one oil-generator cut in the first night with 39 W of slack, restarted the next window (one flap), and all four day-peak turbines stopped again in the second night, `restarted 12, restopped 8`, no brownout.
- **Determinism**: two real 1220 runs alone are byte-identical (console logs, every metric) and equal phase 9's real run; the trimmed run equals phase 9's trimmed run. The "run-to-run spread" of the phase 9 handoff was the scripts: the run deploys the repo's working-tree `scripts/`, and two commits landed between phase 8 and phase 9. So a TP or credit gap between runs of the same scripts is real. Keep `latest_scripts` identical across a pair (`diff -rq --strip-trailing-cr out/<a>/latest_scripts out/<b>/latest_scripts`); when another session edits `scripts/`, run from a `git worktree` of the commit (junction `internals/` and `.venv/` into it with `cmd //c mklink //J`, unlink with `cmd //c rmdir` before `git worktree remove`; `--libs` alone mixes old libs with new slot scripts and crashed `panel_1`).
- Tests: `test/standins.test.mjs` +4 (floor `keepMin` stop, keepMin floor and restart from the pool; dead kept script leaves the count; default floor never stops a kept one; bad floor and `keepMin` without `quietWindows` throw before any side effect), the phase 9 dead-script test now expects `kept` 2; `scenario.test.mjs` default params; 64 green with `node --test "devtools/simulation/headless/test/*.test.mjs"`.
- Docs: `standins.md` (`trim` row, phase table row 10, design note), `scenarios.md` (`restopped`), `ab_results.md` "Phase 10" and the open row. TODO's headless block has the phase 10 line.

With `reevalTicks` 600 (2.4 planet-hours) the gap never browned out on 1220; a smaller `reevalTicks` with a larger `quietWindows` would react sooner at the same hysteresis length.

Pitfalls that still apply: `pass(t)` counts from the run's start, archive ages use `state.tickCount`; `--only-scripts` pins `keep` and a stand-in skips kept slots; validate params for value before any side effect (the constructor, not `#setup`, for anything that must precede the archive seeds); the watcher does not cover `devtools/`; a group that is off or stood in has a boundary (`GROUPS[g].produces` / `consumes`) and the A/B gaps come from there first, name them in ab_results.md rather than tuning the stand-in; `final_save.json` is the raw state (no `state` wrapper) and is UTF-8; `run.mjs --hours` and `summary` hours are clock hours (36,000 ticks), planet-hours (250 ticks) are the construction and day-cycle unit (1220's load cycle is ~6,000 ticks); a generator's `generated` share is demand, not capacity, and `subnet.consumed` is demand, not served load (the re-evaluation relies on that); the stand-in's `standins:` lines go to the run's stdout, not `console.log`; a run deploys the repo's working-tree `scripts/`, so uncommitted script edits from a parallel session end up in the run.
