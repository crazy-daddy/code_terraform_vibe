## Where phase 9 left things

- Power `trim` takes `quietWindows` (default 0 = phase 8 behaviour, restart only; validated in the constructor with `reevalTicks`, and `quietWindows > 0` with `reevalTicks` 0 throws before any side effect). `#trimReeval` first restarts from `t.pool[subnet]` as before, then, with k > 0, keeps the last k window peaks in `t.hist[subnet]` and stops restarted generators (`t.back[subnet]`, lowest-rated first) again while `keptW - rating >= max(hist) × margin`; a second stop puts the entry back into the pool (sorted by rating). Only restarted generators are candidates: the trim's own kept set is the floor. A restarted generator whose script died on its own is dropped from the kept rating (warned); a refused `script.stop` keeps the entry counted (warned). A partial restart on a multi-slot machine keeps the slots that ran. `summary.standins.trim.restarted` and `.restopped` count generators over the run (`restarted` was a slot count in phase 8), `stopped` is the current count; one `standins: power trim <subnet>: N quiet windows, ... stopped again N (...)` line per second stop, the restart line only when something restarted.
- A/B on 1220 (`--hours 0.67 --report-every 5 --standin power=trim,quietWindows=3`): 4 stopped at the trim, 3 restarted in the first window, stopped again three quiet windows later, all 4 restarted at the 7.0 kW day peak and never stopped again (`margin` 1.25 over a three-window max needs peaks ≤ 4,739 W, the trimmed run's load stayed ≥ 5.0 kW at every later report). No brownout, no warning, ghosts 0 at the end, no speed-up on this save once the day load arrives.
- Run-to-run spread: this pair's real run differs from phase 8's real run at the same ticks (0.25 h generated 4,179 W against 7,004 W, TP at 0.333 h 666,689 against 667,169), as much as the pair's own gap (trim +2,400 TP, +3,000 credits). Wall time per pair differs too (1.53× against 1.72×). Treat 1220 TP and credit gaps under ~3,000 as noise until the source is found (candidates: scripts that read real time through `game_clock.real_seconds_per_hour()` (drone navigation timeouts, the exotic cap), parallel-run CPU contention).
- Tests: `test/standins.test.mjs` +5 (second stop after k quiet windows and restart from the pool again, the floor and the kept rating over the window peaks, a dead script dropped and a refused stop kept, `quietWindows` 1.5 and `quietWindows` with `reevalTicks` 0 throw before any side effect); `scenario.test.mjs` default params; 60 green with `node --test "devtools/simulation/headless/test/*.test.mjs"`.
- Docs: `standins.md` (`trim` row, phase table row 9, design note), `scenarios.md` (summary field, console line), `ab_results.md` "Phase 9". TODO's headless block has the phase 9 line.
- Outputs in `out/ab9_*` (never commit `out/`).

## Open (optional)

1. A second stop of the trim's own kept set: today only restarted generators stop again, so a warm-up during the day peak trims to the day and the night cannot cut further. Symmetric rule: any rated, unpinned generator above `keepMin` is a candidate once `hist` is full. Bounded by the same hysteresis, but changes the phase 7 one-shot semantics (the kept set would shrink below the warm-up sizing); needs its own A/B.
2. The run-to-run spread above: run the real 1220 twice alone (no parallel run) and compare at the same ticks before the next power A/B cites a TP or credit gap.
3. Placement without a builder (design note in `standins.md`), if a logistics-off target ever needs blueprints built.
4. The 0142 `[POWER] Night eval ... shed` lines named in phase 6 did not appear in `ab7_*`, `ab8_*` or `ab9_*` console logs under the default `--log-levels` (`{"*": "debug"}`); phase 6 must have used another level or save. Record `--log-levels` next time a row cites them.

Pitfalls that still apply: `pass(t)` counts from the run's start, archive ages use `state.tickCount`; `--only-scripts` pins `keep` and a stand-in skips kept slots; validate params for value before any side effect (the constructor, not `#setup`, for anything that must precede the archive seeds); the watcher does not cover `devtools/`; a group that is off or stood in has a boundary (`GROUPS[g].produces` / `consumes`) and the A/B gaps come from there first, name them in ab_results.md rather than tuning the stand-in; `final_save.json` is the raw state (no `state` wrapper) and is UTF-8; `run.mjs --hours` and `summary` hours are clock hours (36,000 ticks), planet-hours (250 ticks) are the construction and day-cycle unit (1220's load cycle is ~6,000 ticks); a generator's `generated` share is demand, not capacity, and `subnet.consumed` is demand, not served load (the re-evaluation relies on that); the stand-in's `standins:` lines go to the run's stdout, not `console.log`; two background runs in parallel keep wall times comparable only within the pair.
