- `devtools/simulation/headless/standins/{heater,o2gen,pressure}.py`: the Level-1 scripts; `_feed.py` is prepended to each by `standinSource()` (shared Mk III feed keeper). They follow the game-interpreter rules (`CODE_GUIDES.md`); `ruff.toml` and `pyrightconfig.json` treat that folder as game code (per-file ignores, an execution environment with the stubs). Gates: `.venv/Scripts/python.exe -m ruff check devtools/simulation/headless/standins`, `npx pyright devtools/simulation/headless/standins`.
- `devtools/simulation/headless/test/standin.test.mjs`: fake-sim tests for the slot replacement, the script sources (no `lib/` import, `self` bound) and the guard hysteresis. Run: `node --test "devtools/simulation/headless/test/*.test.mjs"`.
- `summary.standins.standin` = `{scripts, failed, guardOff, pools}` ([scenarios.md](../headless/scenarios.md) Output table).
- A/B against everything-real on the midlate save: every pillar within 0.3 %, see "Phase 1" in [ab_results.md](../headless/ab_results.md). Open: the 0262 pair and `park` in the same table.

Known gaps of the Level-1 heater (accepted for phase 1): no Mk IV rod feed; the stand-in sources land in `final_save.json` (never load it in game); the guard pools every steam tank on the network (the real `lib/power.py` `steam_tanks()` walks the fluid network, which on one grid is the same set); `_feed.py` reroutes a starved Mk III port without the real router's reachability check, blacklist or POI pumps.

## Phase 2: `scale`

Goal: one record per group of identical terraformers with `data.scale = N`, so the AtmosphereSystem, the fluid drain and the power draw do N machines' work in one record and one script. Design facts (read on 2026-10-14 from the decompiled worker, re-check after a game update) are in standins.md, "Terraforming Level 2 (`scale`)"; the plan file's "Terraforming" section has the same with line numbers of the 2026-10-14 worker (`fDe.tick` :203760/:203788/:203815, drain `z7` :203681, draw `v1` :168682, script gate :203736) and the pipe-ledger clamp (`pipeMaxFlowPerGameHour` 2000).

Build order (plan file "Phases", phase 2, and "Delegation"):

0. `cavecrew-investigator` re-verifies the three anchor sites in `internals/terraform_decompiled/simworker/deobfuscated.js` before any code (grep, never read whole): the atmosphere loops, the `ratePerGameHour` drain and the `Ag(e.data.tier ?? 1, ...)` draw. Line numbers above are from the 2026-10-14 build.
1. **`anchors.mjs`** (new, next to `simhost.mjs`): `SCALE_PATTERNS`, three regexes anchored on stable strings only, each required to match exactly once (anchors.md policy):
   - AtmosphereSystem loops: O2 `let _ = Math.min(g, r.co2)`, heat `heatUnits = iV(..., f)`, pressure `r.pressure = iV(r.pressure, d * t)`. Multiply the per-machine contribution by `(<data>.scale ?? 1)`, where the data local is the `let (\w+) = \w+.data;` of the enclosing loop, captured from the match.
   - Fluid drain: `let l = a.ratePerGameHour * o;` followed by `` `${portType}_level` `` within 200 characters; multiply by `(e.data.scale ?? 1)`. The fuel-rod branch (`Kb(r.stacks, ..., 1)`) stays unscaled: documented limitation.
   - Power draw: `return a * Ag(e.data.tier ?? 1, e.data.tierUpgrade ?? 0)` (the function name is minified: anchor on `e.data.tier ?? 1, e.data.tierUpgrade ?? 0`); multiply by `(e.data.scale ?? 1)`. The heater's dynamic `data.power` draw is inside `a`, so it scales too.
   Wire them into `simhost.mjs` like `MACHINE_REVISION` (`patchScale()`): a `features.scale` flag, `[headless] simworker changed: <what>` on zero or several matches, no throw. `node devtools/simulation/headless/anchors.mjs` exits 0 when every pattern matches once. Tests: `patch_scale.test.mjs` on synthetic three-line snippets (never copied worker code: this repo is public), `anchors.test.mjs` against the real worker, skipped without `internals/`. A builder can take `patchScale()` + `anchors.mjs`; grouping and undeploy stay in the main thread.
2. **`standins.mjs` mode `scale`**: params `{perRecord: 10, max: 50, guardTicks, stop, start}` (`max` caps N per group as the plan's A/B uses `scale max=50`). Test: `scale_groups.test.mjs`. Group the terraforming machines by (typeId, `data.tier`, `data.tierUpgrade`, `locationId`, `machineSubnets[id]`, declared port target); keep the member with the highest `*_in_level`; `sim.undeploy()` the others (needs `features.machineRevision`; never splice `state.machines`), drop the returned kits from the Inventory (`stacks.mjs`), set `survivor.data.scale = N`, cap N at `perRecord` per record (several records on different tanks against fluid stall). The survivor keeps one running script: put the Level-1 stand-in into it (reuse `#standinSetup` per survivor) so the steam guard and the setpoint logic carry over. Ghosts = scripts removed (the undeployed members' slots), so the virtual script count holds. If `features.scale` is off, fall back to `standin` and log it (anchors.md rule 2).
3. **Stall warning**: a record whose `*_in_level` stays 0 for 6,000 ticks warns once (`summary.standins.scale.stalled`).
4. **Report**: `summary.standins.scale = {records: {id: N}, undeployed: [...], stalled: [...]}`; add the row to scenarios.md's Output table and move the phase-2 row of standins.md to done.
5. **A/B** (ab_results.md "Open rows"): midlate save, 20 game minutes, real vs `scale max=50`: heat / O2 / pressure within 1 %, `planet.power.consumed` within 1 % at every report, no record's `*_in_level` pinned at 0 (track every record's `*_in_level` and the feeding tanks' levels). `cavecrew-reviewer` on the diff before the run; the run in the background.
6. **Docs** (plan file, phase 2 and 5): standins.md phase row and `Modes` row; scenarios.md Output table; `DESIGN_HISTORY.md` entry (per-record scale, undeploy not delete, no gate patch, stable-string anchors); `dev_workflow.md` §10c step 4 (`anchors.mjs` after a game update); `archive_ipc.md` gets `standin.terraforming` as harness-only.

Risks the plan lists for this phase: binary grid shed with scaled draw (totals match, per-id shed granularity lost); the fluid port cap limits scale per record (clamp and report); `park` and `scale` are exclusive per subsystem and the real `ScriptParking` must not stop a stand-in slot; `machine.undeploy` may refuse (fluids in ports, construction): keep that member real and report it; anchor fragility after a game update (warn and disable).

Pitfalls seen in phase 1 that apply here too:
- `sim.setScript` on a slot whose status is `running` stops and restarts it; an idle slot stays idle. Mirror that: only running members count as "identical".
- The archive key `standin.terraforming` is written at setup and then every `guardTicks`; the heater script polls it every 2 s. A scaled record is a Mk III heater like any other, so nothing changes there.
- The tests use a fake sim (`test/standin.test.mjs` `fakeSim`): extend it with `undeploy` and an `inventory.slots` with kits instead of loading a save.
