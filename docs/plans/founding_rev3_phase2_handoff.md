## Phase 2 scope (decided with the operator 2026-10-21)

Main focus: the base spirals outward; the second outpost looks ahead to the steam outpost. All from in-game data (§11i "Knowledge levels"; biome map and `contact_inference.BIOME_KINDS` are allowed).

1. **`reach_gain` term** (`outpost_sites`, new entry in `WEIGHTS` / `WEIGHTS_EARLY`, about +3): share of known contacts (POIs of any kind, discovered sites) beyond `CONSTRUCTOR_REACH_M` of every current reach point (`ctx["starts"]`) but within it of the candidate's centre, assuming the new outpost hosts a Charging Station (phase 1 guarantees it before drones). Share over the contacts out of reach today (0 when all are reached; no reach points = 0). Counters `grid` (−6/km to the nearest outpost) and `home`, which both pull the second outpost next to the first. Compute in `_finish()` from a bucketed contact list (`ctx["pois"]` already bucketed; add the sites) so the per-anchor cost stays within `FINISH_UNITS`; measure in `tests/test_autoplay_outpost_sites.py` against `ATOMIC_STEP_BUDGET`.
2. **`future` term** (about +3, range `FUTURE_RANGE_M` about 500): for each look-ahead need with a `site_fluid` still at `later` (today `power`/steam; `reactor`/water once `nuclear_ahead()`), closeness `1 − d / FUTURE_RANGE_M` to the best such contact: a discovered thermal site fully, an unknown POI by P(thermal) from `priors()` × the geothermal-biome inference (`infer_kinds()` already types unknown contacts in geothermal as thermal), and with no contact at all the nearest geothermal cell at half value (reuse the phase 1 probe cells: pass them into `read_world()` / `prepare()` as `"geothermal": [(x, y)]`). The bundle's wants need the future fluids: extend `wants()` with `"future": [fluid, ...]` from `lookahead()`'s `later` needs (the planner passes them; `outpost_plan._rank()` has `snap`).
3. **`power` need on a discovered vent**: `lookahead()` requires a *surveyed* steam site (`snap["fluid_sites"]`); accept a discovered site of kind `thermal` too (new snapshot list `thermal_sites` from `journal.discovered_sites`, or extend `fluid_sites()` with unsurveyed thermal rows flagged `surveyed: False`). `_site_ok()` / `near_fluid()` for the host check may keep requiring the surveyed site; the need itself should form earlier so the proposal asks for the survey (`survey: True`).
4. **Replay** both recorded runs: `python devtools/simulation/planner_replay.py` (usage in its `-h`; results format in [planner_rev2_results.md](planner_rev2_results.md)) over `internals/sample_saves/20261007_c5f9ebf` and `20261018_4c29716`. Expected: the second outpost in run 2 moves away from the western iron cluster when no vent is known nearby, toward the east deposit or the geothermal area; with a vent in the north-west it stays. Record a "Revision 3" section in `planner_rev2_results.md` and tune the two weights there.

## Pitfalls

- `check()` reads the biome only with `want_biome` set, so `ctx["biomes"]` is not a full map after ranking; the geothermal cells come from the phase 1 probe, not from the ranking cache.
- `bundle_key()` gives both factory bundles the key `general`, so the second factory proposal inherits the first's rejected-site holds (`REJECT_RADIUS_M`); fine, but a rejected first site is held for the second too.
- `WEIGHTS_EARLY` applies before the first mining drill (`game_phase.drills()`); the second outpost is usually ranked early, so tune the early dict first.
- Score terms sum into `confidence` only for `RESOURCE_TERMS`; keep `reach_gain` and `future` out of the confidence share or a map full of unknown POIs looks "known".
- Session budget: planner-rev2 ate about 12 % of a weekly budget in one session (memory note); keep phase 2 to B + C + replay and hand the `power` need change off if the replay tuning runs long.
