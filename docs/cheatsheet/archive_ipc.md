## 📡 4. Inter-Process Communication & Data Archive

### Signal Bus (`get_component("comms")`)
- **Channel `bio_orders`**: Exchange broadcasts open orders -> Collector adjusts harvest target.
  - Payload: `{"order_id": str, "specimen_id": str, "biome": str, "target_fragment": str, "count": int}`
- **Channel `sample_ready`**: Lab notifies Exchange immediately on sample extraction.
  - Payload: `{"order_id": str, "sample_id": str, "sample_type": str, "lab_id": str}`
- **Channel `system.version_confirmed`**: `status_panel.py` "Confirm New Version" button broadcasts newly-confirmed build hash so every script parked in `validate_game_version()` wakes immediately, no polling — see `lib/version_guard.py` and Data Archive entry below.
- **Channel `biome_processor_heartbeat`**: every biome processor controller fires this unconditionally each cycle so `BioLabController._wait_for_luminizer()`-style waits use `comms.wait_broadcast()`, not polling — see §1f/§1g.

### Data Archive (`get_component("notebook")` / `lib/archive.py`)
**Key convention:** one shared dict per concern `{entity_id: value}` via `archive.transaction()`, never one key per entity — archive has fixed key-count cap (CODE_GUIDES.md#archive). `lib/archive.py`'s `get_entry()`/`set_entry()`/`pop_entry()` read/write one entity's slot (transactions). **Per-machine status dicts** (`{machine_id: {..., tick}}`, the keys in `ArchiveCleaner.STATUS_TICK_KEYS`) are written only through `archive.publish_status(key, name, entry, tick, log, stale_ticks=STATUS_STALE_TICKS)`: it stamps `entry["tick"]`, sets the machine's entry and drops every other entry that is not a dict or is `STATUS_STALE_TICKS` ticks (~1 h) or more behind, in one transaction; warns on a rejected write, logs each dropped id at debug. Readers treat an entry that old as gone. `ArchiveCleaner.clean_status_ticks()` applies the same rule, so entries go even after the last machine of a kind stopped publishing. `stale_ticks=None` skips the age rule. Remaining per-entity keys below (`biomass_mixer.gate.<id>`, per-grid `power.*:<anchor>`) are legacy, pending consolidation (TODO.md). Retired families go in `ArchiveCleaner`'s `RETIRED_KEY_PREFIXES`; only the cleaner deletes leftovers, never former writers.

**Updaters must be pure:** a `transaction()` updater may only compute the new value (mutating a closure list like `claimed = [False]` is fine). Any log/print call inside it gets the whole write rejected — `lib/archive.py`'s wrapper just returns `False`, so it fails silently. Collect messages in a `notes` list and log them after the call; check the return value where a failed write matters (claims, telemetry).
- `power.shedding_tiers`: Custom shedding tiers list-of-lists `[[tier1_machines...], [tier2_machines...], ...]` (or `power.shedding_tiers:<grid_anchor>`). Default `DEFAULT_SHEDDING_TIERS` in `lib/power.py` — see §1a.
- `power.shedded`: Active list of machines Power Guard currently shedded — hard-shed (breaker off) most Tier 1 patterns, soft-shed (production paused, power on) Tier 2 `smelter_*`/`fabricator_*` — see §1a. `SmelterController`/`FabricatorController` own `is_shedded()` checks it to pause production.
- `fleet.status`: one shared telemetry dict `{name: {name, state, x, y, wh, level, target, intent, home, role, tick}}` (drones add `unit`, `engine`) for every ground vehicle AND drone (`lib/fleet_status.py` `publish()`, called by `publish_telemetry()` in `lib/fleet_unit.py` `FleetUnitMixin`, shared by `VehicleController` and `DroneController`; each adds its fields via `_telemetry_extra()`). Unchanged payload re-written only as heartbeat, at most every `FLEET_STATUS_MIN_INTERVAL_TICKS = 50` ticks (~5 s); any changed field writes immediately. `home` = home outpost id (vehicle `home_base`, drone `home_outpost.id`); `role` = job designation (Pioneer: detected `hauler`/`miner`/`scout`/`constructor`; Rover: `rover`; drone: `hauler`/`miner`/`scout`), `None` until detected. Readers: FLEET/DRONE FLEET cards (`role`/`home` and `intent` columns), `drone_haulers_present()` (drone entries only, by `engine`), drone upgrade.
  - `intent`: one line set by the job loops via `set_intent()` (`lib/fleet_intent.py` `describe()`: `"<verb> <item> [+N] [at <site>] [from <src> [+N]] [to <dest>] [for <root>]"`). Cleared by `set_intent(None)` at job end and by any `publish_telemetry()` state in `fleet_status.IDLE_STATES`. Set in: push/pull haul (`vehicle_cargo.py`), drone haul (`drone_hauler.py`), home-demand + stationed mining (`rover.py`, `pioneer.py`, `vehicle_mining.py`), biosite sampling (`drone_mining.py`), construction (`pioneer_construction.py`), survey/scout.
  - `for <root>` (`fleet_intent.haul_root()`): a `logistics.requests` entry at the destination names its `by`; else, for home, `demand_root()` walks recipe inputs (`_recipe_inputs_for()`, depth `ROOT_WALK_DEPTH = 6`) down from each root in order `manual_order` → `blueprint <kind>` → `upgrade <requester>` → `<supply dock id>` → `<requester>` (any request) → `stock_target`, first along items still short of stock, then along any path; unreached raw ore → `ore_buffer`. Stationed outpost mining with no request → `<outpost_id> stock`. Several roots in one load → `"<first> +N"`. The path found is logged at `debug()`. `ArchiveCleaner.clean_telemetry()` deletes legacy per-entity `fleet.status.<id>`/`rover.status.<id>`/`drone.status.<id>` keys and prunes entries of vehicles/drones not in `fleet.vehicles()`/`fleet.drones()`.
- `rover.claims` / `survey.claims` (mirrored, legacy + current key): Atomic target reservation dict `{target_key: {"vehicle": id, "tick": tick}}`. Stale after `CLAIM_STALE_TICKS = 36,000` ticks (1 hr) — see `lib/vehicle_claims.py`. Doesn't exclusivity-gate mineral mining sites: a mine claim is keyed per vehicle, `"<target_key>@<vehicle>"` (see `mining.reserved_yield` below); still exclusive for survey/POI targets (key prefix `"poi_"`) and construction jobs (key prefix `"build_"`, `PioneerController.construction_claim_key()`, see §2a construction-job-claims entry).
- `construction.power_tiles`: power-line ledger `{"surveyed": tick | None, "rows": {"<ty>": [[tx0, tx1], ...]}, "dirty": [[tx, ty], ...]}` (world tile indices, inclusive runs per row). Filled by the one-off autoplay survey, kept current by Pioneers (`note_power_job()`), dirty tiles re-probed by the planner; more than `POWER_DIRTY_MAX = 400` dirty tiles reset `surveyed` to None (full survey) — see autoplay.md §11d.
- `construction.hold`: `{"by", "tick", "kinds": [kind, ...]}`; Pioneers leave jobs of a held kind alone while `tick` is younger than `HOLD_STALE_TICKS = 600`. Written and deleted by the autoplay power survey.
- `construction.priority`: `{blueprint_id: int}` build order for Constructor Pioneers; no entry = 0, lower runs first (plan-ahead jobs from `autoplay/` use 1, an operator may set any int in the Notebook). Written by the autoplay planner or by hand, read and pruned (dead blueprint ids) by `run_construction_loop()` — see §2a construction-job-priority entry.
- `mining.reserved_yield`: Non-exclusive in-flight mining yield dict `{vehicle_name: {"vehicle": id, "target_key": str, "item_id": str, "units": int, "outpost_id": str, "tick": tick}}`, one entry per vehicle's current mine trip (planned trip yield). `vehicle_mining.home_ore_demand()` and `stockpile_headroom()` subtract it per delivery outpost. Older entries keyed by target_key (no `outpost_id`) still count until stale. Stale after `RESERVATION_STALE_TICKS = 36,000` ticks (same window as claims) — see `lib/mining_reservations.py`.
- `survey.unsupported_targets` / `rover.unsupported_targets` (mirrored): Hardware-capability blacklist entries (`reason`, `scanner_type`, `scanner_tier`, `hardness_limit`, unlocked researches) — see `lib/vehicle_claims.py`. Populated per-contact from `SonarScanResult.blocked` (`docs/types/fleet_and_vehicles.md` `BlockedContact`: `.x`/`.y`/`.reason`/`.message`), not from `scan()` top-level `.status` — wide/deep sonar sweep covers several "?" contacts at once, `.status` is one verdict for WHOLE sweep (`"ok"` once any contact in range resolves, even if others stayed blocked), so reading only `.status` silently drops every blocked contact unless nothing resolved. `scan_and_survey()` (`lib/vehicle_survey.py`) iterates `res.blocked`, blacklists each contact by own coords. `VehicleClaimsMixin.clear_unsupported_target()` (called by `vehicle_survey.py`/`vehicle_mining.py` on successful resolution) removes archive entries *and* matching `"unsupported.<target_key>"` Planet Map marker directly via `markers.remove()`, so marker vanishes immediately, not lingering until Control Panel "Sync Unsupported" button (`lib/unsupported_markers.py`) next clicked. **`reason == "wrong_scanner"` (bio contact) special-cased**: permanent hardware mismatch, not research/tier gap — ground vehicles never carry `bio_scanner` (drone-only module, `docs/database/equipment_biosphere.md`), so `can_attempt_target()` never true for it; neither `vehicle_survey.py` nor `vehicle_mining.py` calls `clear_unsupported_target()` for it. Deleting entry once drone resolves it would just let next rover/pioneer sonar sweep over coord re-`blacklist_target()` it (sonar re-reports same "?" contact blocked every sweep in range, regardless of archive state) — so entry deliberately kept forever. Instead `unsupported_markers.clear_wrong_scanner_marker(x, y)` (called by `drone_scout.py` right after successful `bio_scanner.scan()`) removes only stale `"Bio Contact"` marker via `markers.remove()`, blacklist entry intact; `update_unsupported_markers()` sync-button path independently skips (re-)placing marker for any `wrong_scanner` entry whose coord `journal.has_scanned()` reports true, so later button press can't replant. Drones otherwise not in this blacklist/marker family — non-bio-contact resolution uses unrelated `scout.empty_pois` fact cache below, never places map markers.
- `console.log_levels`: `{module_name | "*": level}` lowest level each `TreeConsole(module=...)` writes (`"trace"` < `"debug"` < `"info"` < `"warn"` < `"error"`), see `docs/AI_CHEATSHEET.md` §0a **Log levels**. Seeded `{"*": "debug"}` by the first `TreeConsole` that finds it missing; operator-edited in Notebook, read once per script start.
- `heat.optimal_setpoints`: Caching `{thermal_state: best_power}`
- `pressure.optimal_resonance`: Caching `{resonance_state: best_window}`
- `fabricator.manual_orders`: `{item_id: quantity}` ad-hoc Fabricator build requests, edited directly in Notebook (e.g. `{"drone_small": 2}`) — see §2a-1 item 3. Prioritized over other demanded recipes, counted down to 0 (then dropped) as units delivered.
- `fabricator.manual_transit`: `{item_id: {"units": n, "base": home stock when recorded}}` manual-order units drained from an off-home Fabricator/Fuel Assembler, see §2a-1 item 3. Written by `production.consume_manual_order()`; pruned by `reconcile_manual_transit()` (control_room_automation, before `plan_sites()`) once home stock reaches `base + units` or none of the item is left off home.
- `fluid_routing.pipe_conflicts`: `{router label: {"source", "fluid", "tick"}}`, one entry per port that yielded a pipe conflict (`lib/fluid_routing.py` `yield_pipe_conflict()`), pruned after `CONFLICT_BLACKLIST_TICKS`; read by `control_room_automation.py` for the AUTOMATION card. See §1b step 4.
- `lead_cask.roles`: `{cask_id: "fuel_rod" | "raw_uranium"}` Lead Cask reservations, see §1n. Written by `lead_cask.ensure_rod_cask()` (one `"fuel_rod"` cask per outpost with a Fuel Assembler); operator-editable in Notebook. Casks without an entry take either item. Pruned of gone casks on every write.
- `reactor.fuel` (`lead_cask.REACTOR_FUEL_KEY`): `{reactor_id: {outpost, status, spare, hours, alert, level, tick}}` Reactor fuel state, see §1c-4. Written by each Reactor script (`ReactorController.report_fuel()`); pruned of Reactors no longer on the network on every write. Read by the Status panel's ALERTS.
- `lead_cask.inbound`: `{drone_name: {outpost, units, tick}}` Raw Uranium a plated drone has promised to unload at `outpost` (claimed site's share, then units aboard), see §2j-1. Written by `lead_cask.reserve_inbound()`/`set_inbound()`/`release_inbound()`; entries older than `INBOUND_STALE_TICKS = 36000` ignored and pruned on write.
- `fluid_routing.water_reserve`: `{"hold", "level_t", "floor_t", "tick", "by"}` Reactor water reservation, written by the lowest-id Reactor controller, read by `fluid_routing.water_reserve_holds()`; stale after 1200 ticks. See §1c-4.
- `fluid_routing.tank_assignments`: `{building_id: fluid_id}` operator-designated Liquid/Gas Tank reservations, edited directly in Notebook (e.g. `{"gas_tank_1": "steam", "gas_tank_3":
  "ammonia"}`), same edit convention as `fabricator.manual_orders` (NOT same eligibility convention — see below) — see `lib/fluid_routing.py` `get_tank_assignments()`/`tank_matches_assignment()`/`tank_is_eligible_target()`. `fluid_id` values use exact vocabulary of `building.fluid()`/`production.FLUID_LATCH_IDS` (`"water"`, `"oil"`, `"steam"`, or a biome essence id such as `"frozen_essence"`), no separate taxonomy. Exists because generic tank `.fluid()` latch purely content-based, network-blind (`FluidOutputRouter` otherwise picks candidate tanks by building *type* alone, no notion of which of outpost's several non-merged physical pipe networks candidate sits on — see `docs/guide/infrastructure_and_pipes.md` "Service-footprint contacts stay independent" note) — and same latch clears to `""` instant tank drains to 0, so unrelated router could mistake operator's dedicated oil tank for blank up-for-grabs buffer during empty window, stranding its network. Keyed by stable building id so reservation survives empty window, unlike live latch. **Deny-by-default, deliberately**: unassigned, unlatched tank NOT eligible for new connection — `tank_is_eligible_target()` only passes tank with explicit matching entry here, or (zero-config escape hatch) already-latched `.fluid()` matching what router wants. Tradeoff accepted: brand-new tank (always `fill_pct()==0`, so top-ranked by every router's least-full-first sort) sits idle until operator assigns it — better than silently filled with wrong fluid. `lib/fluid_routing.py` `warn_about_unassigned_tanks()` (called from `FluidOutputRouter.ensure_connection()` and Steam Turbine `ensure_input_connection()`) prints (console + `notify()`) every blocked tank (unlatched AND unassigned) network-wide at most once per `UNASSIGNED_TANK_WARNING_INTERVAL_TICKS=600` ticks (~60s normal speed) — only signal such tank exists, since invisible to every router. Same call adds blank `""` entry here for each blocked tank not yet in dict (never overwrites existing entry), so operator only types fluid id; blank entry still counts as unassigned. Throttle timestamp (`fluid_routing.last_unassigned_warning_tick`) lives in `archive`, not module-level Python global — each deployed machine script importing this Library gets own copy of module state (same "per-script-run" caveat as `production_cascade.py` `_WARNED_UNKNOWN_MANUAL_ITEMS` above), so with several Water Pumps/Thermal Caps/Turbines calling in, plain global would print one copy each per interval instead of one shared notice. Value `"retiring"` (`RETIRING_ASSIGNMENT`, written by the tank upgrade §2k-3) makes a tank ineligible even while latched, so producers move off it and it drains; `assign_tanks_from_current_fluid()` never overwrites it. `production_fluids.py` consumer-side `fluid_building_is_viable()` deliberately does NOT consult this registry — tank's own `.fluid()` latch already complete answer to "can it deliver this fluid now."

- `fabricator.wants`: `{fabricator_id: {"site": outpost_id, "wants": {item_id: units}, "tick": n}}`, input units each Fabricator's `load_inputs()` is still short of (up to `min(required × crafts_remaining, craft_prefill_units())`). Written by `FabricatorController.publish_wants()` when the wanted items change or a want shrinks, else every `WANTS_REFRESH_TICKS = 300` while non-empty; an empty want removes the entry; entries older than `WANTS_STALE_TICKS = 900` are pruned by the writer and skipped by `production.fabricator_wants_for(item, site)`. - `fleet.decommission`: one shared dict `{machine_id: {kind, state, attempts, reason}}` for Pioneer and drone retirement — see §2k-4. Written by the retire buttons (FLEET / DRONE FLEET cards), the machine's own script (`ready`) and the coordinator.
- `drone.loadouts`: retired key, purged by `ArchiveCleaner` (`RETIRED_KEY_PREFIXES`). Drone slot contents come from `drone.modules()`, §2k.
- `fabricator.upgrade_orders`: `{requester_id: {item_id: qty}}` — §2a-1 item 4.
- `fabricator.backlog_orders`: `{requester_id: {item_id: qty}}` — §2a-1 item 5.
- `drone.home_depots`: one shared dict `{drone_name: outpost_id (pool) | depot_id (hardwired)}` of pinned drone homes (not one key per drone). Written by `resolve_home_depot()` in `lib/drone_energy.py`; `HOME_DEPOT` script variable overrides and overwrites the entry. Entries of drones no longer in `fleet.drones()` pruned on every write. See §2h.
- `logistics.requests`: `{outpost_id: {item_id: {"target", "have", "min"?, "buy"?, "urgent"?, "by", "tick"}}}` pull requests (`min` = need tier, absent = all need; `buy: True` = a Pioneer pull hauler may buy it at the Shop; `urgent: True` = haulers skip their minimum load and rank it first) — see §2i. Entries stale after `REQUEST_STALE_TICKS = 6000`.
- `depot.stage`: `{depot_id: {item_id: {"units", "by", "tick"}}}` hauler-drone stage requests (`lib/depot_stage.py`), fulfilled by the Depot's `fulfil_stage()` — see §2h/§2j. Stale after `STAGE_STALE_TICKS = 9000`, pruned on every write.
- `logistics.pickups`: `{"pull:<vehicle>:<dest>:<item>[:<source>]": {"vehicle", "dest", "source", "item_id", "units", "tick", "aboard"}}` in-flight reverse-hauler pickups (`aboard: True` once loaded) — see §2i.
- `logistics.drone_yield`: bool operator switch (`vehicles_panel.py` FLEET card, default off) — reverse haulers leave drone-servable pickups to drone haulers, see §2i.
- `seed.combos_tried`: `{"a,b,c": True | {"by": maker_id, "tick", "stage"}}` Seed Maker triples tried (True) or claimed in flight — see §1i. Name-keyed, never reset; ≤ 4060 keys.
- `seed_maker.status`: `{maker_id: {state, found, tried, open, saturated, last, tick}}` — see §1i. Stage B (§1k) writes `{state: "supplying"|"idle"|"waiting_material", deficit, last, tick}`.
- `plant.recipes`: `{species: {seed_id, blend, reqs: [[kind, species|None]], growth_time, base_yield}}` published by `seed_supply.py` — see §1k.
- `plant.seed_demand`: `{"now": {seed_id: n}, "rotation": {seed_id: cells}, "priority": [seed_id], "tick"}` published by the planting Harvester (Crop Automator fallback when stale) — see §1k.
- `plant.field_fill`: operator override of `field_layout.FIELD_FILL`, `"crowncap"` or `"grandbloom"` — see §1k.
- `plant.layout`: `{version, mode: "starter"|"full", fill, chunks, base, anchor, cells: {sector: species}, reserved: {sector: machine kind}, garden: [sectors]}` the field layout — see §1k.
- `plant.automators`: `{machine_id: {sector, status, queue, cells, mature, open, waiting_machines, forage, harvest_yield, garden, tick}}` Crop Automator telemetry — see §1k. `forage` = Forage in its output; `harvest_yield` = learned Forage per harvest, read by `storage.crop_automator_wake_free()`; `garden` read by `storage.crop_automator_forage()` for drain priority. Entries unrefreshed for `STATUS_STALE_TICKS` pruned by the next publishing automator.
- `plant.providers`: `{machine_id: {kind, sector, status, buffer, enabled, tick}}` Grow Lamp / Sprinkler / Dispenser telemetry — see §1k. Entries unrefreshed for `STATUS_STALE_TICKS` pruned by the next publishing provider.
- `wildlife.status`: `{habitat_id: {species, target, established, rearing, rearing_progress, pop, capacity, tier, stage, rate, efficiency, feed_item, feed_level, gas: [fluid, level, band], liquid: [...], insight, bought: {adaptation, breakthrough}, blocker, parked, release, retries, tick}}` (§1l-2); `wildlife.feed`: `{feed_maker_id: {recipes: {recipe_id: inputs}, recipe, picked, running, progress, output, stockpile, tier, blocker, retire, tick}}`; `wildlife.plan`: `{assign: {habitat_id: {species, adapt_first, tick}}, buy: {habitat_id: slot}, feed_demand: {feed_item: [home target, priority, short]}, forage_reserve, form_targets, fluid_ration, fluid_supply, release: {habitat_id: species | "-"}, progress, alerts, complete, tick}` (`complete` only once Wildlife is complete); `wildlife.released`: `{species: {habitat, pop, bought: {adaptation, breakthrough}, tick}}` (at most 16 entries, never pruned); `wildlife.readiness`: `{missing_creatures, missing_recipes}`; `wildlife.targets` (operator): species list. Status/feed entries unrefreshed for `STATUS_STALE_TICKS` are pruned by the next publisher.
- `plant.terraformer`: `{terraformer_id: {status, tier, phase, remaining_km2, progress, batch, km2_rate, batch_km2, onboard: {item_id: units}, enabled, blocker, supported_batch, in_flight, tick}}` — see §1k. Entries unrefreshed for `STATUS_STALE_TICKS` pruned by the next publishing Terraformer.

- `weather.signals`: `{event_id: {total, expires_gh, packets: {"<n>": [dx, dy]}}}` incomplete Weather Station messages (valid packets only) — see §1m. Entries dropped when their listening window closes.
- `weather.aftermaths`: `{event_id: {kind ("uranium"|"storm_glass"), x, y, units_min, units_max, ready_gh, expires_gh, decoded_gh, collected?, exhausted?}}` decoded aftermath sites for collection — see §1m; collectors add `collected`/`exhausted` (§2j-1). Pruned after `expires_gh`.
- `system.good_version`: Last operator-confirmed `get_game_version()` build hash (`lib/version_guard.py`). Seeded from current build on first read (fresh save never immediately halts). Every controller's `run()` calls `validate_game_version()` once at startup, before loop (not every tick — build change only takes effect on next script restart, same as game); if running build no longer matches key, script blocks until operator clicks "Confirm New Version" on `status_panel.py` (updates key, broadcasts `system.version_confirmed`, see §7). Build hashes support equality checks only, never newer/older comparison.
