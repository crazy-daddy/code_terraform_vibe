## §4 Inter-Process Communication & Data Archive

### Signal Bus (`get_component("comms")`)
- **Channel `sample_ready`**: Lab notifies Exchange immediately on sample extraction.
  - Payload: `{"order_id": str, "sample_id": str, "sample_type": str, "lab_id": str}`
- **Channel `system.version_confirmed`**: `status_panel.py` "Confirm New Version" button broadcasts newly-confirmed build hash so every script parked in `validate_game_version()` wakes immediately, no polling — see `lib/version_guard.py` and Data Archive entry below.
- **Channel `biome_processor_heartbeat`**: every biome processor controller fires this unconditionally each cycle so `BioLabController._wait_for_luminizer()`-style waits use `comms.wait_broadcast()`, not polling — see §1f/§1g.

### Data Archive (`get_component("notebook")` / `lib/archive.py`)
**Key convention:** one shared dict per concern `{entity_id: value}` via `archive.transaction()`, never one key per entity — archive has fixed key-count cap (CODE_GUIDES.md#archive). `lib/archive.py`'s `get_entry()`/`set_entry()`/`pop_entry()` read/write one entity's slot (transactions). **Per-machine status dicts** (`{machine_id: {..., tick}}`, the keys in `ArchiveCleaner.STATUS_TICK_KEYS`) are written only through `archive.publish_status(key, name, entry, tick, log, stale_ticks=STATUS_STALE_TICKS)`: it stamps `entry["tick"]`, sets the machine's entry and drops every other entry that is not a dict or is `STATUS_STALE_TICKS` ticks (~1 h) or more behind, in one transaction; warns on a rejected write, logs each dropped id at debug. Readers treat an entry that old as gone. `ArchiveCleaner.clean_status_ticks()` applies the same rule, so entries go even after the last machine of a kind stopped publishing. `stale_ticks=None` skips the age rule. Remaining per-entity keys below (`biomass_mixer.gate.<id>`, per-grid `power.*:<anchor>`) are legacy, pending consolidation (TODO.md). Retired families go in `ArchiveCleaner`'s `RETIRED_KEY_PREFIXES`; only the cleaner deletes leftovers, never former writers.

**Updaters must be pure:** a `transaction()` updater may only compute the new value (mutating a closure list like `claimed = [False]` is fine). Any log/print call inside it gets the whole write rejected — `lib/archive.py`'s wrapper just returns `False`, so it fails silently. Collect messages in a `notes` list and log them after the call; check the return value where a failed write matters (claims, telemetry).
#### Power, fleet & construction

- `power.shedding_tiers`: Custom shedding tiers list-of-lists `[[tier1_machines...], [tier2_machines...], ...]` (or `power.shedding_tiers:<grid_anchor>`). Default `DEFAULT_SHEDDING_TIERS` in `lib/power.py` — see §1a.
- `power.shedded`: Active list of machines Power Guard currently shedded — hard-shed (breaker off) most Tier 1 patterns, soft-shed (production paused, power on) Tier 2 `smelter_*`/`fabricator_*` — see §1a. `SmelterController`/`FabricatorController` own `is_shedded()` checks it to pause production. A headless run with the orchestrator `off` stubs it to `[]` ([standins.md](../headless/standins.md)).
- `fleet.status`: one shared telemetry dict `{name: {name, state, x, y, wh, level, target, intent, home, base, role, tick}}` (drones add `unit`, `engine`) for every ground vehicle AND drone (`lib/fleet_status.py` `publish()`, called by `publish_telemetry()` in `lib/fleet_unit.py` `FleetUnitMixin`, shared by `VehicleController` and `DroneController`; each adds its fields via `_telemetry_extra()`). Unchanged payload re-written only as heartbeat, at most every `FLEET_STATUS_MIN_INTERVAL_TICKS = 50` ticks (~5 s); any changed field writes immediately. `home` = home outpost id (vehicle `home_base`, drone `home_outpost.id`); `base` (vehicles) = the outpost it is currently based at (`VehicleController.base_id`, moved by `set_base()`; a floating hauler's trip destination, §2f); `role` = job designation (Pioneer: detected `hauler`/`miner`/`scout`/`builder`; Rover: `rover`; drone: `hauler`/`miner`/`scout`), `None` until detected. Readers: FLEET card Ground/Drones tabs (`role`, `base` else `home`, and `intent` columns), Pioneer hauler dispersal (`outpost_flow.idle_haulers_by_base()`), `drone_haulers_present()` (drone entries only, by `engine`), drone upgrade.
  - `intent`: one line set by the job loops via `set_intent()` (`lib/fleet_intent.py` `describe()`: `"<verb> <item> [+N] [at <site>] [from <src> [+N]] [to <dest>] [for <root>]"`). Cleared by `set_intent(None)` at job end and by any `publish_telemetry()` state where `fleet_status.is_idle()`: any `IDLE*` state, `READY_AT_OUTPOST`/`_BASE`/`_DEPOT`, `SURVEY_COMPLETE`, `WAITING_AFTERMATH`, or off duty (`is_off_duty()`: `RECALLED`, `UPGRADE_HOLD`, `AWAITING_MODULES`, `DECOMMISSION_READY`). Every reader classifies states through these two, never a local list. Set in: push/pull haul (`vehicle_cargo.py`), drone haul (`drone_hauler.py`), home-demand + stationed mining (`rover.py`, `pioneer.py`, `vehicle_mining.py`), biosite sampling (`drone_mining.py`), construction (`pioneer_construction.py`), survey/scout.
  - `for <root>` (`fleet_intent.haul_root()`): a `logistics.requests` entry at the destination names its `by`; else, for home, `demand_root()` walks recipe inputs (`_recipe_inputs_for()`, depth `ROOT_WALK_DEPTH = 6`) down from each root in order `manual_order` → `blueprint <kind>` → `upgrade <requester>` → `<supply dock id>` → `<requester>` (any request) → `stock_target`, first along items still short of stock, then along any path; unreached raw ore → `ore_buffer`. Stationed outpost mining with no request → `<outpost_id> stock`. Several roots in one load → `"<first> +N"`. The path found is logged at `debug()`. `ArchiveCleaner.clean_telemetry()` deletes legacy per-entity `fleet.status.<id>`/`rover.status.<id>`/`drone.status.<id>` keys and prunes entries of vehicles/drones not in `fleet.vehicles()`/`fleet.drones()`.
- `rover.claims` / `survey.claims` (mirrored, legacy + current key): Atomic target reservation dict `{target_key: {"vehicle": id, "tick": tick}}`. Stale after `fleet_claims_common.CLAIM_STALE_TICKS` (1 hr) — see `lib/vehicle_claims.py`. Doesn't exclusivity-gate mineral mining sites: a mine claim is keyed per vehicle, `"<target_key>@<vehicle>"` (see `mining.reserved_yield` below); still exclusive for survey/POI targets (key prefix `"poi_"`) and construction jobs (key prefix `"build_"`, `PioneerController.construction_claim_key()`, see §2a construction-job-claims entry).
- `construction.power_tiles`: power-line ledger `{"surveyed": tick | None, "rows": {"<ty>": [[tx0, tx1], ...]}, "dirty": [[tx, ty], ...]}` (world tile indices, inclusive runs per row). Filled by the one-off autoplay survey, kept current by Pioneers (`note_power_job()`), dirty tiles re-probed by the planner; more than `POWER_DIRTY_MAX = 400` dirty tiles reset `surveyed` to None (full survey) — see autoplay.md §11d.
- `construction.hold`: `{"by", "tick", "kinds": [kind, ...]}`; Pioneers leave jobs of a held kind alone while `tick` is younger than `HOLD_STALE_TICKS = 600`. Written and deleted by the autoplay power survey.
- `construction.lots`: `{builder name: {"ids": [blueprint_id, ...], "tick": tick}}`, the jobs each Constructor Pioneer reserved for its current batch; peers skip the ids of active owners. Written, pruned and released by `construction_lots.py` (`write_lot`/`release_lot`, driven by `BuildJob` in `job_build.py`) — see vehicles_drones.md §2a construction-lots entry.
- `construction.priority`: `{blueprint_id: int}` build order for Constructor Pioneers; no entry = 0, lower runs first (plan-ahead jobs from `autoplay/` use 1, an operator may set any int in the Notebook). Written by the autoplay planner or by hand, read and pruned (dead blueprint ids) by `BuildJob` (`lib/job_build.py`, via `construction_lots.py`) — see §2a construction-job-priority entry.
#### Mining, fabrication & reactor fuel

- `mining.reserved_yield`: Non-exclusive in-flight mining yield dict `{vehicle_name: {"vehicle": id, "target_key": str, "item_id": str, "units": int, "outpost_id": str, "tick": tick}}`, one entry per vehicle's current mine trip (planned trip yield). `logistics_requests.outpost_tier_deficits()` (so every hauler and `home_ore_demand()`) and `stockpile_headroom()` subtract it per delivery outpost. Older entries keyed by target_key (no `outpost_id`) still count until stale. Stale after `RESERVATION_STALE_TICKS = 36,000` ticks (same window as claims) — see `lib/mining_reservations.py`.
- `survey.unsupported_targets` / `rover.unsupported_targets` (mirrored): Hardware-capability blacklist entries (`reason`, `scanner_type`, `scanner_tier`, `hardness_limit`, unlocked researches) — see `lib/vehicle_claims.py`. `scanner_tier` is the mounted module's item id (`sonar_module_wide`, `drill_module_heavy`, from `vehicle.modules()`), ranked by its `lib/item_tiers.py` ladder index; any other value (older tier names like `"wide"`, `None`) ranks below every tier, so the first sonar that reads it retries the contact once and re-records it. Populated per-contact from `SonarScanResult.blocked` (`docs/types/fleet_and_vehicles.md` `BlockedContact`: `.x`/`.y`/`.reason`/`.message`), not from `scan()` top-level `.status` — wide/deep sonar sweep covers several "?" contacts at once, `.status` is one verdict for WHOLE sweep (`"ok"` once any contact in range resolves, even if others stayed blocked), so reading only `.status` silently drops every blocked contact unless nothing resolved. `scan_and_survey()` (`lib/vehicle_survey.py`) iterates `res.blocked`, blacklists each contact by own coords. `VehicleClaimsMixin.clear_unsupported_target()` (called by `vehicle_survey.py`/`vehicle_mining.py` on successful resolution) removes archive entries *and* matching `"unsupported.<target_key>"` Planet Map marker directly via `markers.remove()`, so marker vanishes immediately, not lingering until Control Panel "Sync Unsupported" button (`lib/unsupported_markers.py`) next clicked. **`reason == "wrong_scanner"` (bio contact) special-cased**: permanent hardware mismatch, not research/tier gap — ground vehicles never carry `bio_scanner` (drone-only module, `docs/database/equipment_biosphere.md`), so `can_attempt_target()` never true for it; neither `vehicle_survey.py` nor `vehicle_mining.py` calls `clear_unsupported_target()` for it. Deleting entry once drone resolves it would just let next rover/pioneer sonar sweep over coord re-`blacklist_target()` it (sonar re-reports same "?" contact blocked every sweep in range, regardless of archive state) — so entry deliberately kept forever. Instead `unsupported_markers.clear_wrong_scanner_marker(x, y)` (called by `drone_scout.py` right after successful `bio_scanner.scan()`) removes only stale `"Bio Contact"` marker via `markers.remove()`, blacklist entry intact; `update_unsupported_markers()` sync-button path independently skips (re-)placing marker for any `wrong_scanner` entry whose coord `journal.has_scanned()` reports true, so later button press can't replant. Drones otherwise not in this blacklist/marker family — non-bio-contact resolution uses unrelated `scout.empty_pois` fact cache below, never places map markers.
- `console.log_levels`: `{module_name | "*": level}` lowest level each `TreeConsole(module=...)` writes (`"trace"` < `"debug"` < `"info"` < `"warn"` < `"error"`), see `docs/AI_CHEATSHEET.md` §0a **Log levels**. Seeded `{"*": "debug"}` by the first `TreeConsole` that finds it missing; operator-edited in Notebook, read once per script start.
- `heat.optimal_setpoints`: Caching `{thermal_state: best_power}`
- `pressure.optimal_resonance`: Caching `{resonance_state: best_window}`
- `fabricator.manual_orders`: `{item_id: quantity}` ad-hoc Fabricator build requests, edited directly in Notebook (e.g. `{"drone_small": 2}`) — see §2a-1 item 3. Wanted at the `MANUAL` band (fabricator_demand.md §2a-p), counted down to 0 (then dropped) as units delivered.
- `fabricator.manual_transit`: `{item_id: {"units": n, "base": home stock when recorded}}` manual-order units drained from an off-home Fabricator/Fuel Assembler, see §2a-1 item 3. Written by `production.consume_manual_order()`; pruned by `reconcile_manual_transit()` (orchestrator_automation, before `plan_sites()`) once home stock reaches `base + units` or none of the item is left off home.
- `fluid_routing.pipe_conflicts`: `{router label: {"source", "fluid", "tick"}}`, one entry per port that yielded a pipe conflict (`lib/fluid_routing.py` `yield_pipe_conflict()`), pruned after `CONFLICT_BLACKLIST_TICKS`; read by `orchestrator_automation.py` for the AUTOMATION card. See §1b step 4.
- `lead_cask.roles`: `{cask_id: "fuel_rod" | "raw_uranium"}` Lead Cask reservations, see §1n. Written by `lead_cask.ensure_rod_cask()` (one `"fuel_rod"` cask per outpost with a Fuel Assembler); operator-editable in Notebook. Casks without an entry take either item. Pruned of gone casks on every write.
- `reactor.fuel` (`lead_cask.REACTOR_FUEL_KEY`): `{reactor_id: {outpost, status, spare, hours, alert, level, tick}}` Reactor fuel state, see §1c-4. Written by each Reactor script (`ReactorController.report_fuel()`); pruned of Reactors no longer on the network on every write. Read by the Status panel's ALERTS, and by `lead_cask.rod_emergency()` (Power Guard, Fuel Assembler).
- `lead_cask.inbound`: `{drone_name: {outpost, units, tick}}` Raw Uranium a plated drone has promised to unload at `outpost` (claimed site's share, then units aboard), see §2j-1. Written by `lead_cask.reserve_inbound()`/`set_inbound()`/`release_inbound()`; entries older than `INBOUND_STALE_TICKS = 36000` ignored and pruned on write.
- `supply_dock.order_prio`: `{order_id: prio}` ladder prio (0-999, `lib/priority.py`) of each active Earth order, written by `supply_dock.publish_order_prios()` each dock plan; read by the demand tree (`production_docks.dock_order_prios()`) and `order_rows()`.
- `supply_dock.priority_override`: `{order_id: prio}` operator overrides (0-999) of an order's prio, written by `supply_dock.set_order_override()` (ORDERS card); entries of orders that are no candidate any more are dropped by `publish_order_prios()`.
- `fluid_routing.water_reserve`: `{"hold", "level_t", "floor_t", "tick", "by"}` Reactor water reservation, written by the lowest-id Reactor controller, read by `fluid_routing.water_reserve_holds()`; stale after 1200 ticks. See §1c-4.
- `fluid_routing.tank_assignments`: `{building_id: fluid_id}` operator-designated Liquid/Gas Tank reservations, edited directly in Notebook (e.g. `{"gas_tank_1": "steam", "gas_tank_3":
  "ammonia"}`), same edit convention as `fabricator.manual_orders` (NOT same eligibility convention — see below) — see `lib/fluid_routing.py` `get_tank_assignments()`/`tank_matches_assignment()`/`tank_is_eligible_target()`. `fluid_id` values use exact vocabulary of `building.fluid()`/`production.FLUID_LATCH_IDS` (`"water"`, `"oil"`, `"steam"`, or a biome essence id such as `"frozen_essence"`), no separate taxonomy. Exists because generic tank `.fluid()` latch purely content-based, network-blind (`FluidOutputRouter` otherwise picks candidate tanks by building *type* alone, no notion of which of outpost's several non-merged physical pipe networks candidate sits on — see `docs/guide/infrastructure_and_pipes.md` "Service-footprint contacts stay independent" note) — and same latch clears to `""` instant tank drains to 0, so unrelated router could mistake operator's dedicated oil tank for blank up-for-grabs buffer during empty window, stranding its network. Keyed by stable building id so reservation survives empty window, unlike live latch. **Deny-by-default, deliberately**: unassigned, unlatched tank NOT eligible for new connection — `tank_is_eligible_target()` only passes tank with explicit matching entry here, or (zero-config escape hatch) already-latched `.fluid()` matching what router wants. Tradeoff accepted: brand-new tank (always `fill_pct()==0`, so top-ranked by every router's least-full-first sort) sits idle until operator assigns it — better than silently filled with wrong fluid. `lib/fluid_routing.py` `warn_about_unassigned_tanks()` (called from `FluidOutputRouter.ensure_connection()` and Steam Turbine `ensure_input_connection()`) prints (console + `notify()`) every blocked tank (unlatched AND unassigned) network-wide at most once per `UNASSIGNED_TANK_WARNING_INTERVAL_TICKS=600` ticks (~60s normal speed) — only signal such tank exists, since invisible to every router. Same call adds blank `""` entry here for each blocked tank not yet in dict (never overwrites existing entry), so operator only types fluid id; blank entry still counts as unassigned. Throttle timestamp (`fluid_routing.last_unassigned_warning_tick`) lives in `archive`, not module-level Python global — each deployed machine script importing this Library gets own copy of module state (same "per-script-run" caveat as `production_cascade.py` `_WARNED_UNKNOWN_MANUAL_ITEMS` above), so with several Water Pumps/Thermal Caps/Turbines calling in, plain global would print one copy each per interval instead of one shared notice. Value `"retiring"` (`RETIRING_ASSIGNMENT`, written by the tank upgrade §2k-3) makes a tank ineligible even while latched, so producers move off it and it drains; `assign_tanks_from_current_fluid()` never overwrites it. `production_fluids.py` consumer-side `fluid_building_is_viable()` deliberately does NOT consult this registry — tank's own `.fluid()` latch already complete answer to "can it deliver this fluid now."
#### Production planning & site supply

- `smelter.diag.<smelter_id>`: retired key family, purged by `ArchiveCleaner.clean_retired_keys()` (`RETIRED_KEY_PREFIXES`). Per-step Smelter outcome goes to debug() via `log_outcome()`: `shedded`, `no_demand`, `no_ore`, `ore_reserved_for_dock`, `buffer_full`, `fair_share_capped`, `took`, `busy_all_sources` (harmless), `busy_starving` (real lost time), `recipe_switch`, `output_blocked`, `demand_covered_by_peers`.
- `mining.active_ores`: `[ore_item_id, ...]`, add-only latch of ores needed once; only these keep a `STOCK` ore buffer (`outpost_mining.active_ores()`; storage_mining.md §2d).
- `mining.reach`: `{vehicle: {"outpost", "ores", "tick"}}`, ores each stationed miner can reach and cut (`outpost_mining.publish_reach()`, `mineable_ores_by_outpost()`; storage_mining.md §2d).
- `mining.ore_stock_targets`: `{ore_item_id: units}`, one stock target per raw ore shared by every outpost (`outpost_mining.ore_stock_target()`, default `storage.default_stock_target()`, seeded on first lookup only once Warehouses are unlocked, editable in the Notebook; storage_mining.md §2d). `outposts.ore_stock_targets` (old per-outpost shape) is a retired key.
- `production.ingot_stock_targets`: `{smelter_output_id: {"target": units, "need": units}}`, the fab-site ingot buffer per item, same at every outpost with a Fabricator (`production.ingot_stock_levels()`, target default `storage.default_stock_target()`, seeded with the need level on first lookup only once Warehouses are unlocked, editable in the Notebook; §2a fab-site ingot buffer).
- `production.demand`: `{"v": 1, "tick", "plan", "network": {item_id: ladder}, "sites": {site_id: {"targets": {item_id: ladder}, "ship": {item_id: [units, prio]}, "have": {item_id: units}}}, "smelter": {"network": {item_id: ladder}, "sites": {site_id: {"demands": {item_id: ladder}, "have": {item_id: units}}}}, "depths": {item_id: depth}, "blueprint": {item_id: gross units}}`, the shared demand record (`lib/production_demand_record.py`; a ladder is `[[prio, cum_units], ...]`, §2a-p). Writers: the orchestrator's `DemandPublisher` and `site_supply.publish_site_requests()`; machines never write it. Readers: `get_site_fabricator_ladders()` (netted by `_net_consumed()`), the Smelter via `smelter_demands_from_record()`, `recipe_depths()` and `blueprint_demand_wants()`. Only a record of the current `DEMAND_VERSION` and `fabricator.site_plan` is read.
- `production.demand_tick`: the record's publish tick alone (one int), read per poll to see a new record.
- `fabricator.wants`: `{fabricator_id: {"site": outpost_id, "wants": {item_id: [units, prio]}, "tick": n}}`, input units each Fabricator's `load_inputs()` is still short of (up to `min(required × crafts_remaining, craft_prefill_units())`) and the prio of the recipe they serve. Written by `FabricatorController.publish_wants()` when the wanted items change, a want shrinks or its prio changes, else every `WANTS_REFRESH_TICKS = 300` while non-empty; an empty want removes the entry; entries older than `WANTS_STALE_TICKS = 900` are pruned by the writer and skipped by `production.fabricator_wants_for(item, site)` (highest prio first, then the largest). Read by the Smelter's `drain_output()` to push ingots straight into a local Fabricator (§2a-0).
- `smelter.wants`: `{smelter_id: {"site": outpost_id, "ore": item_id, "fill_to": units, "prio": p, "tick": n}}`, absolute input level the Smelter's `load_ore()` caps allow for its current recipe: `in_buf + min(hardware, demand_share, prefill)` (no chunk, no fair share; §1 Ore intake caps). Absent while a Supply Dock order still ships that ore raw or the output is blocked. Written by `SmelterController.publish_want()` when it changes, else every `WANTS_REFRESH_TICKS` while set; no want removes the entry; stale after `WANTS_STALE_TICKS` (same constants as `fabricator.wants`). `prio` = the top open level of the demand the Smelter refines for (§2a-p). Read by `production_core.smelter_wants_at(site)` for the Drone Depot's direct Smelter feed, most urgent `prio` first (§2h).
- `fabricator.site_plan`: `{root_item_id: [site_id, ...]}`, the fab sites building each root target's tree (`site_plan.plan_sites()`, §2a-0-6); entries removed once built, cleared with Fabricators at home only.
- `site_supply.construction_stock`: `{item_id: {"target": units, "need": units}}`, the construction stock at the Constructor's home (`site_supply.construction_stock_levels()`, seeded from `EARLY_CONSTRUCTION_STOCK`, raised to `LATE_CONSTRUCTION_STOCK` in the mining-drill phase while unedited, editable in the Notebook; pull_logistics.md §2i-1). `fabricator.stock_targets` (old home segment floor) is a retired key.
- `site_supply.construction_rush`: `{item_id: {"units": n, "tick": t}}`, an urgent shortfall of the construction stock (`CONSTRUCTION_RUSH_KEY`). Written by the autoplay power and fluid planners (`site_supply.set_construction_rush()`, cleared once the chunk is queued). While younger than `CONSTRUCTION_RUSH_STALE_TICKS = 3000` it raises the item's need level, capped at the target (pull_logistics.md §2i-1).
- `site_supply.stranded`: `{outpost_id: {item_id: first_tick}}`, stranded ore, goods, reagents and stragglers (home included), pruned to what is stranded now (`site_supply.evict_stranded()`, §2i-1).
- `plant.geometry`: `{"source": field_layout.geometry_source(), "chunk_count": {fill: n}}` — the Harvester's `full_chunk_count()` result (~48k interpreter steps to compute) kept across restarts while the layout constants are unchanged (`harvester_hub.stored_chunk_count()`).

Shape and classes in `docs/cheatsheet/dev_workflow.md` §1d-3.
