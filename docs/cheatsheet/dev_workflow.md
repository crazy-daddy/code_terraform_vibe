### 1d. Per-Script Tick-Cost Profiling (`lib/profiling.py`)

Game exposes no per-script CPU/ms budget API. `clock.tick()` (deterministic
sim tick since save start, 10 ticks/sec normal speed) = sanctioned stand-in per
`docs/components/clock.md`. `lib/profiling.py` wraps pattern so any controller's `run()` loop
measures own `step()` with two calls:

```python
start = profiling.begin()
self.step()
profiling.end(self.name, start)   # logs a warning if delta > SLOW_STEP_TICK_THRESHOLD=1
```

- Samples roll into `archive` as one fixed-size history list per script name
  (`ARCHIVE_KEY_PREFIX="profiling."`, `HISTORY_LEN=50`) — one archive entry per profiled *script
  name*, not per sample, respects Data Archive's hard 2,048-entry cap.
- `profiling.report(names=None)` prints avg/max ticks-per-`step()` for every profiled name (or
  subset) — call ad hoc, not from hot loop.
- **Granularity**: a script gets a fixed step allowance per tick (§1d-1), so `step()` spans `steps / allowance` ticks and a tick delta does measure its cost, in whole ticks. A `0` means the step fit into the rest of one tick's allowance (up to ~300 steps with ~165 scripts running), not that it was free. `SLOW_STEP_TICK_THRESHOLD=1`: any nonzero delta is worth a look. For sub-tick costs, count operations (docs/BENCHMARK.md) or time a loop in `devtools/panel_benchmark.py`.
- **Not currently wired into any script.** `lib/profiling.py` and `lib/archive_cleaner.py`'s
  cleanup of it kept for future script suspected of real bulk per-call work.
- **Storage shape & cleanup**: each archive entry `{"history": [...], "last_tick": N}`.
  `lib/archive_cleaner.py`'s `clean_profiling()` purges entry whose `last_tick` not advanced
  in `PROFILING_STALE_TICKS=6000` (10 sim minutes, "instrumentation removed"), always purges
  legacy bare-list entries. Runs in
  `ArchiveCleaner.run()`'s normal sweep.

### 1d-1. Script Cost Model (measured, [`docs/BENCHMARK.md`](../BENCHMARK.md) "Load dependence")

- **Step allowance**: `allowance = max(1, min(1000, floor(50000 / N)))` steps per script per tick, N = scripts whose status is `running`, `waiting` (in `sleep()`, a Signal Bus wait, or the pause after a console write) or `flushing`; completed, stopped, paused, errored and breakpoint-halted scripts don't count (game scheduler, from the decompiled simworker kept locally and gitignored (`internals/`, `docs/extracted/`): `interpreter.stepsPerTick = 1000`, `interpreter.totalStepsPerTick = 50000`). So ≤ 50 running scripts: full speed (100 µs of simulation time per step). Above 50: `100,000 / allowance` µs per step, 303 steps (≈ 330 µs) at N = 165; each extra script shrinks everyone's allowance by a factor `(N−1)/N` (~0.6% at 165), each removed one grows it likewise. How busy the scripts are does not matter.
- **What this means for code**:
  - Fewer steps per poll make *that* script react sooner (a planning pass finishes in fewer ticks); they barely help other scripts. Shorter sleeps likewise cost only the script itself.
  - The lever for the whole base is the **number of running scripts**. Setpoints (`set_tilt`, `set_throttle`, `set_power`, `set_intake`, all *self only*) hold only while the machine's script runs: a script that ends, or `run_control.stop()`, drops them to idle (solar tilt back to 90°, measured). So a machine that needs a held setpoint needs a running script; one whose idle state is acceptable (off, no recipe running, night) can have its script end and be restarted with `run_control.start()` when there is work.
  - Work duplicated across instances (e.g. every Smelter walking the demand tree) costs only those instances their own latency, not other scripts. Centralizing it into one script trades their latency for that script's; it is not a base-wide saving.
  - The base as a whole gets at most 50,000 steps per tick once N ≥ 50, whatever N is; more scripts only split it. Don't split work into helper scripts for throughput, and don't borrow idle machine scripts for unrelated computation; split only where a slow task delays a script that must react quickly (e.g. the headless panel's grid supervision), and measure that delay first. A script that uses its whole allowance 30 ticks in a row raises the game's `scriptBudgetPressure` event.
  - Console writes and `sleep()` cost 0.1 s of the script's own time each (debug lines are buffered, §0a).
  - **Census** (`lib/script_census.py`, `census_if_due()` from `control_room_automation.py` `park_if_due()`): every `CENSUS_TICK_INTERVAL = 300` ticks counts `run_control.is_running()` over every outpost building, Harvesting-field machine and mobile unit (atomic batches of `CENSUS_CHUNK = 100`) and logs debug `scripts running: N of M machines, allowance A steps/tick`. `is_running()` is per machine, so a machine with scripts in several slots counts once. `census_if_due()` returns its `snapshot()` (`machine_refs()` rows `(id, kind, name, mobile)` + running ids), which feeds the machine activity sample (§1d-3).
- **Scheduler details** (same source):
  - **Breaker pause** — the one documented lever: `power_control.set_powered(id, False)` pauses the machine's script (status `paused`, not counted in N) and preserves its setpoints; `set_powered(id, True)` resumes that script where it stopped, Python state intact (docs/components/power_control.md). Only machines with a breaker (`can_power_off()`). Measured with a breaker: bio_caster, bio_collector, bio_exchange, bio_lab, charging_station, drone_service_station, drone_station_large, fabricator, garbage_disposal, oil_generator, oxygen_generator, plant_terraformer, pressure_generator, seed_maker, smelter, steam_condenser, steam_turbine, supply_dock, temp_heater, weather_station, and (probed by id, as `outpost.buildings()` does not list them) water_pump, oil_pump, thermal_cap, crop_automator, mining_drill_heavy. Without: solar_generator, harvester, scanner, battery, battery_large, bulk_liquid_reservoir, gas_tank, warehouse, large_warehouse; mobile units have none. A machine without a breaker can only leave N through `run_control.stop()`/`start()` (setpoints reset, script restarts) — acceptable for solar at night, when output is 0 W anyway. `PowerGridManager` load shedding (§1a) uses the same breakers, so a parked machine must not be confused with a shed one.
  - **Callbacks run as one unit**: each call of a Python callback from `map`, `itertools.starmap`, `sorted`/`list.sort`/`min`/`max`/`heapq.nsmallest`/`nlargest` with `key=`, and the `archive.transaction` updater runs without a budget check inside it, capped at `stepsPerTick × 10` = 10,000 steps (`StepLimitError` beyond). The cap comes from the fixed interpreter config, not the Advanced Scripting settings (those only switch the string limit 10,000 → 100,000 and the collection limit 10,000 → 50,000). `StepLimitError` cannot be caught by `try/except` (only Python exceptions and `RecursionError` can) and ends the script, so chunks must be sized well under the cap at their worst case: the Harvester search chunk (`EXPAND_CHUNK_NODES = 40`, bucket entries plus bucket advances) peaks at ~3,800 interpreter operations. The budget is checked only between callbacks and resets every tick, so a callback can overrun the tick's allowance without being charged later. What a callback may call (decompiled `validateNativeCall`): game reads without side effects (`get_component()`, `stacks()`, `count()`, `fleet.vehicles()`, `outpost.buildings()`) are allowed and uncharged; a call that changes game state or observes (`set_enabled`, `connect`, `take`, archive writes, scans) or suspends (`sleep()`, waits, `mine`) raises `RuntimeError` (catchable, but it aborts the callback); remote writes raise `PermissionError` as anywhere. Keep logging out of callbacks. Measured (~330-step allowance): 1,000 iterations of pure arithmetic (~7,700 steps) take 23 ticks as a direct call and 1 tick inside one `map()` callback. With work split into chunks of ≤ 10,000 steps, `map` over the chunks runs one chunk per tick. Engine quirk that a game update may close; the 50,000-step total exists to protect frame time, so use it only for a few heavy pure computations, behind one helper: `lib/atomic.py` (`run_atomic(fn, *args)` runs one call as a `map()` callback; `run_batched(fn, items, size, *args)` runs `fn` on each `size`-item slice as one call and joins the returned lists; `run_chunked(step_fn, state)` repeats bounded chunks until `step_fn` returns True; `ATOMIC_ENABLED = False` calls directly). Used by the drone hauler and Pioneer route planners (`logistics_requests.route_atomic_ok()`, `docs/cheatsheet/vehicles_drones.md` **Plan**), the Constructor Pioneer job scan (`lib/construction_plan.py`, `JOB_CHUNK`/`TRIP_CHUNK`/`PROGRESS_CHUNK`), the Wildlife planner (`lib/wildlife_planner.py`: the whole `build_plan()`, `MODEL_CHUNK`; tank discovery and reads, `TANK_CHUNK`), `storage.warehouse_stocks()` (`stacks()` reads, `STOCKS_CHUNK` Warehouses per call) and the Harvester route search (`lib/harvester_heat.py`, `EXPAND_CHUNK_NODES`).
  - **Import-time code** (module bodies of libs) runs synchronously and is capped at 10,000 steps too: keep heavy precomputation out of module bodies and build it lazily.
  - `sleep()`, Signal Bus waits and the pause after a console write all leave the script counted in N (status `waiting`/`flushing`).
- **Measuring**: `devtools/panel_benchmark.py` with `QUICK = True` (empty loop, `len()`, call, component call; min/median/max) in a Control Room card. Compare runs that differ only in which scripts run. Heavy scripts can report their own phases in ticks, like the Harvester's `planned in … (N ticks: phase n, …)` note (§1k). Offline, `devtools/step_profile.py` estimates a code path's steps per function on the synthetic `tests/sample_world.py` save (§10).

### 1d-2. Script Parking (`lib/script_parking.py`)

Takes idle machines' scripts out of the running-script count (§1d-1).

- **Machine side** (`ParkRequester(machine_id, kind)`, `update(idle, wake_after=None)` once per step): after `PARK_AFTER_IDLE_STEPS = 3` idle steps in a row it files `{"kind", "tick"[, "wake_after"]}` in `script.park_requests` (refreshed each further idle step); the first busy step withdraws it. Wired into Smelter/Fabricator (`step()` returned not active), Supply Dock (standing by: no order, no cargo) Oil Generator (neither mode burning and no deficit without oil, §1c-1), Oil Pump (well dormant; Water Pumps are not parked: they run at full throttle and a stall can be a routing problem the pump itself resolves), Exotic Gas Cap / Spring Tap (kind `exotic_cap`, `lib/exotic_cap.py`: deposit dormant, buffer no longer releasing, and Deep-survey `next_phase_in()` leaves at least `EXOTIC_PARK_MIN_TICKS = 600` after `EXOTIC_WAKE_LEAD_TICKS = 150`; files `wake_after` = time left − lead. Common deposits cycle in under a minute of real time, so they normally never park), Crop Automator (in the layout, not shed, nothing queued or finished, no new job; mature crops waiting for output room don't count as work; strays keep running to empty themselves; `storage.take_item()` wakes an automator before pulling Forage from it only when the pull leaves room for one harvest (`crop_automator_wake_free()`), `wake_for_visit(..., hold=False)`) and Thermal Cap (vent dormant and chamber ≤ `CAP_PARK_MAX_PRESSURE = 0.02`, filing its own wake time: `CAP_PARK_WAKE_FRACTION = 0.5` of the time until the vent turns active when `next_phase_in()` is known, else of the time the fastest confirmed pressure rise needs from empty to `PRESSURE_BAND_CRITICAL`; no request without either); an exception counts as busy.
- **Panel side** (`ScriptParking.step(grids, elevation, dock_plan)`, control_room_automation.py `park_if_due()` every `PARKING_TICK_INTERVAL = 50` ticks, checked each loop and between the storage pass's sub-steps): parks a request not older than `REQUEST_FRESH_TICKS = 150` with `power_control.set_powered(id, False)` if the machine is on a grid, has a breaker, and is not in `power.shedded`; a dock is not parked while the dock plan assigns it an order, an Oil Generator not while its grid is low (below). Parked machines live in `script.parked` `{id: {"kind", "mode", "since"}}`; only ids listed there are ever switched back on; an id whose component is gone, or that reads powered again (`is_powered()`, e.g. the player flipped its breaker), is dropped (its pre-park request cleared). Each park is written to `script.parked` in its own transaction *before* the breaker goes off (removed again if `set_powered` fails), and the pass's other changes are applied as a diff in one transaction, so a script killed mid-pass never leaves an untracked dark machine and entries other scripts wrote meanwhile (`turbine_commit`, `wake_for_visit()`) survive. **Orphan backup scan** (`_adopt_orphans()`): a grid member that reads off at its breaker, has a park request older than `REQUEST_FRESH_TICKS`, and is in neither `script.parked` nor `power.shedded` is re-adopted into `script.parked` with its request tick as `since` (warn line `Re-adopted N untracked dark machine(s)`), so its wake re-check is due on the next pass. The API cannot tell a game outage shutdown (which the game recovers itself) from a breaker-off, so an outage-dark machine with a stale request can be adopted too; its wake then only switches it on early.
- **Wake** (`set_powered(id, True)`, the script resumes where it paused and parks again on its own if still idle): after `WAKE_AFTER_TICKS` (smelter 300, fabricator 300, supply_dock 600, oil_generator 6000 (backstop: the low-reserve wake is the real trigger), thermal_cap 600, oil_pump 3000, exotic_cap 6000 (backstop), crop_automator 600, charging_station 3000, drone_service_station 3000, drone_depot 3000, field_provider 6000, seed_maker 3000, feed_maker 3000, fuel_assembler 3000), or the machine's own `wake_after` (capped at `MAX_WAKE_AFTER_TICKS = 6000`), a Smelter as soon as a Fabricator at its outpost finds no stock of one of its outputs (`fabricator.wake_local_smelters()`), a dock as soon as the plan assigns it an order, Oil Pumps as soon as `well_active()` reads true (readable from any script), Exotic Gas Caps / Spring Taps as soon as `deposit().current_phase()` reads `"active"`, Oil Generators as soon as their grid's lower of battery / combined reserve fraction drops below `OIL_WAKE_RESERVE_FRACTION = 0.25` (their own start line is 0.15; unreadable reserve also wakes), or while the network-wide oil tank fill is `≥ OIL_SURPLUS_WAKE_FRACTION = 0.90` (`oil_generator` surplus base load, §1c-1; not parked then either). Requests filed before a machine was parked are cleared on wake.
- **Field providers** (Grow Lamp, Sprinkler, Dispenser; kind `field_provider`): park while switched off (no layout crop beside them needs their service), not shed and not a stray; the breaker keeps `set_enabled(False)` (ending the script would too, but a lit one must stay powered, so only off ones park, and central on/off is a blocked remote write). Woken by `script_parking.wake_kind("field_provider", reason)`, called by `harvester_planting` after writing `plant.layout` and by `seed_supply` when the `plant.recipes` it writes differ from its last write this run; re-check every 6000 ticks otherwise.
- **Seed Maker** (stage B `SeedSupplyController`, kind `seed_maker`): parks when its step returns `SUPPLY_IDLE_POLL_SECONDS` (no seed deficit). Re-check every 3000 ticks, below `logistics_requests.REQUEST_STALE_TICKS = 6000`, so its life-form stock requests are republished before they expire; `harvester_planting.publish_seed_demand()` calls `wake_kind("seed_maker")` when its `now` demand changes (non-empty). Stage A (discovery sweep) is not parked.
- **Scanner** (no breaker): its script ends once every sector of the grid is mapped.
- **Drone Depots** (kind `drone_depot`, all three sizes): park when `DroneDepotController.parkable()`: not retiring, no drone docked, no stage request, stockpile empty (life forms too: a hauler or the Liquifier `take()` from it). Woken by `wake_for_visit()` from `drone_navigation.fly_to_station()` (every depot or service visit; renewed every `VISIT_HOLD_RENEW_TICKS = 1000` ticks of flight) and `depot_stage.request_stage()` (a hauler's pickup, so staging runs while it flies there). Held like stations (`HELD_KINDS`), no last-awake rule.
- **Stations** (Charging Station, Drone Service Station; `STATION_KINDS`): park when their step has no work (no bay active or queued, no rescue, no vehicle they are responsible for below target). The last awake station of a type never parks (`_awake_stations()`, built once per pass), so a fleet scan always runs as the backstop for vehicles whose own script is not running. `wake_for_visit(id, reason)` (any script): holds the station awake for `STATION_HOLD_TICKS = 3000` (`script.park_holds`, `{id: until_tick}`; a held station is not parked) and switches it on if parked, clearing its pre-park request (`hold=False`: no hold, for kinds outside `HELD_KINDS`). Called by `vehicle_energy.recharge_at_station()` before driving there and every 5th wait cycle, `drone_energy.return_to_service_for_charge()` (also on each launch-charge re-check) and `drone_hauler._go_to_nearest_service()` / every 30 s of `_refuel_at_service()`. Awake stations leave parked ones out of responsibility (`parked_ids(kind)`); when a vehicle needing attention (stranded, below return floor, or below its rescue target) is nearest to a parked station (`parked_nearest()`), the awake one wakes that station and leaves it the vehicle, so the nearest station still watches and rescues.
- **Stray dark machines** (`_strays()`, end of each pass): a grid member that reads off at its breaker (`powered` False), has one (`can_power_off()`), and is in none of `script.parked` (any mode), `power.shedded`, `script.park_requests`, the retired registry (`machine.retired`, `lib/retired_machines.py`) or the operator's `script.manual_off` (`{id: note}`). Typically a machine built before its grid had power: its breaker is off and its script never started. Tracked in `script.stray_dark` `{id: {"kind", "first", "stage"}}`; three stages by time since first seen: (1) at once, a warn line naming `script.manual_off`; (2) after `STRAY_NOTIFY_TICKS = 600`, one `notify()` and a Status panel alert (`stray_alerts()`, every stage-2 id); (3) after `STRAY_SWITCH_ON_TICKS = 3000`, `set_powered(id, True)`, then `run_control.start()` when `status().state` is `"idle"` (`"error"`/`"completed"` scripts get a warn line and are not restarted). A stray switched on, or listed/owned meanwhile, leaves `script.stray_dark`. Other breaker owners therefore record what they switch off: turbine commitment (`"turbine"`) and the Biomass Mixer gate (`"mixer_gate"`) in `script.parked` under their own mode, retirements in `machine.retired`.
- **Grid member reads**: `_members()` reads every grid member's id/type/powered in atomic `run_batched()` slices of `MEMBER_CHUNK = 150` (~15 operations each).
- **Solar at night** (`solar_generator` has a breaker too, but at 0 W a stop costs nothing and tells a player-stopped script apart): elevation ≤ 0 → `run_control.stop()` every running `solar_generator` script (mode `"stopped"`); elevation > 0 → `run_control.start()` only those. Tilt resets while stopped, output is 0 W then.
- Not parked: Reactors (heat returns to 0 when the script stops, §1c-4), terraformers (heater, O2 generator, pressure generator: they work until their target and are sold there, and do no work while unpowered), bio machines, turbines (parked by `PowerGridManager`'s turbine commitment instead, `lib/turbine_commit.py`, mode `"turbine"` in `script.parked`, which `ScriptParking` leaves alone), Water Pumps, mobile units.

### 1d-3. Machine Activity (`lib/machine_activity.py`)

Which machine groups have more members than their pooled work needs: retire candidates that would lower the running-script count (§1d-1).

- **Sample**: `record(snapshot, now)` from `control_room_automation.py` `park_if_due()` right after each census (§1d-1, every `CENSUS_TICK_INTERVAL = 300` ticks). Uses the census snapshot plus `fleet.status`, `script.parked` and `script.park_requests`; no calls on the machines. Classification and accumulation run in atomic `run_batched()` slices of `ACTIVITY_CHUNK = 50`.
- **Class per machine per sample**: `active` (vehicle/drone in a working state; running building without park request), `waiting` (vehicle/drone in `FLEET_WAITING_STATES`: `WAITING_DEPOT_SPACE`, `WAITING_DEPOT_BAY`, `WAITING_INVENTORY_SPACE`, `STRANDED`, `AWAITING_RESCUE`), `idle` (vehicle/drone in any `IDLE*` state or `FLEET_IDLE_STATES` = `fleet_status.IDLE_STATES` + `READY_AT_DEPOT`, `WAITING_AFTERMATH`, `DECOMMISSION_READY`; running building with an open park request), `running` (script runs, no idle signal: building group none of whose members ever filed a park request or was parked, i.e. no `ParkRequester`; vehicle/drone without a `fleet.status` entry), `parked` (in `script.parked`, any mode), `off` (neither running nor parked). Machines never running or parked (storage, tanks) are not tracked.
- **Group** (`group_of()`): building/field machine `type_id`; mobile unit kind (`drone_small/medium/large` → `drone`) + `:<role>` from `fleet.status` (`drone:miner`, `pioneer:hauler`, ...). Members of a group pool their work, so the group, not the single machine, says how many are needed.
- **Decay**: every count is multiplied by `0.5 ** (elapsed / HALF_LIFE_TICKS)` (`HALF_LIFE_TICKS = 216000`, ~6 h) before the sample adds 1; weights below `MIN_WEIGHT = 0.01` drop.
- **Spare** = `SPARE_CLASSES` (`waiting`, `idle`, `parked`, `off`). Per group: `spare_mean` = average spare members; `retire` = largest k with at least `SPARE_QUANTILE = 0.9` of the sample weight at k or more spare members at once (`spare_quantile()`), i.e. members the group could lose and still have had every busy member it used in 90 % of the samples. A group busy all night but idle all day gets `retire` 0.
- **Archive** `machine.activity` (single writer, `archive.set()`): `{"tick", "samples", "groups": {group: {"n", "sig", "w", "c": {class: weight}, "spare": [weight per spare count], "share": {class: %}, "spare_mean", "retire"}}, "machines": {id: {"g", "c", "l": class in the last sample}}}`. Machines and groups missing from the sample are pruned. View helpers: `group_rows(state)` (most `retire` first, then `spare_mean`, then name) and `machine_rows(state, group)` (`(id, {class: %}, last class, spare %)`, most spare first).
- **Log**: every `SUMMARY_LOG_TICKS = 36000` ticks one debug block `machine activity: …` with one line per group, most `retire` first: `<group>: N machines, active a% waiting w% idle i% … ; spare mean m, retire r`.
- **Card**: `activity_panel.py` (MACHINE ACTIVITY, panels.md §7) draws both views.
- Reading `waiting`: a Drone miner in `WAITING_DEPOT_SPACE` has work but the Depot cannot take it, so its output is surplus too; that is why it counts as spare.

## 🐞 8. Live Debugging via External IDE

Game exposes real Debug Adapter Protocol (DAP) integration against actual running game interpreter, not simulation: breakpoints, conditions, logpoints, call stacks, locals, watches, hover inspection, Step Over/Into/Out. Setup + full details:
`%APPDATA%\io.codeterraform.game\external-ide\README.txt`.

- **VS Code** (supported path, extension already installed this save): open script, set breakpoint, press **F5**. Idle script starts running; already-running script attaches without restart. **Shift+F5** or closing debug session disconnects but leaves script running in game. Use **Stop Script in Game** to actually stop. Watches/Debug Console **read-only** (can't execute world actions or assign variables). Edited main-script code needs **Run Script in Game** before re-attaching; edited Libraries need re-applying in game.
- **Any other DAP-capable editor**: launch
  `node "%APPDATA%\io.codeterraform.game\external-ide\server\debug-adapter.cjs"`
  (Node.js 20+, stdio transport). `launch` = attach-and-run idle script; `attach` = inspect already-running one. Set `workspace` to this save's scripts directory, `script` to target file.
- **Non-debug editor tooling** (LSP-only, no execution): `external-ide\server\server.cjs --stdio`. Per-editor docs (neovim/Helix/Sublime) in README. PyCharm needs generic LSP plugin; its own Python checker doesn't know game's owner globals/runtime rules.
- Console output mirrors to `external-ide\logs\all.log` (plus one file per script). Useful to tail even without debugger.
- **`devtools/dap_client.py`**: minimal DAP client for driving debug session from script instead of VS Code. Needs Node.js 20+; this save's copy at `C:\Program Files\nodejs\node.exe`, not on default shell `PATH`. Invoke by full path, or `export PATH="/c/Program Files/nodejs:$PATH"` for current shell session only (shell state doesn't persist between tool calls here). Vendored into `devtools/` (not imported from the standalone `early_game_runner/` project). `devtools/scripts_sync.py` only consumer. `DapClient` = low-level stdio transport (Content-Length framing, background reader thread). `run_session(workspace, script, breakpoints,
  mode, on_stopped, wait_timeout)` wraps full initialize → attach/launch → setBreakpoints → configurationDone → wait-for-`stopped` → callback → continue → disconnect sequence in one call.
  Also runnable directly: `python devtools/dap_client.py --workspace <dir> --script <path> --break
  <file.py>:<line> [--mode attach|launch]`. Prints stack trace + top-frame locals at first hit, then resumes and disconnects.
  - **`launch` starts idle scripts without breakpoints**: `dap_client.launch_script(workspace, script)`
    (or CLI `python devtools/dap_client.py --workspace <dir> --script <path> --launch`) sends `initialize` →
    `launch` → `configurationDone` with no breakpoints set, triggering `{ action: "start", runIfIdle: true }`
    in `debug-adapter.cjs`. It then cleanly disconnects with `terminateDebuggee=False`, leaving the freshly-started
    script running in the live game.
  - **Does NOT force-restart already-running script**: `runIfIdle: true` is exactly that:
    a script already running just gets attached-to (per `debug-adapter.cjs`'s own `configurationDoneRequest`),
    its old in-memory code untouched. There is no `supportsRestartRequest` capability advertised by
    `initialize`, and the base `DebugSession`'s `restartRequest`/DAP `restart` is an unimplemented no-op
    stub in the concrete session class too.
  - **General external-command channel** (`.codeterraform/command.json`/`command-result.json`/
    `command.lock`, distinct from the debug bridge's own `debug-command.json`/`debug-result.json`) is what
    "Run Script in Game"/"Create Library in Game"/etc. (VS Code commands in `extension.cjs`, not
    `debug-adapter.cjs`) use. Request:
    `{"version":1,"requestId":"<uuid>","issuedAt":<epoch_ms>,"session":{"id":..., "generation":1} (read
    live from codeterraform-workspace.json),"action":"run","scriptId":"<script id>","source":"<full
    script text>"}`, written via the same atomic-write + `command.lock` (staleness >30s, `wx`-create,
    35s acquire budget) protocol as the debug bridge's `H.send()`, then polled from `command-result.json`

### 8a. Fast-Forwarding the Simulation (WebView2 DevTools)

The in-game speed tops out at 3× (`game.maxGameSpeed`). Faster testing works by shortening the sim worker's tick timer from DevTools. Nothing on disk changes, and the patch is gone after a game restart.

**Clock mechanics** (`internals/terraform_decompiled/simworker/deobfuscated.js`, search `WCe`):
- The sim runs in a Web Worker (`simWorker-*.js`) inside WebView2 (Tauri), in a `msedgewebview2.exe` child process. Cheat Engine's speedhack hooks the game exe, so it never reaches the sim's timers.
- `setInterval(u, 1000 / game.tickRate)` (100 ms) drives the loop. Each callback runs `l` ticks. `l` is the in-game speed (1–3, from `sim.setSpeed`). The loop stops early when a tick requests a presentation flush.
- The sim never reads wall-clock time. Game time, `sleep()`, and interpreter step budgets all count ticks, so firing ticks faster keeps script behavior identical.
- `m()` re-arms the interval on every resume and after every save barrier. It looks up the global `setInterval` each time.

**Steps:**
1. With the game closed, set the user environment variable `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`. Untested: Tauri passes its own browser arguments and may override it. If `http://localhost:9222/json` responds while the game runs, it worked.
2. Start the game. Open `edge://inspect`, add `localhost:9222` under *Configure*, and inspect the game page.
3. In the DevTools console, select the `simWorker-…` context in the context dropdown, then run:
   ```js
   const _si = setInterval;
   globalThis.setInterval = (fn, ms, ...a) => _si(fn, ms / 10, ...a);  // 10x
   ```
4. Pause and resume in the game so `m()` re-arms the timer at 10 ms. Combined with in-game speed 3, this gives up to 30×.
5. To revert, run `globalThis.setInterval = _si`, then pause and resume.

Alternative: set a breakpoint in `u` and raise `l` in the Scope pane. This scales worse because of the early stop on flush.

**Limits:** Real CPU time per tick (all scripts' step budgets) caps the speed-up; a slow tick makes the timer run back-to-back. `isBackpressured()` skips ticks while the UI is behind on snapshots. This runs against the live save, so the permission rule above applies: ask before using it on the main save.

## 🧬 9. Dev Workflow: Tiered `scripts/` + `devtools/scripts_sync.py`

Repo (`C:\Users\<user>\Code_Terraform`) = dev root, separate from live save folder (`%APPDATA%\io.codeterraform.game\save_*_scripts`). Source of truth: `scripts/<tier>/<category>/<name>.py`. `devtools/scripts_sync.py` (adapted from `inspirations/vakermit/bin/ct_sync.py`) pushes it into the save folder's numbered script slots and mirrors `lib/`. One direction only: no pull from the game. Full mechanics (push/restart, renumbering, `_unmatched/` staging) in tool's module docstring. This section covers project-specific tiering layer on top.

**Tier list**: not hardcoded. `discover_tiers()`/`tier_number()` in `scripts_sync.py` scan `scripts/` for `<N>_<anything>` dirs, sort by `N` ascending (numeric, so `10_x` after `9_x`, not between `1_x`/`2_x`). Only number matters, rest of name free text. Numbers may skip. Add `scripts/6_derp/` (or `scripts/3_inbetween/` between two existing tiers) with own `.criteria` → picked up automatically, no code change. Dir starting with digit but not plain `<int>_...` (`1N3_DERP`), or two dirs claiming same number (`10_hi`/`10_ho`) → raise `TierNamingError`, no silent guessing. Each tier gated by `.criteria` file at root (absent for `0_cold_boot`, always-active baseline). Current tiers:

| Tier | `.criteria` | Unlocks (tech id / `research_*` id) |
| :--- | :--- | :--- |
| `0_cold_boot` | *(none — baseline)* | — |
| `1_early` | `{"tech": ["ship_computer"]}` | `research_computer` |
| `2_libunlock` | `{"tech": ["shared_library"]}` | `research_shared_library` |
| `3_archiveunlock` | `{"tech": ["data_archive_unlock"]}` | `research_data_archive` |
| `4_controlpanel` | `{"tech": ["custom_panels_unlock"]}` | `research_custom_panels` |

`.criteria` keys use save file's own **tech ids** (from `state.unlockedTech`), not `research_*` ids from `docs/database/research_catalog.md`. Table above = mapping. Supported keys: `"tech": [id, ...]` (all must be present), `"outpost_count": N` (`len(state.planet.outposts) >= N`). `"plant_recipes": N` (`len(state.planet.plants.discoveredRecipes) >= N`). `"buildings": {typeId: N, ...}` (each type's count in `state.machines[*].typeId` >= N; finished machines only; pending `constructionBlueprints` and `isUnderConstruction` machines not counted). `"buildings_any": {typeId: N, ...}` (OR-group: at least one listed type's count >= N; used for "any Mining Drill variant"). Map-deployed buildings (drills included) appear in `state.machines` like any other machine, so both building keys see them; entries still `isUnderConstruction` are **not** counted (only finished deployments). TP-threshold criteria not supported (no TP field known in save state).

**Active-tier resolution**: fully automatic, per-save. `scripts_sync.py` derives sibling save-state file from save-scripts dir name (`save_X_scripts/` → `save_X.json`, one level up), reads `state.unlockedTech` / `state.planet.outposts` **read-only**, walks numerically sorted tier list evaluating `.criteria` until one fails. Highest passing tier = active. No hint file, no manual bookkeeping. `--force-tier NAME` overrides for one run, persists nothing. **Assumes monotonic unlocks**: walk stops at first tier whose `.criteria` unmet, so ancestor criteria implicitly required. Out-of-order save (higher tier's `.criteria` satisfied before lower one's) not handled specially. Not expected (techs never "unlearned"), but assumption flagged.

**No duplicate files across tiers**: for given `category/base_name` (incl. `lib` category), resolver walks from active tier down to `0_cold_boot`, uses first file found. Higher tier needs own copy only when behavior genuinely diverges.

**lib/ from `2_libunlock` on = every module of every tier** (`lib_chain()`, `LIB_UNLOCK_TIER_NUMBER = 2`): after the active tier's chain, the resolver also walks every HIGHER tier (ascending). A module defined at or below the active tier resolves through the normal chain, so a higher tier's override of an existing module stays gated (today only `5_steampower/lib/power.py`). A module that only exists in a higher tier is deployed anyway (idle until its machines exist) — so entrypoints never need a per-tier copy just to import a newer lib (e.g. the Mixer gate idles inside the single `control_room_automation.py`). Pyright's `.pyright-resolved/lib` uses the same chain.

**Library registration hook** (`register_new_libraries()`, runs after every lib mirror in `once`/`watch`; standalone `python devtools/scripts_sync.py register-libs [--dry-run]`): a file written into the save's `lib/` is **not** seen by the game until it is registered as a Library (manually: Computer → Library → + New, same name — the game then picks up the file on disk). The hook does the same as VS Code's **Import File as Game Library**: `action: "create-library"` with `name` (module stem) and `source` over the external-command channel (§8: `.codeterraform/command.json` + `command.lock` + `command-result.json`, `session` from `codeterraform-workspace.json`), for every deployed module missing from `context.libraryScripts`. Needs the game running with the save open; otherwise it warns and the next sync retries. `duplicate_name` counts as already registered. Source limit 200,000 chars (`interpreter.maxSourceLength`). It only registers new modules; applying a *changed* registered lib still needs the in-game "Apply & restart all" (§8).

**Global (untiered) categories**: category dir directly under `scripts/` (sibling of tier dirs, e.g. `scripts/contract/`) not gated by any `.criteria`. Always included, merged on top of active tier resolution (`list_global_categories`/`resolve_global_category` in `scripts_sync.py`). Contracts live here: genuinely tech-independent, self-contained (no imports), available from very first save, not tied to any progression tier.

**`panel` and `automation` = role-matched slot types** (`ROLE_MATCHED` in `scripts_sync.py`). Sources at `scripts/4_controlpanel/control_panel/<role>_panel.py` (Control Room cards) and `scripts/4_controlpanel/automation/<role>_automation.py` (Computer > Automations): separate, genuinely different hand-authored scripts (§7), not interchangeable template copies. The game picks `panel_N` / `automation_N` slot numbers per save and can't rename them, so a live slot is paired with its source by role (`role_for_slot()`), in this order: (1) `# ct-<type>: <role>` marker in the slot's code (`_<type>` suffix optional; every source carries it on line 1, so every filled slot has it); (2) slot's first comment line equal to a source's first comment line after the marker (bridges slots filled before markers existed); (3) an **empty** slot takes the one role no other slot of its type holds yet. Several unpaired roles → skipped with a warning; type `# ct-<type>: <role>` into the slot in game to choose. A marker naming no source is reported, not guessed past. Role-matched slots are never staged to `_unmatched/`. A role source is any resolved script whose stem ends in `_<type>`. An automation slot is a top-level `automation_N.py` in the save folder, listed in the workspace's `context.automations`; `"action": "run"` restarts it like any slot. Deleting a panel/automation in game keeps its `.py` file and its code (Scripts > Unassigned) but drops it from `context.customPanels`/`context.automations`; such a slot is skipped and holds no role (`unassigned_slot()`).

**Orphaned slots** (`sweep_orphans()`, every `once`/`watch` pass and the `watch` 5 s poll): the game never deletes a slot's `.py` file. A slot whose machine was sold/decommissioned, or whose panel/automation was deleted for good, leaves `context.scripts` and is listed in `abandonedPaths` of the save folder's `codeterraform-scripts.json`. A file that matches both is moved to `devtools/.sync-backups/orphans/<save>/` (never deleted), so it is not pushed and does not clutter the save. A slot's file is its workspace `name`, which can differ from its id (contract `contract_lattice` → `lattice.py`; `slot_scripts()`/`slot_id()`, the external-command channel takes the id); a stray `<id>.py` next to such a slot is moved too. A blank file staged in `scripts/_unmatched/` for a slot that is gone is dropped. Unassigned panels/automations (still in `context.scripts`) stay. `status` lists what the next sync would move.

**Pyright/IntelliSense**: `pyrightconfig.json`'s `extraPaths` point at `.pyright-resolved/lib` (regenerate with `python devtools/scripts_sync.py resolve-preview`, gitignored) plus `.pyright-resolved/stubs`, a copy of the save's game-API stubs. The copy drops the game's `isinstance`/`issubclass`/`callable` declarations (`NARROWING_BUILTIN_DEF`): they are plain `-> bool` functions that would hide typeshed's and disable Pyright's type narrowing. Game-injected per-script `self`/`panel` stay undeclared, so Pyright reports them as undefined in entrypoint scripts. Modules that only exist in a higher tier resolve too from `2_libunlock` on (`lib_chain()`); only a higher tier's *override* of an existing module needs `resolve-preview --force-tier <name>` to preview. Game's own in-editor syntax highlighting/autocomplete (tied to `codeterraform-workspace.json`) doesn't apply to source outside save folder at all → check deployed copy in save folder when needed.

**Autoplay** (`--include-autoplay` on `status`/`once`/`watch`/`register-libs`/`apply-libs`): `merge_autoplay()` adds `autoplay/*.py` to the script index and `autoplay/lib/*.py` to the lib index, untiered; a key `scripts/` already resolves stays with `scripts/` (reported as an `AUTOPLAY` conflict). Off by default, so the planner never ships by accident. Its entrypoint is the Automation role `infra_planner_automation` (`# ct-automation: infra_planner_automation`): create an Automation in game; an empty slot takes it when it is the only unpaired role, else type the marker into it. Runs without the flag leave deployed autoplay files alone (no match = no push).

**Push + restart** (`once`/`watch`, `sync_file()`): every save slot with a match is overwritten with its resolved source (placeholders rendered, own id renumbered) whenever the two differ; old copy backed up to `devtools/.sync-backups/`. In-game edits to a matched slot are therefore reverted — edit in `scripts/`. A slot with code and no match is left alone; an empty one with no match is staged to `scripts/_unmatched/`. After a write, `restart_in_game()` sends `"action": "run"` (§8) with the new source if the slot's workspace `status` is `running` or the slot was just filled from empty; retries `RESTART_RETRY_DELAYS_S = (0.5, 1.0, 2.0)` (~3.5s) while the game hasn't registered a new slot yet. **No restart when the script reaches an unapplied lib**: `libs_awaiting_apply()` = resolved `lib/` modules whose source differs from the game's `deployedSource` (or with no Library yet); `libs_reached()` walks the script's import closure (`lib_dependency_closure()`, `ast`-parsed). The workspace file lags the game by minutes, so a `nothing_pending`/`already_applied` answer counts as applied. Off by default: an apply restarts every running importer. Without it, the operator presses in-game **Apply & restart all**. **Recovery** (`recover_scripts()`, after every sync pass, for `RECOVER_SETTLE_S = 10` s after an apply, and on `watch`'s 5 s cycle): once every lib it reaches is applied, restarts a held-back slot (held slots persist per save in `devtools/.sync-backups/held_restarts.json`, so a later `once`/`watch`/`apply-libs` run restarts them after an in-game Apply; deleted slots are dropped), and any script with workspace `status == "error"` that this process pushed or that reaches a lib it wrote (e.g. an `ImportError` against a half-applied lib set). A script is restarted again only after its source or the applied libs change (`note_restart()` records source, apply generation and the run serial it replaced, so a stale `error` in the lagging workspace file is not mistaken for a new one); a repeat error under the same state is reported once. Errors in scripts the tool never touched are left alone. `report_unapplied_libs()` prints the full list of affected save scripts once per change (`watch` re-checks every 5 s, so an in-game Apply clears it). `--no-restart` pushes only. `status` shows per slot: up to date / would fill / would push, and blocking libs. **Hold** (`watch` only): while `devtools/.sync-backups/hold` exists, `Watcher.drain()` queues every change (no push, restart or recovery); removing it pushes the whole batch in one rebuild. - `devtools/step_profile.py`: counts CPython opcodes of one lib code path on the sample world, total and per function (inclusive), with a steps/ticks estimate (`OPCODES_PER_STEP = 2.5`, scheduler share at `--scripts`, default 112). Stub and `copy` frames are not counted. Work inside `run_atomic()` is reported apart (calls, opcodes, largest single call) and counted as at most one tick per call; `--direct-only` lists functions by the opcodes left outside atomic calls. `--list` shows the targets (`fabricator`, `smelter`, `dock_plan`, `demands`, `haul`, `pull`, `wildlife_ration`, `wildlife_plan`); add one per hot path worth tracking. Use it to compare code versions and to size `lib/atomic.py` chunks by their worst case; the numbers are estimates, not game measurements (§1d-1, `docs/BENCHMARK.md`).
- `devtools/log_block_timing.py`: reads the newest save's per-script logs (`logs/<script>.log` and rotations) and times every TreeConsole block (`┏━`/`┗━`) per script kind: count, median/max, median in ticks, self time without timed children, total and share of the observed window. Debug blocks are timed by their `HH:MM:SS` game clock, info blocks by tick, joined by a game-seconds-per-tick ratio calibrated from the logs. Times are wall game time and include sleeps/waits; `--exclude` drops travel/wait blocks, `--since <ISO>` measures only code deployed after that time (check `git log` for earlier perf commits on a block before reworking it). The census lines (§1d-1) give N over time: `med_N` is the median N at the blocks' start, `med_st` the median cost in steps (ticks × `floor(50000 / N)`), comparable across windows with different N; `--sort steps` ranks by total steps. Without census lines both columns show `-`.
- `devtools/repeat_read_scan.py`: static scan of the highest-tier copy of every file under `scripts/` for game reads (`stacks()`, `buildings()`, `get_component()`, ...) and calls into functions that do them, made inside a loop or comprehension. Score = read weight × `LOOP_N` (8) per enclosing loop, callees summed by bare-name resolution; flags `invariant` (direct read without loop-bound names, hoistable) and `atomic` (reached from `lib/atomic.py` runners, ×0.1). Joined with `log_block_timing.py` (same `--since`/`--exclude`), hits are grouped under the slowest timed block whose `log.start()` function reaches them; `[waits]` marks blocks whose code can `sleep()`/`mine()`. Heuristic: verify each hit in code and check `git log` for earlier perf work first. `--no-logs` gives the static ranking.
- Test files per module (`test_production.py`, `test_smelter.py`, `test_fabricator.py`, `test_site_supply.py`, `test_factory_sites.py` for per-site targets, the site plan, consumer hauling, stranded ore eviction and remote docks), home and remote-outpost cases.
- Pyright: `pyrightconfig.json` has a `tests` environment resolving lib imports via `.pyright-resolved/lib`, falling back to `scripts/4_controlpanel/lib`.
- Typed `self` in scripts: every non-`lib/` script that uses the game-injected `self` declares its type with `from typing import TYPE_CHECKING` / `if TYPE_CHECKING:` / `    from user_stubs import <name> as self`. `TYPE_CHECKING` is false in game, so the import never runs. `<name>` is the slot prefix (`o2gen`, `heater`, `drone`, ...), the contract id for a contract script, or an entry in `STEM_ALIASES`/`SELF_TYPE_OVERRIDES` (`devtools/self_typing.py`). The names live in a marked block at the end of the save's `user_stubs.py` (player-owned: the game creates it once and never overwrites it; the in-game editor, the VS Code extension and Pyright all read it). Every sync rewrites that block in the save (`sync_user_stubs()`, text outside the block kept, backup in `devtools/.sync-backups/`), and `resolve-preview` writes the merged copy to `.pyright-resolved/stubs/user_stubs.py`. The block is generated from the game's language server (`external-ide/server/server.cjs`, `scriptPrefix` + `machines.<type_id>.name`) and the save's `__builtins__.pyi` (class = PascalCase of `type_id`, else matched by display name). A prefix shared by several types (`drone`) is a union; each contract gets a `ContractScript` subclass typed with its own `<Id>Contract`. New script: `python devtools/self_typing.py apply`; `tests/test_self_typed.py` fails on a script that uses `self` without the declaration.
