# Dev Tooling: Profiling, Machine Activity, Tiered Sync (§1d, §9)

Part of [`AI_CHEATSHEET.md`](../AI_CHEATSHEET.md).

### §1d Per-Script Tick-Cost Profiling (`lib/profiling.py`)

Game exposes no per-script CPU/ms budget API. `clock.tick()` (deterministic
sim tick since save start, 10 ticks/sec normal speed) = sanctioned stand-in per
`docs/components/clock.md`. `lib/profiling.py` wraps pattern so any controller's `run()` loop
measures own `step()` with two calls:

```python
start = profiling.begin()
self.step()
profiling.end(self.name, start)   # logs a warning if delta > SLOW_STEP_TICK_THRESHOLD=1
```

- Samples roll into `archive` as one fixed-size history list per script name
  (`ARCHIVE_KEY_PREFIX="profiling."`, `HISTORY_LEN=50`) — one archive entry per profiled *script
  name*, not per sample, respects Data Archive's hard 2,048-entry cap.
- `profiling.report(names=None)` prints avg/max ticks-per-`step()` for every profiled name (or
  subset) — call ad hoc, not from hot loop.
- **Granularity**: a script gets a fixed step allowance per tick (§1d-1), so `step()` spans `steps / allowance` ticks and a tick delta does measure its cost, in whole ticks. A `0` means the step fit into the rest of one tick's allowance (up to ~300 steps with ~165 scripts running), not that it was free. `SLOW_STEP_TICK_THRESHOLD=1`: any nonzero delta is worth a look. For sub-tick costs, count operations (docs/BENCHMARK.md) or time a loop in `devtools/perf/panel_benchmark.py`.
- **Not currently wired into any script.** `lib/profiling.py` and `lib/archive_cleaner.py`'s
  cleanup of it kept for future script suspected of real bulk per-call work.
- **Storage shape & cleanup**: each archive entry `{"history": [...], "last_tick": N}`.
  `lib/archive_cleaner.py`'s `clean_profiling()` purges entry whose `last_tick` not advanced
  in `PROFILING_STALE_TICKS=6000` (10 sim minutes, "instrumentation removed"), always purges
  legacy bare-list entries. Runs in
  `ArchiveCleaner.run()`'s normal sweep.

### §1d-1 Script Cost Model (measured, [`docs/BENCHMARK.md`](../BENCHMARK.md) "Load dependence")

- **Step allowance**: `allowance = max(1, min(1000, floor(50000 / N)))` steps per script per tick, N = scripts whose status is `running`, `waiting` (in `sleep()`, a Signal Bus wait, or the pause after a console write) or `flushing`; completed, stopped, paused, errored and breakpoint-halted scripts don't count (game scheduler, from the decompiled simworker (`internals/`, private submodule): `interpreter.stepsPerTick = 1000`, `interpreter.totalStepsPerTick = 50000`). So ≤ 50 running scripts: full speed (100 µs of simulation time per step). Above 50: `100,000 / allowance` µs per step, 303 steps (≈ 330 µs) at N = 165; each extra script shrinks everyone's allowance by a factor `(N−1)/N` (~0.6% at 165), each removed one grows it likewise. How busy the scripts are does not matter.
- **What this means for code**:
  - Fewer steps per poll make *that* script react sooner (a planning pass finishes in fewer ticks); they barely help other scripts. Shorter sleeps likewise cost only the script itself.
  - The lever for the whole base is the **number of running scripts**. Setpoints (`set_tilt`, `set_throttle`, `set_power`, `set_intake`, all *self only*) hold only while the machine's script runs: a script that ends, or `run_control.stop()`, drops them to idle (solar tilt back to 90°, measured). So a machine that needs a held setpoint needs a running script; one whose idle state is acceptable (off, no recipe running, night) can have its script end and be restarted with `run_control.start()` when there is work.
  - Work duplicated across instances (e.g. every Smelter walking the demand tree) costs only those instances their own latency, not other scripts. Centralizing it into one script trades their latency for that script's; it is not a base-wide saving.
  - The base as a whole gets at most 50,000 steps per tick once N ≥ 50, whatever N is; more scripts only split it. Don't split work into helper scripts for throughput, and don't borrow idle machine scripts for unrelated computation; split only where a slow task delays a script that must react quickly (e.g. the headless panel's grid supervision), and measure that delay first. A script that uses its whole allowance 30 ticks in a row raises the game's `scriptBudgetPressure` event.
  - Console writes and `sleep()` cost 0.1 s of the script's own time each (debug lines are buffered, §0a).
  - **Census** (`lib/script_census.py`, `census_if_due()` from `orchestrator_automation.py` `park_if_due()`): every `CENSUS_TICK_INTERVAL = 300` ticks counts `run_control.is_running()` (atomic batches of `CENSUS_CHUNK = 100`; the machine rows are built and de-duplicated in atomic batches of the same size) over every outpost building, Harvesting-field machine, mobile unit, the mobile Harvester (`HARVESTER_ID`) and the POI extractors (`POI_TYPE_IDS`, which `outpost.buildings()` omits; found as `power_control` grid members), plus probed panel and automation ids (`panel_1..` up to `PANEL_PROBE_LIMIT = 40`, `automation_1..` up to `AUTOMATION_PROBE_LIMIT = 10`, extended `PROBE_AHEAD = 40` past the highest id found; no API lists them). Panels/automations count toward N only. Sensor and planet scripts (boot, uplink, ...) are not listed, so N is a lower bound. Logs debug `scripts running: N of M machines (incl. P panel/automation scripts; ...), allowance A steps/tick` (M counts machines only). `is_running()` is per machine, so a machine with scripts in several slots counts once. `census_if_due()` returns its `snapshot()` (`machine_refs()` rows `(id, kind, name, mobile)`, running machine ids, running panel/automation ids; the activity sample ignores the last), which feeds the machine activity sample (§1d-3).
- **Scheduler details** (same source):
  - **Breaker pause** — the one documented lever: `power_control.set_powered(id, False)` pauses the machine's script (status `paused`, not counted in N) and preserves its setpoints; `set_powered(id, True)` resumes that script where it stopped, Python state intact (docs/components/power_control.md). Only machines with a breaker (`can_power_off()`). Measured with a breaker: bio_caster, bio_collector, bio_exchange, bio_lab, charging_station, drone_service_station, drone_station_large, fabricator, garbage_disposal, oil_generator, oxygen_generator, plant_terraformer, pressure_generator, seed_maker, smelter, steam_condenser, steam_turbine, supply_dock, temp_heater, weather_station, and (probed by id, as `outpost.buildings()` does not list them) water_pump, oil_pump, thermal_cap, crop_automator, mining_drill_heavy. Without: solar_generator, harvester, scanner, battery, battery_large, bulk_liquid_reservoir, gas_tank, warehouse, large_warehouse; mobile units have none. A machine without a breaker can only leave N through `run_control.stop()`/`start()` (setpoints reset, script restarts) — acceptable for solar at night, when output is 0 W anyway. `PowerGridManager` load shedding (§1a) uses the same breakers, so a parked machine must not be confused with a shed one.
  - **Callbacks run as one unit**: each call of a Python callback from `map`, `itertools.starmap`, `sorted`/`list.sort`/`min`/`max`/`heapq.nsmallest`/`nlargest` with `key=`, the body of a `functools.lru_cache`/`cache` function on a cache miss (nested cached calls count toward the outer miss), and the `archive.transaction` updater runs without a budget check inside it, capped at `stepsPerTick × 10` = 10,000 steps (`StepLimitError` beyond). The cap comes from the fixed interpreter config, not the Advanced Scripting settings (those only switch the string limit 10,000 → 100,000 and the collection limit 10,000 → 50,000). `StepLimitError` cannot be caught by `try/except` (only Python exceptions and `RecursionError` can) and ends the script, so chunks must be sized well under the cap at their worst case: the Harvester search chunk (`EXPAND_CHUNK_NODES = 40`, bucket entries plus bucket advances) peaks at ~3,800 interpreter operations. The budget is checked only between callbacks and resets every tick, so a callback can overrun the tick's allowance without being charged later. What a callback may call (decompiled `validateNativeCall`): game reads without side effects (`get_component()`, `stacks()`, `count()`, `fleet.vehicles()`, `outpost.buildings()`, Harvester `cells()` and `Cell` attribute reads, confirmed headless 2026-10-24) are allowed and uncharged; a call that changes game state or observes (`set_enabled`, `connect`, `take`, archive writes, scans) or suspends (`sleep()`, waits, `mine`) raises `RuntimeError` (catchable, but it aborts the callback); remote writes raise `PermissionError` as anywhere. `console.print()` counts as a world change, so a log line in a callback raises too; `lib/atomic.py` runners queue every write made through `atomic.console_print()` (all `TreeConsole` levels, `swallowed()`) and write them in order after the outermost `run_atomic()` returns or raises, stamped with the `console.now()` of when they were logged (a plain read). So code that logs through its passed-in `log` can be made atomic unchanged; raw callbacks outside the runners (`sorted(key=)`, `lru_cache`, ...) must still not log. So `lru_cache` fits only small pure helpers (`field_layout.sector_to_rc()`/`neighbours()`/`automator_area()`); the whole-layout builders (`_full_parts()` ~33k steps, `full_layout()` up to ~19k) keep dict memos. Measured (~330-step allowance): 1,000 iterations of pure arithmetic (~7,700 steps) take 23 ticks as a direct call and 1 tick inside one `map()` callback. With work split into chunks of ≤ 10,000 steps, `map` over the chunks runs one chunk per tick. Engine quirk that a game update may close; the 50,000-step total exists to protect frame time, so use it only for a few heavy pure computations, behind one helper: `lib/atomic.py` (`run_atomic(fn, *args)` runs one call as a `map()` callback; `run_batched(fn, items, size, *args)` runs `fn` on each `size`-item slice as one call and joins the returned lists; `run_chunked(step_fn, state)` repeats bounded chunks until `step_fn` returns True; `ATOMIC_ENABLED = False` calls directly). Used by the drone hauler and Pioneer route planners (`logistics_requests.route_atomic_ok()`, `docs/cheatsheet/vehicles_drones.md` **Plan**), the Constructor Pioneer job scan (`lib/construction_plan.py`, `JOB_CHUNK`/`TRIP_CHUNK`/`PROGRESS_CHUNK`), the Wildlife planner (`lib/wildlife_planner.py`: the whole `build_plan()`, `MODEL_CHUNK`; tank discovery and reads, `TANK_CHUNK`), `storage.warehouse_stocks()` (`stacks()` reads, `STOCKS_CHUNK` Warehouses per call) the Harvester route search (`lib/harvester_heat.py`, `EXPAND_CHUNK_NODES`) and the Harvester's cell read and scans (`harvesting.read_cells()`, `lib/harvester_pure.py`, docs/cheatsheet/planting.md).
  - **Import-time code** (module bodies of libs) runs synchronously and is capped at 10,000 steps too: keep heavy precomputation out of module bodies and build it lazily. The cap covers the whole chain below one import statement plus the steps its execution spent before it; `devtools/perf/import_steps.py --save SAVE` counts each slot's chains headless and fails over 90 %.
  - **Callback peaks**: inside a callback each statement checks the step counter of the whole tick slice, so the steps the script spent that tick before the callback count against the 10,000 too (the callback's own steps are checked against the same cap at its end). `devtools/perf/callback_steps.py --save SAVE` reports each slot's peak per callback headless (a `run_atomic()` slice by the fn it runs) and fails over 90 %. A peak of exactly 10,000 may be a crash (some checks throw at `>=`; the run's `console.log` shows real ones); a callback that suspends and is retried counts once per attempt.
  - `sleep()`, Signal Bus waits and the pause after a console write all leave the script counted in N (status `waiting`/`flushing`).
- **Measuring**: `devtools/perf/panel_benchmark.py` with `QUICK = True` (empty loop, `len()`, call, component call; min/median/max) in a Control Room card. Compare runs that differ only in which scripts run. Heavy scripts can report their own phases in ticks, like the Harvester's `planned in … (N ticks: phase n, …)` note (§1k). Offline, `devtools/perf/step_profile.py` estimates a code path's steps per function on the synthetic `tests/sample_world.py` save, and `devtools/perf/tick_profile.py` times functions in ticks on a real save in the headless sim (§10).

### §1d-2 Script Parking (`lib/script_parking.py`, client side `lib/parking_client.py`)

Takes idle machines' scripts out of the running-script count (§1d-1).

#### Machine side

- **Machine side** (`ParkRequester(machine_id, kind)`, `update(idle, wake_after=None)` once per step): after `PARK_AFTER_IDLE_STEPS = 3` idle steps in a row it files `{"kind", "tick"[, "wake_after"]}` in `script.park_requests` (refreshed each further idle step); the first busy step withdraws it. Wired into Smelter/Fabricator (`step()` returned not active), Supply Dock (standing by: no order, no cargo) Oil Generator (neither mode burning and no deficit without oil, §1c-1), Oil Pump (well dormant; Water Pumps are not parked: they run at full throttle and a stall can be a routing problem the pump itself resolves), Exotic Gas Cap / Spring Tap (kind `exotic_cap`, `lib/exotic_cap.py`: deposit dormant, buffer no longer releasing, and Deep-survey `next_phase_in()` leaves at least `EXOTIC_PARK_MIN_TICKS = 600` after `EXOTIC_WAKE_LEAD_TICKS = 150`; files `wake_after` = time left − lead. Common deposits cycle in under a minute of real time, so they normally never park), Crop Automator (in the layout, not shed, nothing queued or finished, no new job; mature crops waiting for output room don't count as work; strays keep running to empty themselves; `storage_take.take_item()` wakes an automator before pulling Forage from it only when the pull leaves room for one harvest (`crop_automator_wake_free()`), `wake_for_visit(..., hold=False)`) and Thermal Cap (vent dormant and chamber ≤ `CAP_PARK_MAX_PRESSURE = 0.02`, filing its own wake time: when `next_phase_in()` is known, the time until the vent turns active minus `CAP_WAKE_LEAD_TICKS = 150`, no request when that leaves under `CAP_PARK_MIN_TICKS = 600`; else `CAP_PARK_WAKE_FRACTION = 0.5` of the time the fastest confirmed pressure rise needs from empty to `PRESSURE_BAND_CRITICAL`; no request without either); an exception counts as busy.
#### Panel side

- **Panel side** (`ScriptParking.step(grids, elevation, dock_plan)`, orchestrator_automation.py `park_if_due()` every `PARKING_TICK_INTERVAL = 50` ticks, checked each loop and between the storage pass's sub-steps; every `PARKING_FULL_TICK_INTERVAL = 150` ticks a full pass, otherwise a fast pass (`full=False`) that only wakes and starts stopped solar scripts after sunrise, on the last full pass's member rows and oil surplus verdict, and measures no grids: parking, the powered-again and orphan checks, the night solar stop and strays wait for the next full pass; in the live save a full pass costs ~28 ticks, a fast one ~12; a fast pass returns before any archive read while no timer is due (`now < next_due`, the earliest `since + wake_after` over breaker and paused entries, or none parked; kept in the instance and lost on a restart, whose first pass is full), no solar script stopped here waits for a risen sun and no parked Oil Pump reads `well_active()`; it then leaves no debug block, so `log_block_timing.py` counts only passes that did work, and its oil surplus wake, Exotic Cap deposit poll and dropping gone or player-resumed entries wait for the next full pass): parks a request not older than `REQUEST_FRESH_TICKS = 150` with `power_control.set_powered(id, False)` if the machine is on a grid, has a breaker, and is not in `power.shedded`; a dock is not parked while the dock plan assigns it an order, an Oil Generator not while its grid is low (below). Parked machines live in `script.parked` `{id: {"kind", "mode", "since"}}`; only ids listed there are ever switched back on; an id whose component is gone, or that reads powered again (`is_powered()`, e.g. the player flipped its breaker), is dropped (its pre-park request cleared). Each park is written to `script.parked` in its own transaction *before* the breaker goes off (removed again if `set_powered` fails), and the pass's other changes are applied as a diff in one transaction, so a script killed mid-pass never leaves an untracked dark machine and entries other scripts wrote meanwhile (`turbine_commit`, `wake_for_visit()`) survive. **Orphan backup scan** (`_adopt_orphans()`): a grid member that reads off at its breaker, has a park request older than `REQUEST_FRESH_TICKS`, and is in neither `script.parked` nor `power.shedded` is re-adopted into `script.parked` with its request tick as `since` (warn line `Re-adopted N untracked dark machine(s)`), so its wake re-check is due on the next pass. The API cannot tell a game outage shutdown (which the game recovers itself) from a breaker-off, so an outage-dark machine with a stale request can be adopted too; its wake then only switches it on early.
#### Wake

- **Wake** (`set_powered(id, True)`, the script resumes where it paused and parks again on its own if still idle): after `WAKE_AFTER_TICKS` (smelter 3000, fabricator 3000, supply_dock 3000 (backstops: demand and order wakes are the real triggers), oil_generator 6000 (backstop: the low-reserve wake is the real trigger), thermal_cap 600, oil_pump 3000, exotic_cap 6000 (backstop), crop_automator 600, charging_station 3000, drone_service_station 3000, drone_depot 3000, field_provider 6000, seed_maker 3000, feed_maker 3000, fuel_assembler 3000, pioneer 3000, drone 3000), or the machine's own `wake_after` (capped at `MAX_WAKE_AFTER_TICKS = 6000`), a Smelter as soon as a Fabricator at its outpost finds no stock of one of its outputs (`fabricator.wake_local_smelters()`), a dock as soon as the plan assigns it an order (`supply_dock._wake_for_plan()` in `plan_dock_assignments()`, `wake_for_visit(dock, hold=False)`), Fabricators and Smelters as soon as their demand rises. **Demand wake at the writer**: `wake_on_rise(kinds, before, after, label)` wakes every parked machine of each kind (`wake_kind()`) when any amount in `after` exceeds its `before`; called by `production_orders._set_requester_order()` (`fabricator.orders`, kind `fabricator`), `production_demand.ingot_stock_levels()` when it seeds a target (`smelter`), `site_plan.plan_sites()` on a new (root, site) pair (`fabricator`). **Demand wake after the record**: `DemandPublisher._publish()` (`lib/demand_publisher.py`) calls `wake_risen(previous, signature)` after each publish but a script's first: per kind of `demand_signature()`, a new key or a larger amount wakes that kind (reason `demand changed: demand record: <item>`). This is the dock-order wake (both kinds) and covers the blueprint keys; a writer's own wake lands before the record carries its change, so a machine woken then reads the old record (`STALE`), finds nothing and parks again. `wake_kind()` clears the woken machines' pre-park requests. **Backstop** (full passes only; a fast pass skips it and the `order assigned` check): `ScriptParking._demand_wakes()` compares `_demand_signature()` with the previous pass's, kept in the instance, the first pass only records it; it reads `fabricator.manual_orders` and `fabricator.orders` (summed per item) and `fabricator.site_plan` (one entry per root and site) for kind `fabricator`, `production.ingot_stock_targets` (the `target`) for kind `smelter`, and the order ids in the dock plan for both kinds, whose items are not read; a new key or a larger amount wakes every parked machine of that kind with reason `demand changed: <item>`, a fall never does, and a kind that rose is not parked in that pass; the computed `production.demand` is not read because they shrink as stock arrives; 5 archive reads and a loop over their entries per 50-tick pass), Oil Pumps as soon as `well_active()` reads true (readable from any script), Exotic Gas Caps / Spring Taps as soon as `deposit().current_phase()` reads `"active"`, Oil Generators as soon as their grid's lower of battery / combined reserve fraction drops below `OIL_WAKE_RESERVE_FRACTION = 0.40` (their own start line is 0.30): **at the writer**, `PowerGridManager.supervise_grid()` (every `SOLAR_TICK_INTERVAL`) calls `power.reserve_is_low()` and, on the drop (the `reserve_low` edge), `wake_kind("oil_generator", ..., within=<the grid's machine ids>)`; the full pass's `_low_reserve_grids()` (same `reserve_is_low()`; unreadable reserve also wakes) is the backstop for a generator parked while its grid is already low. Oil Generators also wake while the network-wide oil tank fill is `≥ OIL_SURPLUS_WAKE_FRACTION = 0.90` (`oil_generator` surplus base load, §1c-1; not parked then either). Requests filed before a machine was parked are cleared on wake. **Re-check backoff**: a machine of a `WAKE_BACKOFF_MAX_TICKS` kind (crop_automator 1800; the event-woken kinds use a fixed long `WAKE_AFTER_TICKS` instead) that files its next park request within `FRUITLESS_REPARK_TICKS = 150` of a `re-check due` wake found no work (the request's own tick counts, since passes can run further apart than that window), so its next `wake_after` doubles from the kind's `WAKE_AFTER_TICKS` (`<< streak`) up to that cap; a later request (it worked) or any non-timed wake (a demand wake included) resets the streak (kept in the `ScriptParking` instance, not the archive). A machine-filed `wake_after` is never changed. `wake_kind(kind, reason, within=None)` wakes only the ids in `within` (None = all, empty = none). The backstop's reserve read takes the grid's Gas Tank ids from the pass's member rows.
#### Per-kind rules

- **Field providers** (Grow Lamp, Sprinkler, Dispenser; kind `field_provider`): park while switched off (no layout crop beside them needs their service), not shed and not a stray; the breaker keeps `set_enabled(False)` (ending the script would too, but a lit one must stay powered, so only off ones park, and central on/off is a blocked remote write). Woken by `parking_client.wake_kind("field_provider", reason)`, called by `harvester_planting` after writing `plant.layout` and by `seed_supply` when the `plant.recipes` it writes differ from its last write this run; re-check every 6000 ticks otherwise.
- **Seed Maker** (stage B `SeedSupplyController`, kind `seed_maker`): parks when its step returns `SUPPLY_IDLE_POLL_SECONDS` (no seed deficit). Re-check every 3000 ticks, below `logistics_requests.REQUEST_STALE_TICKS = 6000`, so its life-form stock requests are republished before they expire; `harvester_planting.publish_seed_demand()` calls `wake_kind("seed_maker")` when its `now` demand changes (non-empty). Stage A (discovery sweep) is not parked.
- **Scanner** (no breaker): its script ends once every sector of the grid is mapped.
- **Drone Depots** (kind `drone_depot`, all three sizes): park when `DroneDepotController.parkable()`: no drone docked, no stage request, stockpile empty (life forms too: a hauler or the Liquifier `take()` from it). Woken by `wake_for_visit()` from `drone_navigation.fly_to_station()` (every depot or service visit; renewed every `VISIT_HOLD_RENEW_TICKS = 1000` ticks of flight) and `depot_stage.request_stage()` (a hauler's pickup, so staging runs while it flies there). Held like stations (`HELD_KINDS`), no last-awake rule.
- **Vehicles** (Pioneers, drones; `PAUSE_KINDS`, mode `"paused"`: no breaker, so `run_control.pause()` / `resume()`). Vehicle side (`fleet_unit.FleetUnitMixin.park_update(job)`, after every `run_job_loop()` cycle, `PARK_KIND` `pioneer` / `drone`, Rovers none): files a `ParkRequester` request carrying its `role` while `parkable()`: a no-work state (`IDLE*`, `SURVEY_COMPLETE`; not `READY_*` or off duty), `job.parkable()` (`PullJob`: only `no demand`, since arriving stock wakes nothing) and `park_spot_ok()`. Pioneer: at its base slot, where the Charging Station charges it while paused (`manage_docked()`). Drone: game status `idle` and not in a Depot bay (hovering, or docked at a drone_service); hovering burns nothing and a paused docked drone does not charge, so no charge gate. Panel side (`_pause_vehicle()`, full passes): pauses a fresh request unless a command is pending, its role has new work this pass, or its `fleet.status` state no longer reads idle (or reads off duty). `_wake_paused()` (every pass) resumes on: re-check due (`WAKE_AFTER_TICKS` 3000, below the 6000-tick heartbeat windows of `logistics_requests.HAULER_FRESH_TICKS` and `construction_plan.PEER_BUILDER_ACTIVE_TICKS`, so the woken vehicle republishes its entry in time); a command for it (`_vehicle_commands()`: `vehicle.recall` / `drone.recall`, `fleet.decommission`, a `fleet.upgrade` drone entry in `UPGRADE_WAKE_STATES` (`ordered`, `requested`), `vehicle.sport_nav_request`; 5 archive reads, on full passes only while any vehicle is paused; a fast pass resumes on re-check due alone); new work for its role (`_work_wakes()`, full passes, read only while a vehicle of that role is paused or asks to be; `WORK_READERS`: `hauler` = a new `outpost item` among `logistics_requests.active_requests()`, `builder` = a new pending or paused construction job id; the first read only records). A command resumes its vehicle at the writer, after the archive write, through `parking_client.resume_vehicle()`: `vehicle_claims.set_vehicle_recalled(True)`, `drone_claims.set_drone_recalled(True)`, `fleet_decommission.request_decommission()`, `pioneer_upgrade.request_sport_nav()` and `fleet_upgrade._start_next_drone()` (the drone entry entering `ordered`). The writers wake on every set call (a no-op on a vehicle that is not paused); the full pass's `_vehicle_commands()` is the backstop for a hand-edited key, which resumes within `PARKING_FULL_TICK_INTERVAL`. The same new work also resumes at its writer, before the next full pass: `logistics_requests.set_requests()` on a new `(outpost, item)` key calls `wake_role("hauler")` (after its archive write landed, so the woken hauler reads the new request), `machine_pack_upgrade` after a planned install calls `wake_role("builder")`; `wake_role()` and `resume_vehicle()` live in `parking_client`. `_work_wakes()` stays the backstop and the only path for player-placed blueprints (no script writer). An entry whose vehicle is gone, runs again (the player resumed it) or is no longer paused after a refused resume (stopped, errored) is dropped without a start. `wake_kind()` resumes paused vehicles too. `fleet_upgrade` counts a paused drone as alive (`parked_ids("drone", mode="paused")`) for a chassis swap; the `ordered` entry then wakes it. After a save load a paused script stays paused and `resume()` starts it from its first line. Measured headless (midlate sample save): one paused vehicle lowers N by 1; a drone paused in flight finishes the flight and docks.
- **Stations** (Charging Station, Drone Service Station; `STATION_KINDS`): park when their step has no work (no bay active or queued, no rescue, no vehicle they are responsible for below target). The last awake station of a type never parks (`_awake_stations()`, built once per pass), so a fleet scan always runs as the backstop for vehicles whose own script is not running. `wake_for_visit(id, reason)` (any script): holds the station awake for `STATION_HOLD_TICKS = 3000` (`script.park_holds`, `{id: until_tick}`; a held station is not parked) and switches it on if parked, clearing its pre-park request (`hold=False`: no hold, for kinds outside `HELD_KINDS`). Called by `vehicle_charging.recharge_at_station()` before driving there and every 5th wait cycle, `drone_charging.return_to_service_for_charge()` (also on each launch-charge re-check), `go_to_nearest_service()` and every 30 s of `refuel_at_service()`. Awake stations leave parked ones out of responsibility (`parked_ids(kind)`); when a vehicle needing attention (stranded, below return floor, or below its rescue target) is nearest to a parked station (`parked_nearest()`), the awake one wakes that station and leaves it the vehicle, so the nearest station still watches and rescues.
#### Strays, grid reads, solar, exclusions

- **Stray dark machines** (`_strays()`, end of each full pass): a grid member that reads off at its breaker (`powered` False) and is in none of `script.parked` (any mode), `power.shedded`, `script.park_requests`, the retired registry (`machine.retired`, `lib/retired_machines.py`) or the operator's `script.manual_off` (`{id: note}`). Typically a machine built before its grid had power: its breaker is off and its script never started. Tracked in `script.stray_dark` `{id: {"kind", "first", "stage", "breaker"}}`. Members with a breaker (`can_power_off()`, `"breaker": true`) go through three stages by time since first seen: (1) at once, a warn line naming `script.manual_off`; (2) after `STRAY_NOTIFY_TICKS = 600`, one `notify()` and a Status panel alert (`stray_alerts()`, every stage-2 id); (3) after `STRAY_SWITCH_ON_TICKS = 3000`, `set_powered(id, True)`, then `run_control.start()` when `status().state` is `"idle"` (`"error"`/`"completed"` scripts get a warn line and are not restarted). Members without a breaker are tracked silently, with no stages. The game switches a machine built before its grid had power on by itself once the subnet has power (`powerStartupPending`), but never starts its script: a stray that leaves the dark set powered, still a member and unowned (none of the lists above), gets `run_control.start()` when its script is `"idle"` (`_start_lit()`, one log line; `"error"`/`"completed"` get a warn line). Only machines first seen dark qualify, so a script stopped on a powered machine is never restarted. A stray switched on, or listed/owned meanwhile, leaves `script.stray_dark`. Other breaker owners therefore record what they switch off: turbine commitment (`"turbine"`) and the Biomass Mixer gate (`"mixer_gate"`) in `script.parked` under their own mode, retirements in `machine.retired`.
- **Grid member reads**: `_members()` reads every grid member's id/type/powered in atomic `run_atomic()` slices of `MEMBER_CHUNK = 150` (~31 steps each, a full chunk ~5.1k of the 10,000-step cap on 0839) and indexes them in the same pass (`_by_type` `{type_id: [ids]}`, `_dark` ids switched off). Station, Gas Tank, solar and stray lookups walk only that index, not every member.
- **Solar at night** (`solar_generator` has a breaker too, but at 0 W a stop costs nothing and tells a player-stopped script apart): elevation ≤ 0 → `run_control.stop()` every running `solar_generator` script (mode `"stopped"`); elevation > 0 → `run_control.start()` only those, on fast passes too. Tilt resets while stopped, output is 0 W then.
- Not parked: Reactors (heat returns to 0 when the script stops, §1c-4), terraformers (heater, O2 generator, pressure generator: they work until their target and are sold there, and do no work while unpowered), bio machines, turbines (parked by `PowerGridManager`'s turbine commitment instead, `lib/turbine_commit.py`, mode `"turbine"` in `script.parked`, which `ScriptParking` leaves alone), Water Pumps, mobile units.

### §1d-3 Machine Activity (`lib/machine_activity.py`)

Which machine groups have more members than their pooled work needs: retire candidates that would lower the running-script count (§1d-1).

- **Sample**: `record(snapshot, now)` from `orchestrator_automation.py` `park_if_due()` right after each census (§1d-1, every `CENSUS_TICK_INTERVAL = 300` ticks). Uses the census snapshot plus `fleet.status`, `script.parked` and `script.park_requests`; no calls on the machines. Classification and the per-group tally run in atomic `run_batched()` slices of `ACTIVITY_CHUNK = 100` machines, accumulation (decay loop over every class a machine has counts in) in slices of `ACCUMULATE_CHUNK = 40`, the group merge in slices of `GROUP_CHUNK = 10` groups.
- **Class per machine per sample**: `active` (vehicle/drone in a working state; running building without park request), `waiting` (vehicle/drone in `FLEET_WAITING_STATES`: `WAITING_DEPOT_SPACE`, `WAITING_DEPOT_BAY`, `WAITING_INVENTORY_SPACE`, `STRANDED`, `AWAITING_RESCUE`), `idle` (vehicle/drone where `fleet_status.is_idle()`; running building with an open park request), `running` (script runs, no idle signal: building group none of whose members ever filed a park request or was parked, i.e. no `ParkRequester`; vehicle/drone without a `fleet.status` entry), `parked` (in `script.parked`, any mode), `off` (neither running nor parked). Machines never running or parked (storage, tanks) are not tracked.
- **Group** (`group_of()`): building/field machine `type_id`; mobile unit kind (`drone_small/medium/large` → `drone`) + `:<role>` from `fleet.status` (`drone:miner`, `pioneer:hauler`, ...). Members of a group pool their work, so the group, not the single machine, says how many are needed.
- **Decay**: every count is multiplied by `0.5 ** (elapsed / HALF_LIFE_TICKS)` (`HALF_LIFE_TICKS = 216000`, ~6 h) before the sample adds 1; weights below `MIN_WEIGHT = 0.01` drop.
- **Spare** = `SPARE_CLASSES` (`waiting`, `idle`, `parked`, `off`). Per group: `spare_mean` = average spare members; `retire` = largest k with at least `SPARE_QUANTILE = 0.9` of the sample weight at k or more spare members at once (`spare_quantile()`), i.e. members the group could lose and still have had every busy member it used in 90 % of the samples. A group busy all night but idle all day gets `retire` 0.
- **Archive** `machine.activity` (single writer, `archive.set()`): `{"tick", "samples", "groups": {group: {"n", "sig", "w", "c": {class: weight}, "spare": [weight per spare count], "share": {class: %}, "spare_mean", "retire"}}, "machines": {id: {"g", "c", "l": class in the last sample}}}`. Machines and groups missing from the sample are pruned. View helpers: `group_rows(state)` (most `retire` first, then `spare_mean`, then name) and `machine_rows(state, group)` (`(id, {class: %}, last class, spare %)`, most spare first).
- **Log**: every `SUMMARY_LOG_TICKS = 36000` ticks one debug block `machine activity: …` with one line per group, most `retire` first: `<group>: N machines, active a% waiting w% idle i% … ; spare mean m, retire r`.
- **Card**: `activity_panel.py` (MACHINE ACTIVITY, panels.md §7) draws both views.
- Reading `waiting`: a Drone miner in `WAITING_DEPOT_SPACE` has work but the Depot cannot take it, so its output is surplus too; that is why it counts as spare.

## §9 Dev Workflow: Tiered `scripts/` + `devtools/scripts_sync.py`

Repo (`C:\Users\<user>\Code_Terraform`) = dev root, separate from live save folder (`%APPDATA%\io.codeterraform.game\save_*_scripts`). Source of truth: `scripts/<tier>/<category>/<name>.py`. `devtools/scripts_sync.py` (adapted from `inspirations/vakermit/bin/ct_sync.py`) pushes it into the save folder's numbered script slots and mirrors `lib/`. One direction only: no pull from the game. Full mechanics (push/restart, renumbering, `_unmatched/` staging) in tool's module docstring. This section covers project-specific tiering layer on top.

**Two meanings of "tier"**: the `scripts/<N>_name/` progression tiers here, and the load-shedding tiers of `PowerGridManager` (§1a). Context tells which is meant.

### Tiers and `.criteria`

**Tier list**: not hardcoded. `discover_tiers()`/`tier_number()` in `scripts_sync.py` scan `scripts/` for `<N>_<anything>` dirs, sort by `N` ascending (numeric, so `10_x` after `9_x`, not between `1_x`/`2_x`). Only number matters, rest of name free text. Numbers may skip. Add `scripts/6_derp/` (or `scripts/3_inbetween/` between two existing tiers) with own `.criteria` → picked up automatically, no code change. Dir starting with digit but not plain `<int>_...` (`1N3_DERP`), or two dirs claiming same number (`10_hi`/`10_ho`) → raise `TierNamingError`, no silent guessing. Each tier gated by `.criteria` file at root (absent for `0_cold_boot`, always-active baseline). Current tiers:

| Tier | `.criteria` | Unlocks (tech id / `research_*` id) |
| :--- | :--- | :--- |
| `0_cold_boot` | *(none — baseline)* | — : self-contained scripts, no `lib/` imports (Solar buyer to 70k TP, Bio-Loop, Smelter, Harvester, atmosphere generators) |
| `4_controlpanel` | `{"tech": ["automations_unlock", "data_archive_unlock"]}` | `research_data_archive` (70k TP): full `lib/` stack and the `orchestrator_automation.py` Automation (early build order §2m); its cards wait for Custom Panels (150k TP) |

Only two tiers on purpose: a tier pays off only where scripts are genuinely *replaced*, and that happens once, when `lib/` and the Data Archive arrive (70k TP). Everything that first deploys after that (Charging Station, Rovers, Pioneer, Supply Dock) has only a tier-4 script. Later machines need no gate (their slots only exist once the machine is built), and later behaviour changes switch at runtime instead (e.g. power phases, power_fluids.md §1a). Rationale: `DESIGN_HISTORY.md`.

`.criteria` keys use save file's own **tech ids** (from `state.unlockedTech`), not `research_*` ids from `docs/database/research_catalog.md`. Table above = mapping. Supported keys: `"tech": [id, ...]` (all must be present), `"outpost_count": N` (`len(state.planet.outposts) >= N`). `"plant_recipes": N` (`len(state.planet.plants.discoveredRecipes) >= N`). `"buildings": {typeId: N, ...}` (each type's count in `state.machines[*].typeId` >= N; finished machines only; pending `constructionBlueprints` and `isUnderConstruction` machines not counted). `"buildings_any": {typeId: N, ...}` (OR-group: at least one listed type's count >= N; used for "any Mining Drill variant"). Map-deployed buildings (drills included) appear in `state.machines` like any other machine, so both building keys see them; entries still `isUnderConstruction` are **not** counted (only finished deployments). TP-threshold criteria not supported (no TP field known in save state).

**Active-tier resolution**: fully automatic, per-save. `scripts_sync.py` derives sibling save-state file from save-scripts dir name (`save_X_scripts/` → `save_X.json`, one level up), reads `state.unlockedTech` / `state.planet.outposts` **read-only**, walks numerically sorted tier list evaluating `.criteria` until one fails. Highest passing tier = active. No hint file, no manual bookkeeping. `--force-tier NAME` overrides for one run, persists nothing. **Assumes monotonic unlocks**: walk stops at first tier whose `.criteria` unmet, so ancestor criteria implicitly required. Out-of-order save (higher tier's `.criteria` satisfied before lower one's) not handled specially. Not expected (techs never "unlearned"), but assumption flagged.

**No duplicate files across tiers**: for given `category/base_name` (incl. `lib` category), resolver walks from active tier down to `0_cold_boot`, uses first file found. Higher tier needs own copy only when behavior genuinely diverges.

**lib/ from `4_controlpanel` on = every module of every tier** (`lib_chain()`, `LIB_UNLOCK_TIER_NUMBER = 4`): after the active tier's chain, the resolver also walks every HIGHER tier (ascending). A module defined at or below the active tier resolves through the normal chain, so a higher tier's override of an existing module stays gated (none today). A module that only exists in a higher tier is deployed anyway (idle until its machines exist) — so entrypoints never need a per-tier copy just to import a newer lib (e.g. the Mixer gate idles inside the single `orchestrator_automation.py`). Pyright's `.pyright-resolved/lib` uses the same chain.

### Global categories, role slots, orphans

**Global (untiered) categories**: category dir directly under `scripts/` (sibling of tier dirs, e.g. `scripts/contract/`) not gated by any `.criteria`. Always included, merged on top of active tier resolution (`list_global_categories`/`resolve_global_category` in `scripts_sync.py`). Contracts live here: genuinely tech-independent, self-contained (no imports), available from very first save, not tied to any progression tier.

**`panel` and `automation` = role-matched slot types** (`ROLE_MATCHED` in `scripts_sync.py`). Sources at `scripts/4_controlpanel/control_panel/<role>_panel.py` (Control Room cards) and `scripts/4_controlpanel/automation/<role>_automation.py` (Computer > Automations): separate, genuinely different hand-authored scripts (§7), not interchangeable template copies. The game picks `panel_N` / `automation_N` slot numbers per save and can't rename them, so a live slot is paired with its source by role (`role_for_slot()`), in this order: (1) `# ct-<type>: <role>` marker in the slot's code (`_<type>` suffix optional; every source carries it on line 1, so every filled slot has it); (2) slot's first comment line equal to a source's first comment line after the marker (bridges slots filled before markers existed); (3) an **empty** slot takes the one role no other slot of its type holds yet. Several unpaired roles → skipped with a warning; type `# ct-<type>: <role>` into the slot in game to choose. A marker naming no source is reported, not guessed past. Role-matched slots are never staged to `_unmatched/`. A role source is any resolved script whose stem ends in `_<type>`. An automation slot is a top-level `automation_N.py` in the save folder, listed in the workspace's `context.automations`; `"action": "run"` restarts it like any slot. Deleting a panel/automation in game keeps its `.py` file and its code (Scripts > Unassigned) but drops it from `context.customPanels`/`context.automations`; such a slot is skipped and holds no role (`unassigned_slot()`).

**Orphaned slots** (`sweep_orphans()`, every `once`/`watch` pass and the `watch` 5 s poll): the game never deletes a slot's `.py` file. A slot whose machine was sold/decommissioned, or whose panel/automation was deleted for good, leaves `context.scripts` and is listed in `abandonedPaths` of the save folder's `codeterraform-scripts.json`. A file that matches both is moved to `devtools/.sync-backups/orphans/<save>/` (never deleted), so it is not pushed and does not clutter the save. A slot's file is its workspace `name`, which can differ from its id (contract `contract_lattice` → `lattice.py`; `slot_scripts()`/`slot_id()`, the external-command channel takes the id); a stray `<id>.py` next to such a slot is moved too. A blank file staged in `scripts/_unmatched/` for a slot that is gone is dropped. Unassigned panels/automations (still in `context.scripts`) stay. `status` lists what the next sync would move.

### Pyright and autoplay

**Pyright/IntelliSense**: `pyrightconfig.json`'s `extraPaths` point at `.pyright-resolved/lib` (regenerate with `.venv/Scripts/python.exe devtools/scripts_sync.py resolve-preview`, gitignored) plus `.pyright-resolved/stubs`, a copy of the save's game-API stubs. The copy drops the game's `isinstance`/`issubclass`/`callable` declarations (`NARROWING_BUILTIN_DEF`): they are plain `-> bool` functions that would hide typeshed's and disable Pyright's type narrowing. Game-injected per-script `self`/`panel` stay undeclared, so Pyright reports them as undefined in entrypoint scripts. Modules that only exist in a higher tier resolve too from `2_libunlock` on (`lib_chain()`); only a higher tier's *override* of an existing module needs `resolve-preview --force-tier <name>` to preview. Game's own in-editor syntax highlighting/autocomplete (tied to `codeterraform-workspace.json`) doesn't apply to source outside save folder at all → check deployed copy in save folder when needed.

**Autoplay** (`--include-autoplay` on `status`/`once`/`watch`/`register-libs`/`apply-libs`): `merge_autoplay()` adds `autoplay/*.py` to the script index and `autoplay/lib/*.py` to the lib index, untiered; a key `scripts/` already resolves stays with `scripts/` (reported as an `AUTOPLAY` conflict). Off by default, so the planner never ships by accident. Merged only from `4_controlpanel` on: before the lib tier the game refuses Libraries (`research_required`). Its entrypoint is the Automation role `infra_planner_automation` (`# ct-automation: infra_planner_automation`): create an Automation in game; an empty slot takes it when it is the only unpaired role, else type the marker into it. Runs without the flag leave deployed autoplay files alone (no match = no push). Below the lib tier (e.g. a snapshot restored from before it), deployed lib modules that don't resolve move to `.sync-backups/orphans/<save>/lib/` (`retire_stale_libs()`).

### Library registration, push and restart

**Library registration hook** (`register_new_libraries()`, runs after every lib mirror in `once`/`watch`; standalone `python devtools/scripts_sync.py register-libs [--dry-run]`): a file written into the save's `lib/` is **not** seen by the game until it is registered as a Library (manually: Computer → Library → + New, same name — the game then picks up the file on disk). The hook does the same as VS Code's **Import File as Game Library**: `action: "create-library"` with `name` (module stem) and `source` over the external-command channel (§8: `.codeterraform/command.json` + `command.lock` + `command-result.json`, `session` from `codeterraform-workspace.json`), for every deployed module missing from `context.libraryScripts`. Needs the game running with the save open; otherwise it warns and the next sync retries. `duplicate_name` counts as already registered. Source limit 200,000 chars (`interpreter.maxSourceLength`). It only registers new modules; applying a *changed* registered lib still needs the in-game "Apply & restart all" (§8).

**Push + restart** (`once`/`watch`, `sync_file()`): every save slot with a match is overwritten with its resolved source (placeholders rendered, own id renumbered) whenever the two differ; old copy backed up to `devtools/.sync-backups/`. In-game edits to a matched slot are therefore reverted — edit in `scripts/`. A slot with code and no match is left alone; an empty one with no match is staged to `scripts/_unmatched/`. After a write, `restart_in_game()` sends `"action": "run"` (§8) with the new source if the slot's live `status` (fleet file, see Run status) is `running` or the slot was just filled from empty; retries `RESTART_RETRY_DELAYS_S = (0.5, 1.0, 2.0)` (~3.5s) while the game hasn't registered a new slot yet. A `run` refused with `under_construction` (machine still being built; the game never starts a script on its own when the build finishes) or `offline` (machine unpowered, e.g. built before its power line; sync log only) is not retried there: the slot becomes a held restart, and `recover_scripts()` tries again every `CONSTRUCTION_RETRY_S = 15` s until it starts. An `offline` hold (`_OFFLINE_WAIT`, in memory) is dropped without a command once the slot reads `running`/`paused`: the panel's stray pass (§1d-2) or the `--early` starter got there first. **No restart when the script reaches an unapplied lib**: `libs_awaiting_apply()` = resolved `lib/` modules whose source differs from the game's `deployedSource` (or with no Library yet); `libs_reached()` walks the script's import closure (`lib_dependency_closure()`, `ast`-parsed). A hit is still pushed and held back (restarting it would run new script code against the stale cached lib). **`--apply-libs`** (`once`/`watch`; standalone `apply-libs [--dry-run]`): `apply_pending_libraries()` waits up to `APPLY_PICKUP_TIMEOUT_S = 15` s for the game's saved `source` to match each changed file, then sends one `apply-library` per lib in `apply_order()`: imported libs before their importers (the game restarts every running transitive importer at each apply, and the restarted script resolves its other imports against each Library's last applied source; `apply-all-libraries` would go in the game's registration order). A lib the game holds other source for (in-game edit, or file not picked up in time) is warned about, not applied, and neither is any lib importing it; a lib whose import failed to apply is skipped. An apply whose reply times out (`unconfirmed` after `COMMAND_RESULT_TIMEOUT_S = 20` s; seen on v0.1.34 for a lib with 205 importers) counts as applied once the workspace file lists its `deployedSource`, within `APPLY_CONFIRM_TIMEOUT_S = 90` s; otherwise the game counts as unreachable and the remaining libs wait. A `session_changed` reply while the workspace session is unchanged (the game read the request after its 15 s window) is resent once. The workspace file's `deployedSource` lags the game by minutes, so an `already_applied` answer counts as applied. **Stragglers** (`restart_stragglers()`): an apply silently skips any running importer the game's scheduler holds no loaded source for (seen live: 40 of 54 restarted, the orchestrator Automation left on the old lib). The game answers an apply only after its restarts ran; its `affected` counts every consumer it handled, paused ones included (a script on a switched-off machine, e.g. parked, reruns on the new lib at power-on). A lib whose `affected` covers all running and paused importers of it (`live_importers()`) with no `restartFailed` needs no check. Otherwise: before the applies the tool records each running importer's `runtimeRunSerial` (workspace file, bumped on every start, written behind the game); it polls up to `STRAGGLER_SETTLE_S = 30` s for the serials of the running importers reaching an unvouched lib to rise, and restarts (`restart_in_game()`) every one still `running` whose serial rose by fewer than the applied libs it reaches. An in-game Apply gets no such check. Off by default: an apply restarts every running importer. Without it, the operator presses in-game **Apply & restart all**. **Run status** (`live_slot_scripts()`): `status`/`errorLine`/`errorMessage` come from `codeterraform-fleet.json`, which the game rewrites within ~0.5 s of any change; `codeterraform-workspace.json` is rewritten only when a source or the save's structure changes, so its `status` can say `running` for minutes after a crash. **Recovery** (`recover_scripts()`, after every sync pass, for `RECOVER_SETTLE_S = 10` s after an apply, and on `watch`'s 5 s cycle): once every lib it reaches is applied, restarts a held-back slot (held slots persist per save in `devtools/.sync-backups/held_restarts.json`, so a later `once`/`watch`/`apply-libs` run restarts them after an in-game Apply; deleted slots are dropped), and any script with live `status == "error"` that this process pushed or that reaches a lib it wrote (e.g. an `ImportError` against a half-applied lib set), re-checking that status right before each restart so a script started meanwhile is not started twice. A script is restarted again only after its source or the applied libs change (`note_restart()` records source, apply generation and time); one still in `error` `RECOVER_REERROR_S = 3` s after that restart is reported once, not retried. Errors in scripts the tool never touched are left alone. `report_unapplied_libs()` prints the full list of affected save scripts once per change (`watch` re-checks every 5 s, so an in-game Apply clears it). `--no-restart` pushes only. **Log**: every line the tool prints is also appended, UTC-stamped like the game's `logs/` files, to `devtools/.sync-backups/sync.log` (rotated once at 2 MB into `sync.1.log`), plus debug lines for the apply order and why `recover_scripts()` left a script stopped (once per change). `status` shows per slot: up to date / would fill / would push, and blocking libs. **Hold** (`watch` only): while any hold file exists, `Watcher.drain()` queues every change (no push, restart or recovery); removing the last one pushes the whole batch in one rebuild. One file per holder, `devtools/.sync-backups/holds/<session id>` (`active_holds()`), so parallel sessions never release each other's hold; the legacy single file `devtools/.sync-backups/hold` still counts. Set and remove with `scripts_sync.py hold <id> [--note ...]` / `release <id>`, or plain `mkdir -p`/`date >`/`rm -f` on the file. `watch` names the holders on every change of the set and warns once about a hold older than `HOLD_STALE_S` (30 min), which still holds. Claude sets its hold before a multi-file or multi-step edit to `scripts/` and removes it once the files are consistent. A running `watch` picks up this rule only after a restart. Restarts are operator-invoked automation (the operator runs the tool), not Claude starting a live session; CLAUDE.md's Live Debugging rule binds Claude's own actions, so Claude still asks before running `once`/`watch` without `--no-restart`.

### Parameterized templates

**Parameterized templates** (`${VAR}` / `${VAR:default}` in source script): `sync_file()` detects via `find_placeholders()`, resolves each per save slot from: retired push-hauler `DESTINATION_OUTPOST_ID` re-homing (`rehome_retired_destination()`, §2f; beats the slot code and cache) → value the slot's current code holds at the placeholder's position (`infer_placeholders()`: template line → regex, placeholder → capture; an in-game edit wins and overwrites the cached answer) → cached answer (used when the template line changed so inference misses) → template default if the slot already has code (code predating a placeholder never set it) → interactive prompt (`typer.prompt`, blocking) for an empty slot. E.g. `scripts/4_controlpanel/pioneer/pioneer.py`'s `HOME_BASE`, asked once per slot (`pioneer_2.py`, `pioneer_3.py`, ... each independently) so operator sets where each specific Pioneer goes. Answers cached in `devtools/.sync-backups/script_params.json` (gitignored, keyed by `<save dir name>/<slot filename>`) → re-filling same slot doesn't re-ask. `--dry-run` never prompts or caches. Blocks under `watch` too, no skipping: filesystem observer runs on own thread, queues further events into `Watcher.pending`/`repo_due` while main thread waits on `input()`. Nothing lost, only delayed until answered (or `Ctrl-C`, still raises cleanly through `input()`). **Fleet-upgrade replacement drones never prompt** (`upgrade_fill_for()`/`inherit_placeholders()`): a `drone_*` slot named in `fleet.upgrade.lineage`, or a new drone slot whose machine `typeId` matches the single `announced`/`swapping` swap's `target_kind`, is filled with the old slot's cached answers → the old drone's archived `params` → template defaults, in every mode . Read from the save file (`read_save_state()` also returns `machine_types` and `fleet_upgrade`). A new `drone_*` slot whose machine isn't in the save yet is **held** (autosave lag) and retried every 5 s by `watch` (`HELD_SLOTS`); `once` reports it and fills on a later run. Wrong `typeId` (hand-deployed) → normal prompt. **FLEET Commission tab deploys never prompt either** (§2k-2): a `drone_*` slot whose `fleet.upgrade.lineage` entry has `job` (no `from`) is filled from its `params` (`HOME_DEPOT`); a `pioneer_*` slot named in `fleet.commission.lineage` gets `HOME_BASE` = its `home_base` (`commission_fill_for()`; `read_save_state()` also returns `fleet_commission`). A new `pioneer_*` slot is held while the save predates its machine, like a drone slot (the coordinator deploys in the same pass that leaves `buying`, so an older save can't show the job `deploying`).
