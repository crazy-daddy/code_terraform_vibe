### §1e Bio Luminizer Lamp-Mix Solve (`lib/bio_coastal.py` `BioLuminizerController`, `_solve_3x3()`)

Shared, biome-agnostic helpers referenced here (`_focus_local_order()`,
`_snapshot_property_count()`) live in `lib/bio.py` (§1g).

Tints coastal fragment glow to `BioOrder.target_glow` via `docs/components/bio_luminizer.md`'s
three lamps: `self.lamp_signature("red"/"green"/"blue")` each give fixed per-unit `[r,g,b]`
impurity, so lamp brightnesses `(r, g, b)` (each whole number 0-40) give
`glow = base + r*red_sig + g*green_sig + b*blue_sig`, where `base = self.glow()` read with all
lamps 0. Solving `(r, g, b)` for `target` = 3×3 linear system, `M @ [r,g,b] = target -
base` (`M`'s columns `red_sig`/`green_sig`/`blue_sig`) — no numpy, so `_solve_3x3()` inverts
via plain-Python closed-form Cramer's rule. Round to nearest int, clamp `[0, 40]`, verify against live `self.glow()` read; if rounding off by one, bounded ±1-per-channel
neighborhood search (≤27 `set_lamps()`/`glow()` round-trips) finds exact integer match. Fragment with no active coastal order needing it passes through unchanged via `self.discard()`.

**Key rules** (postmortems: `DESIGN_HISTORY.md`):
- **`exchange.active_order()` = shared, mutable, single-slot delivery-routing state — never use
  to look up "which order needs this fragment."** Use `_find_coastal_order()`/
  `_focus_local_order()` (scans `exchange.orders()` directly).
- **`set_order()`/`clear_order()`/`deliver()` are `*(self only)*` hardware calls** — script can't drive sibling machine. Other controller checking "does stack match order"
  must compare raw property directly (e.g. `list(stack.properties.get("glow", [])) ==
  list(order.target_glow)`), not call `matches_order()` remotely.
- **Staged sample may already be finished, not just raw** — `_order_matching_glow()`
  checks each staged stack, ejects (not reloads) one whose glow exactly
  matches live order's target; only stack matching no order's target treated raw and
  loaded. `_find_raw_stack()` applies same exact-glow exclusion when pulling from storage.

### §1f Raw-Specimen Backlog Control (`lib/bio.py`'s `BioCollectorController`/`BioLabController`, `lib/bio_coastal.py`'s `BioLuminizerController`)

Mechanism = **structural idle-gate**, not a numeric backlog cap (rejected alternatives:
`DESIGN_HISTORY.md`): `BioLabController` refuses to
pull next specimen from Collector, and refuses to drain own extracted output, until
local biome processor fully idle (chamber/input/output empty — `_processor_is_idle()`, §1g). Max one raw specimen in flight ahead of processor, so no Warehouse pileup structurally possible regardless of how broadly Collector searches for "needed" fragments.

- `BioCollectorController.step()` nets demand against per-cycle `_local_stock_snapshot()`,
  prefers `_focus_local_order()`'s fragments over other incomplete orders' when picking
  cataloged location to harvest, falls back to any other needed fragment if preferred
  order's not discoverable nearby — soft preference, not hard block.
- **No busy-polling**: `_processor_is_idle()`-gated consumers wait on `"biome_processor_heartbeat"`
  Signal Bus broadcast (every processor controller fires it unconditionally each cycle) via
  `comms.wait_broadcast(...)` instead of `sleep()`, fallback `sleep(0.5)` if `comms`
  unavailable or wait errors.
- **`BioLabController` gates *extraction* on demand too**, not just idle-gate: once specimen
  reaches `stage == "analyzed"`, `_bio_demand_totals(orders, my_biome)` (module-level,
  shared with Collector's demand computation; reads the outpost's own Exchange `orders()`,
  no Signal Bus) checked before loading reagents — if
  demand doesn't exceed local stock, `self.machine.discard()` runs instead of `extract()`.
  Unreadable orders (no Exchange, `orders()` raised) skip the gate.
  Lets "uncataloged discovery" harvesting (needs only analysis, not extraction) avoid
  spending reagents/storage on sample nothing would collect.
- **Self-cleaning backstop**: `BioExchangeController._cleanup_orphaned_artifacts()` runs every
  `sweep_and_deliver()` cycle after normal per-order delivery loop — any locally-staged
  bio sample whose item id not required by any incomplete order anywhere taken into
  `self.machine.input`, destroyed via `input.flush()`. "Bio sample" =
  `item_catalog.lookup(id).category == "biology_sample"` (`_is_bio_sample()`, cached per id in
  `_ITEM_CATEGORY_CACHE`; falls back to "has properties or some order requires it" only if
  catalog unavailable; Deep samples are propertyless, so a properties test alone misses them). Matches item id only (not exact glow), since not-yet-tinted raw sample never matches any order's `target_glow` and shouldn't be
  misclassified orphaned.
- `MAX_LOCAL_BIO_ARTIFACTS = 4` = coarse
  total-artifact safety net, on purpose, not primary mechanism: if sum of every
  currently-demanded fragment's local stock (`_total_demanded_artifacts(snapshot, fragment_ids)`)
  reaches this, `BioCollectorController.step()` pauses harvesting that cycle. Healthy
  pipeline stays 0-2, never trips.
- `best_unload_target()`'s Inventory fallback gated by `outpost.is_home` (plain `bool`
  attribute on `OutpostRef`, not method — `Outpost` component from `get_component()`
  has `is_home()` as *method* with same name; watch this trap) — remote (Warehouse-only)
  outpost's drain calls skip `"inventory"` target, return `None` (caller leaves stack
  staged, retries next cycle) rather than attempt connection that can't work.

### §1g Multi-Biome Bio Pipeline (`lib/bio.py` shared + `lib/bio_coastal.py`/`lib/bio_volcanic.py`/`lib/bio_deep.py`/`lib/bio_geothermal.py`)

Collector→Lab→(transform)→Exchange pipeline biome-agnostic in `lib/bio.py`; only transform step differs per biome, each own module subclassing `lib/bio_processor.py` `BioProcessorController` (shared sample loading, heartbeat, run loop; see §0 module map). `get_my_biome()` always reads `machine.outpost.biome` live, never hardcoded. `local_biome_processor(outpost)` probes which of `BIOME_PROCESSOR_TYPE_IDS = ["bio_luminizer", "bio_caster",
"bio_conditioner", "dna_sequencer"]` deployed there; returns `(None, None)` for Frozen (no transform step) or outpost without processor yet.

- **Generic idle-gate**: `_processor_is_idle(processor, processor_type)` dispatches on `processor_type`. `bio_luminizer`/`dna_sequencer` expose `.chamber`; `bio_caster`/`bio_conditioner` expose `.fragment()`.
- **Generic property matching, not just glow**: `_local_stock_snapshot()` second return = `by_properties: {(item_id, properties_key): count}` (`_properties_key()` canonicalizes any properties dict: sorted, list values tupled). `_order_target_properties(order, fragment_id)` resolves "already correctly processed for this order" per biome, the marker the Exchange checks: `{"glow": order.target_glow, "luminous": True}` (Coastal), `{"forged": True}` (Volcanic), `{"conditioned": True}` (Deep), `None` for Geothermal (spliced output carries `{"dnaSequence": <encoded strand>, "spliced": True}`, no gene list to compare, so spliced stock is not netted out). `_snapshot_property_count()` matches these as a subset: finished output keeps the raw sample's other properties.
- **Finished samples never go back into a processor**: `load()` refuses `luminous`/`forged`/`conditioned`/`spliced` samples with `not_in_input`. `BioProcessorController._classify_stack()` calls a stack carrying the controller's `FINISHED_MARKER` finished (Volcanic: any properties), whether or not an open order still wants it.
- **Leftover destruction** (`lib/bio_processor.py`): a finished stack is a leftover when no local order still takes it (`_order_takes()`: not `complete` and `requires − delivered > 0` for the fragment; Coastal also needs `target_glow` == its glow). An empty `orders()` list marks nothing as leftover. With no raw sample to load, `_stage_leftover()` takes one leftover stack from local storage into the processor's own `self.input`; the next cycle `self.input.flush()`es it (`_flush_leftovers()`), but only when every staged stack is a leftover. Otherwise the leftover is ejected back to storage. This also clears Geothermal overproduction once its order completes.
- `_focus_local_order()` also excludes Frozen orders outright (`order.biome == "frozen"`). Frozen has no single-slot processor bottleneck; Exchange blanket sweep already delivers plain fragment once extracted.
- **Bio Caster (Volcanic, `lib/bio_volcanic.py` `BioCasterController`)**: proportional heat/cool toward `required_range()` midpoint. Wanted rate = error / (`CASTER_CONVERGE_STEPS = 3` × measured step interval) × `SECONDS_PER_GAME_HOUR` + `CASTER_PASSIVE_COOL_C_PER_H = 20` feed-forward; knob % = rate / `CASTER_FULL_RATE_C_PER_H = 2400` (positive heat, negative cool, clamped 100, integer). Step interval = EMA (`CASTER_STEP_EMA_ALPHA = 0.5`) of clock-tick gaps between calls (`CLOCK_TICKS_PER_SECOND = 10`), starts `CASTER_STEP_SECONDS_DEFAULT = 1.0` s, sample clamped `CASTER_STEP_SECONDS_MIN = 0.5` s, gaps > `CASTER_STEP_SECONDS_MAX = 5` s ignored. Full knob = 96 °C/s (25 s game hour), so fixed-step bang-bang overshoots whole band. Casts when temperature in range AND `materials()` matches `required_materials()` exactly. **Unverified live**: assumes staging material into `self.input` via `take()` enough for `cast()` to auto-consume, same as Fabricator/Smelter recipe. Confirm with `debug()` output first real recipe run.
- **Bio Caster sample pick** (`bio.processor_fragment_preference()`): Caster `_load_next_sample()` and Collector harvest both rank fragments with it, so the Collector harvests what the Caster casts next (Lab follows Collector cargo). Order: Caster's selected `recipe()` first (repeat casts, no re-heat), then smallest gap between `temperature()` and the recipe's `temperature_range`. Collector keeps focus-order fragments before other orders' fragments; ranking applies inside each tier. Other processor types keep scan/`requires` order. Raw samples only: `_find_raw_stack()` skips property-tagged (forged) stacks; a forged stack found in `self.input` is ejected to `best_unload_target()` since `load()` rejects it with `not_in_input`.
- **Bio Caster staged surplus** (`_return_staged_surplus()`): with a fragment loaded, staged materials above `required_materials()` (or not in it) are ejected to `best_unload_target()` before staging/casting, since `cast()` needs an exact match. With the chamber empty, every staged material is ejected: the Lab hands over the next sample only when the caster input is empty (`bio._processor_is_idle()`). Staging holds while the caster output is not drained, and every take/eject on `self.input` is followed by `STAGE_SETTLE_TICKS = 20` ticks without further staging/ejecting, so an in-flight transfer is not counted twice. The settle wait and one-transfer-per-cycle rule apply to every processor's sample loading (`lib/bio_processor.py`), not only the caster's materials.
- **Propertyless stacks**: pass `properties=None` with `"exact"` to `take()`/`load()`/`eject()` for a stack without properties. `{}` + `"exact"` matches nothing and returns `source_empty`. Volcanic, Geothermal and Deep use `stack.properties or None`.
- **Bio Caster fluids**: `_ensure_fluid_inputs()` runs one `fluid_routing.FluidInputRouter` each for `steam_in` and `water_in` every step. Sources are `production.FLUID_SOURCE_TYPE_IDS` (steam: `thermal_cap`, `gas_tank`; water: `water_pump`, `steam_condenser`, `liquid_tank`, `bulk_liquid_reservoir`), network-wide, ranked by `fluid_routing.rank_sources()` ([power_fluids.md §1b](power_fluids.md)), tanks only when latched to the right fluid (`fluid_building_is_viable()`). Router constants match the Plant Terraformer's: `FLUID_STALL_STREAK_BLACKLIST_THRESHOLD = 5`, `FLUID_RESCAN_INTERVAL_TICKS = 150`, `FLUID_DISCOVERY_CACHE_INTERVAL_TICKS = 100`, `FLUID_NEUTRAL_GRACE_STEPS = 5`. `_set_knobs()` writes heat/cool only on change and holds a knob at 0 while its buffer is empty (`set_heat`/`set_cool` return `"empty"` otherwise).
- **Bio Caster material demand** (`BioCasterController._aggregate_material_demand()` / `_publish_material_demand()`): every `MATERIAL_PUBLISH_INTERVAL_TICKS = 600` ticks (60 s) the caster sums forge materials for **all** open local orders, not just the next cast. Recipes come from `find_recipe(fid).materials` (no fragment or analysis needed per docs; `None`/empty = skipped with a debug line). Each unit counted once:
  - casts per fragment = Σ orders `requires − delivered − in_transit` (game `in_transit` covers Exchange inputs + timed deliveries) − forged units in local storage (any property-tagged stack of the fragment) − forged units in caster output − 1 if in crucible.
  - need = casts × recipe materials + what the crucible's current cast still lacks − materials staged in `self.input`.
  - Published as requester `REQUESTER_ID = "bio_caster"` to `fabricator.orders` (one `production.set_order()` entry: the floor, the urgent amount − `logistics_requests.in_flight()` to this outpost = the current delivery, at the UPGRADE band, plus the rest of need − in-flight at the STOCK band: every open order, built in idle Fabricator time; all recipes share 7 materials, sized as `autoplay_roles.CASTER_STOCK_SLOTS`) (only Fabricator-buildable items; Fabricator compares against `total_stock()`, which excludes hauler cargo) and to `logistics.requests` at the caster's outpost (ladder `[[NEED, focus], [STOCK, qty]]`, `have` = local stock; the NEED level is what the current focus order — the delivery being worked on, same `_focus_local_order()` pick as Collector — still needs, capped by global casts, plus what the crucible's cast lacks; `publish_requests()`, §2i, so an item another requester owns there is left to it). Both cleared when need is empty. The Fabricator order is a heartbeat entry (`ORDER_STALE_TICKS`, archive_ipc.md `fabricator.orders`), republished every `MATERIAL_PUBLISH_INTERVAL_TICKS = 600`, so it lapses when no caster script runs (stopped, undeployed, no Bio Exchange); the logistics request lapses after `REQUEST_STALE_TICKS`.
- **DNA Sequencer (Geothermal, `lib/bio_geothermal.py` `DnaSequencerController`)**: fully spec'd, no live-verification gap. `order.required_genes[fragment_id]` = splice target, validated against `gene_catalog()` before `splice()` (unknown gene id risks `"destroyed"` result). `chamber.spliced == True` never spliced again ("one splice per fragment").
- **Bio Conditioner (Deep, `lib/bio_deep.py` `BioConditionerController`) — fully automated.** In-game docs never expose pass/fail rule for 10 QC properties; wrong `accept()`/`reject()` call `"burned"`s (destroys) specimen. Rulebook (`CONDITIONER_RULEBOOK` in `lib/bio_deep.py`) recovered from decompiled game client, cross-checked vs logged outcomes. See `DESIGN_HISTORY.md` for provenance:

  | Property | Pass rule |
  | --- | --- |
  | `glow` | `blue`, `green`, or `purple` |
  | `brightness` | 45–80 lm if `glow` `blue`/`green`; 20–50 lm if `glow` `purple`; else fail (incl. `white`/`dark`) |
  | `smell` | `salty` or `fishy` |
  | `gunk` | 70–85% |
  | `cracks` | `none` or `small` |
  | `feel` | `hard` |
  | `twitch` | `weak` or `still` |
  | `bugs` | 1–3 |
  | `weight` | 180–260 g, extended to 300 g if `gunk` ≥ 70 |
  | `sound` | `ding`; or `thud` only if `cracks` `none`/`small` |

  Every stage recorded to bounded `archive["bio.conditioner_observations"]` history (`CONDITIONER_OBSERVATION_HISTORY_LIMIT = 200`) for audit. Unrecognized `current()` property (rulebook stale) halts, no blind guess.
- **Confirmed live**: Conditioned fragment `.properties` carries `{'conditioned': True}`, distinct from untested raw fragment `properties=None`. `_find_raw_stack()`/`_load_next_sample()` skip/recover any stack with `properties.get("conditioned")` truthy, not treat as raw QC input.

### §1g-1 Bio Chain Completion: Retire a Biome's Chain (`lib/bio_retire.py`)

A biome's Bio Orders are the chain's only consumer. Their completion already cataloged every fragment and unlocked every feed recipe Wildlife needs. Once every order of a biome reads `status == "complete"`, that biome's Collectors, Labs, processors and Exchanges are sold.

- **Detection** (`BioRetirement.step()`, `orchestrator_automation.py` storage pass): `orders()` from any Bio Exchange, grouped by `order.biome`; a biome with ≥ 1 order and none incomplete is latched in `bio.retire["done"]` (§4, never removed, so it survives the sale of the last Exchange). Only Exchanges are discovered until some biome is done.
- **Drain, machine side** (self-only): every chain script's run loop calls `retire_pass()`; for a machine whose `outpost.biome` matches a done biome it runs `drain()` and waits `RETIRED_POLL_SECONDS = 5.0` instead of working. The script re-reads the done list at most every `RETIRE_CHECK_TICKS = 600` (60 s). `same_biome()`: equal or one name contains the other, like `is_local_order()`, but an empty biome never matches (never retires). `drain()`: Collector `discard()`s cargo; Lab `discard()`s the specimen (stages reagents) or `unload_reagents()`; Exchange `clear_order()`; Luminizer / DNA Sequencer `discard()`, Caster / Conditioner `eject()` the chamber; then input `eject()`ed and a non-empty output sent to local storage. Leftover samples land in Warehouses.
- **Sale**: each pass tries `computer.undeploy(id)` on every chain machine of a done biome and sells the kit (bio machines take no tier packs). Decompiled undeploy cargo check blocks on any bin item, Collector cargo, Lab specimen or loaded reagents, processor chamber, or a running action → `cargo_present`, retried next pass. Refused sales (`retired_machines.sell_kits()`) stay in `bio.retire["unsold"]` and are retried next pass, warning only the first time. A sold Lab clears its outpost's `bio_reagents` pull requests, a sold Caster its `bio_caster` ones; the Caster's Fabricator order lapses on its `ORDER_STALE_TICKS` heartbeat.

### §1h Essence Pipeline: Drone Depot → Essence Liquifier → Liquid Tank → Biomass Mixer (`lib/essence_liquifier.py`, `lib/biomass_mixer.py`, `lib/biomass_mixer_gate.py`)

Liquifier/Mixer controllers only wiring + feeding; the only production decision is the gate's pause/resume.

- **Liquifier feed**: item transfers explicit (`InputSlot.take()`), never passive. Depot's own `output.connect(liquifier)` (§2h) only declares link. `EssenceLiquifierController` points `.input` at same-outpost Drone Depot (`DRONE_DEPOT_TYPE_ID = "drone_station"`), reads stock via `depot.output.stacks()`, `take()`s only items where `nocturna.life_form_biome(item_id) == liquifier.biome()` (non-life-forms read `None`, never touched). Species already in bin tried first. Foreign-biome life form in Depot → one warning per item id (permanently uses Depot material slot). Tops up only when input has `FEED_MIN_ROOM_UNITS = 5` free, since `take()` blocks time proportional to units moved. **Request retention (§2i)**: a native item with `logistics_requests.retain_amount() > 0` is only fed from the Depot beyond what the local Warehouse stash still lacks (`retain - warehouse_stock`). `feed_from_warehouse()` (after the Depot feed) liquifies native life forms from the local Warehouse buffer (§2h) above their retain amount.
- **Liquifier drain**: single `<biome>_essence_out` port uses same `FluidOutputRouter` as Water Pump (§1c), with `fluid_id="<biome>_essence"` and `game_rules.LIQUID_TANK_TYPE_IDS`, so subject to `fluid_routing.tank_assignments` (§4). Empty new tank must be assigned to e.g. `"frozen_essence"` before any Liquifier uses it. Same constants as Pump (`ESSENCE_TANK_REBALANCE_FILL_FRACTION = 0.98`, `CONNECTION_GRACE_TICKS = 2`, `RESCAN_INTERVAL_TICKS = 300`, `DISCOVERY_CACHE_INTERVAL_TICKS = 100`). Router "blocked" input **not** raw `is_stalled()`: true for `stall_reason()` in `("output_full", "unconnected")` or when declared link `FluidConnection.state` broken. `"no_input"` (waiting for drones) excluded, else idle Liquifier blacklists good tank.
- **Mixer inputs**: one `EssenceInputRouter` per biome (`game_rules.BIOMES`), each a thin wrapper around the shared consumer-side `fluid_routing.FluidInputRouter` (§1b), `DISCOVERY_CACHE_INTERVAL_TICKS = 100`. Starvation is per port (not machine-wide `is_stalled()`): buffer < `STARVED_LEVEL_T = 1` t with `flow_rate() == 0` for `STALL_STREAK_THRESHOLD = 6` steps (~30 s) → source dropped + blacklisted, next candidate tried (catches a "ready" link to a dry remote Liquifier while a full tank sits unused). Port healthy if `port.connections()` has any peer in state `"local"`/`"ready"`, declared by either side. So Liquifier (or operator) already wired onto Mixer left alone. Else candidates: Liquid Tanks eligible for that essence and same-biome Liquifiers directly, ranked by `fluid_routing.rank_sources()` ([power_fluids.md §1b](power_fluids.md)). Reachability from `FluidConnection.state` (`fluid_routing.HEALTHY_CONNECTION_STATES` / `BROKEN_CONNECTION_STATES`), not Mixer's machine-wide `is_stalled()`. Broken link blacklisted immediately (`RESCAN_INTERVAL_TICKS = 300`, per-entry). `"neutral"` link (e.g. empty unlatched tank) gets `NEUTRAL_GRACE_STEPS = 6` steps, then dropped only if other untried candidate exists. Ports with no biome source anywhere stay quiet (debug only). Mixer warns once when `is_stalled()` starts (active < `required_essences()`), notes once on recovery.
- **Mixer math** (decompiled simworker `tickBiomassMixers()`/`mpe()`, `K7 = 1.5`): per game hour, mixing d balanced essences → `1.4 · d^1.5` t biomass, draining `4` t/h of **each** selected essence (Mk I; Mk II ×4.5 out, ×2.4 in). Biomass per ton essence = `0.35 · √d` (Mk II `0.656 · √d`), **independent of balance** — imbalance (`balanceFactor = min level / demand`) only cuts throughput, all selected essences drain by the same bottleneck amount. Mixer picks the d with the highest **rate** (`d^1.5 · balance`, phase minimum up to 5), not the best efficiency, so it runs degraded at d−1 when one buffer is dry.
- **Mixer gate** (`MixerGate`, called every `MIXER_GATE_TICK_INTERVAL = 10` ticks from `orchestrator_automation.py` at every tier; Mixer rediscovery every 300 ticks keeps it cheap while no Mixer exists): pauses Mixer via `power_control.set_powered(id, False)` (no `set_enabled()`; breaker-off also pauses the Mixer's own script, so it can't live in `lib/biomass_mixer.py`). Fluid still flows **into** an unpowered Mixer (simworker only requires the link's *source* to be powered), so buffers refill while paused. *Expected* essence = same-biome Liquifier exists on network AND `<biome>_essence_in` has a non-broken connection. RUN → PAUSE when any expected, non-given-up buffer < `PAUSE_LEVEL_T = 1.5` t. PAUSE → RUN when all ≥ `RESUME_LEVEL_T = 10` t. Escapes: buffer not rising by `PROGRESS_EPSILON_T = 0.05` t for `NO_PROGRESS_TICKS = 600` → that biome *given up*; `MAX_PAUSE_TICKS = 3000` or backpressure (buffer within `FULL_MARGIN_T = 1` t of capacity AND its Liquifier `stall_reason() == "output_full"`) → give up all still-waiting biomes. Given-up biome rejoins at ≥ `RESUME_LEVEL_T`. Mixers/Liquifiers rediscovered every `DISCOVERY_INTERVAL_TICKS = 300` (tick-based, not step-based — panel loop runs ~2–7 s/step), plus an early rescan when essence arrives on a linked input whose biome has no known Liquifier. Liquifier ids persisted in `biomass_mixer.gate_known_liquifiers` (first run baselines silently); a new one whose biome input is still unlinked holds that Mixer in RUN (resuming it if gate-paused) up to `REWIRE_HOLD_TICKS = 1200`, since the Mixer's own router is paused along with it. No gating while expected count < `required_essences()` (Mixer self-stalls anyway). Each pause is recorded in `script.parked` (mode `"mixer_gate"`, dropped on resume) so script parking never treats the dark Mixer as stray (§1d-2). Only switches ON a Mixer it switched off itself (`paused_by_gate`), never one in archive `power.shedded`; Mixer switched off/on externally is respected. State in `biomass_mixer.gate.<id>` (§4). ⚠️ If `orchestrator_automation.py` stops while a Mixer is gate-paused, the Mixer stays off until the gate runs again (it resumes from archive state) or the operator flips the breaker.

### §1h-1 Biomass Completion: Retire the Essence Chain (`lib/biomass_retire.py`)

Biomass pillar = fixed 100,000 TP; final phase "Full Biomass" at `BIOMASS_COMPLETE_T = 250000` t (decompiled sensor phase table: 0 / 250 / 2,000 / 10,000 / 60,000 / 250,000). Past it the pillar adds no Index, and no research is gated above 130,000 t. Essence feeds only the Mixer, the Mixer makes only biomass → whole chain obsolete. `biomass_complete()` = `biomass_sensor.get_value() >= BIOMASS_COMPLETE_T` (never flips back).

- **Stage 1, automatic.** Liquifier: no feeding; `retire_step()` `eject()`s the input bin to `best_unload_target()` (else a local Depot). Mixer script: routing stops. `orchestrator_automation.py`: Mixer gate stops; `BiomassRetirement.step()` (storage cadence, 100 ticks) registers every Mixer at once and each Liquifier once its input bin is empty in `machine.retired` (`"by": "biomass"`, `lib/retired_machines.py`; released on undeploy), then switches their breakers off, and publishes `biomass.retire` (§4).
- **Ready to undeploy** (decompiled undeploy cargo check): no items in any bin/stack. Fluid buffers don't block → Mixer always ready, Liquifier when `input.count() == 0`. Leftover essence is lost; essence tanks keep theirs.
- **Stage 2, automatic.** Same `BiomassRetirement.step()`, `sell_ready_machines()`: each ready machine → `computer.undeploy(id)` → sells the kit (`essence_liquifier` / `biomass_mixer`) and, for a Mk II Mixer, `biomass_mixer_upgrade_pack_mk2` (undeploy returns applied tier packs). Decompiled resale: deployable equipment and upgrade packs sell at full Shop cost (35,000 / 60,000 / 90,000 cr). Transient undeploy refusals (`inventory_full`, `cargo_present`, `docked_drone`) → retried next pass, listed as `refused` in the status. Refused sales (`retired_machines.sell_kits()`) stay in `biomass.retire["unsold"]`, retried next pass. Prunes the machines' `essence_liquifier.status` / `biomass_mixer.status` entries and `biomass_mixer.gate.<id>` keys.
- **Miner drones** (`drone_mining.py`): mixed-biome tiles allowed after completion, since nothing has to be liquified locally. Candidate order (`biosite_candidates`, sort key `(-band, -request_score, not partial, -buffer_need, distance)`): (0) highest request band of a requested form on the site (`network_band_deficits()`); (1) request score > 0 (a form some outpost requests, `network_deficits()`, weighted by `RARITY_REQUEST_WEIGHT`); (2) partly drained; (3) buffer need = forms on the site whose stock at the drone's home outpost (Warehouses + local Depot stockpiles, `_buffer_shortfalls()`) is below `lifeform_buffer_cap()`, weighted by `RARITY_REQUEST_WEIGHT` (common 1, uncommon 2, rare 4), so the fungus site (one per biome, 36 h regrowth) wins; (4) distance. Skipped only with no request, no buffer need, and not a partly drained site still holding a requested type (`active_requests()`, met or not — finished so its cooldown starts). `extract()` takes no species, so co-located forms already at buffer come home as well.
- **Life-form buffer**: life forms can't be sold (decompiled `not_sellable`, no sell value) and creature feeds (Wildlife) use all 30. Each outpost keeps `drone_depot.lifeform_buffer_cap()` = `LIFEFORM_BUFFER_SLOTS` (2) Warehouse slots per form, each filled to `storage.slot_fill()` (`WAREHOUSE_STOCK_TARGET`, 1,800; 3,600 units per form), filled by Depot staging and refilled by the drone buffer need above. Stored stock is never destroyed. The only destruction is the Depot's last-resort `flush_surplus()` (§2h): stockpile full, a drone waiting, the form's stash at cap and covering every request. The Waste Processor (`lib/waste_sink.py` `WasteSinkController`) destroys no items: outside a water drain (§1c) it is switched off and `eject()`s anything staged in its input back to local storage.

### §1i Seed Discovery Sweep (`lib/seed_maker.py` `SeedMakerController`, stage A)

Fair brute force (no save peeking). Facts it relies on (docs/components/seed_maker.md + decompiled recipe generator): 15 recipes (`SEED_SPECIES_TOTAL`), uniformly random over all C(30,3) = 4060 triples, **no biome structure**, each life form in at most `MAX_RECIPES_PER_FORM = 4` recipes. Every trial costs 1 t of each of the 3 forms (hit or sludge); a trial takes ~0.06 game-h (~15 ticks), so **life-form supply is the bottleneck**, not the machine. Expected full sweep ≈ 3770 trials ≈ 11.3k t life forms (offline sim with generator rules, saturation pruning included); hits evenly spaced (~254 trials apart), so the last species costs no more than the first.

- **Order doesn't matter for hit rate** → next triple chosen purely by local stock: open triple maximizing its scarcest member's stock (forms ranked by stock, smallest worst-index searched first), walked in `lib/atomic.py` chunks of `PICK_CHUNK = 150` checks (plain steps took ~19 ticks once the top triples were mostly tried). The tried mirror is re-read before each pick, and a lost claim re-picks in the same step (`CLAIM_ATTEMPTS = 4`): makers sharing the outpost otherwise all chase the same max-min triple. No need to gather all 30 forms first.
- **Saturation pruning**: forms already in 4 `recipes()` blends skipped entirely (every other triple with them is guaranteed sludge).
- **State**: `seed.combos_tried` `{"a,b,c": True | claim}` (§4) — name-keyed, never reset. Claim `{"by", "tick", "stage": "loading"|"running"}` expires after `SEED_CLAIM_STALE_TICKS = 3000`; claiming + marking via `archive.transaction()`, so several Seed Makers at one outpost can share it (one is enough). Hits are not stored — `recipes()` is the game's own journal; known blends get marked tried.
- **Restart recovery** (`_recover()`): wait while `is_running()`, drain output; chamber holding a known blend (in `recipes()`) → combined and drained (`_craft()`, not a trial); chamber holding a full open triple → re-combine; other chamber content → `eject()` to local storage; own `"running"` claim with empty chamber → trial finished → marked tried; own `"loading"` claim → released; own replacement claims → released.
- **Replacement seeds** (`_pick_replacement()`, before each pick): the Harvester's `plant.seed_demand["replace"]` `{seed_id: seeds still needed}` (§1k; slow starter crops held back until their seed is at home) is honoured while discovery runs. An entry is crafted from its known blend instead of the next trial when the blend is in `recipes()`, its 3 forms are in local stock, and home holds fewer seeds than asked (`stock_scan.held_units()`, same netting as stage B); largest ask first. Missing forms skip it this round (no extra request; discovery is not blocked). Stale demand (`SEED_DEMAND_STALE_TICKS`) or no `replace` field → no demand. Not a trial: the blend stays marked tried, `combos_tried` is untouched. Makers sharing an outpost claim one seed each in `seed.replace_claims` (§4) via `archive.transaction()`: a claim is won only while home seeds plus peers' live claims stay below the ask; dropped once the seed left the output bin (or the craft failed), expiring after `SEED_CLAIM_STALE_TICKS`. Costs 3 t life forms like a trial (cost/benefit: DESIGN_HISTORY §1i-1).
- **Loading**: first straight from a holder the last stock scan saw (`_load_direct()`, Inventory/Warehouse/Bin, no holder search), else `storage.take_item(input, form, 1, outpost=...)` (Warehouses + home Inventory), fallback local Drone Depot. Stage A keeps its scan between trials (each trial subtracts its 3 t), rescanning every `STOCK_REFRESH_TICKS = 300`, after a failed load, or while waiting for material. A `"busy"` Warehouse (one transfer at a time, makers share them) is retried `LOAD_BUSY_RETRIES = 4` times, `LOAD_BUSY_WAIT_S = 1.0` apart; any other load failure → eject chamber, release claim.
- **Requests**: recomputed every `REQUEST_REFRESH_TICKS = 1200` by one maker per outpost (`seed_maker.refresh`, §4; peers reuse its open-triple count, the refresh walks the whole tried dict, ~400 ticks on a ~1.3k-entry dict) (plus `REPUBLISH_TICKS` it must stay below `REQUEST_STALE_TICKS = 6000`, else requests blink out between refreshes; open-triple count is closed-form minus closed `_tried` entries — a full 4060-triple walk cost ~620 ticks/step), each form still in ≥1 open triple requested at `min(SEED_STASH_TARGET_T = 60, its open-triple count)` t (1 t per open triple it's in — big hauler batches early, no overstock near the end) via `logistics_requests.publish_requests(outpost, "seed_maker", ..., skip_foreign=False)` (§2i; seed forms take an item from the Feed Makers). Cleared at its outpost once all 15 known or no open triple left.
- **Output**: `drain_port_inventory_first()`: seed sent to `"inventory"` (planting starts there), a local Warehouse when Inventory is full.
- Telemetry `seed_maker.status` (§4): written when state or found count changes (`last` rides along), else at most every `STATUS_REFRESH_TICKS = 1200` (its tried count walks the whole tried dict, ~34 ticks per step when written every trial). Stage B: §1k.
