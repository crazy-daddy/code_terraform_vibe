# Fleet Lifecycle (§2b-1, §2b-2, §2f-1, §2k, §2k-2, §2k-4)

Part of [`AI_CHEATSHEET.md`](../AI_CHEATSHEET.md). Pioneer auto-upgrade and holder/rack split, dynamic Pioneer roles (refit and job switch), fleet hardware upgrade, commissioning and decommissioning. Surface vehicles in [`vehicles_drones.md`](vehicles_drones.md); drones in [`drones.md`](drones.md).

### §2b-1 Pioneer Auto-Upgrade (`lib/pioneer_upgrade.py` `PioneerUpgradeMixin`)

Auto hardware tier upgrades for Pioneer, checked once per idle-at-base cycle (`handle_upgrade_cycle_if_idle()`, called from same "parked at base, checking readiness" checkpoint every role loop has: `BuildJob._ready_at_base()` in `lib/job_build.py`, `SurveyJob.prepare()` in `lib/job_survey.py`, `MineJob.prepare()` in `lib/job_mine.py`, `PullJob.prepare()` in `lib/job_pull.py`; `Job.prepare()`/`SurveyJob.prepare()`/`MineJob.prepare()`/`PullJob.prepare()` gate with `getattr(host, ...)`).

- **Idle gate**: at base, empty cargo, no `mission`. `MineJob.prepare_cargo()` ends the step after a return-and-unload in both mining roles (Rover and stationed Miner), so the next cycle passes the gate before picking a target. At a recharge-and-resume base stop (`_recharge_and_resume_mining()`) `run_module_upgrades_mid_job()` swaps Sonar/Drill and runs the holder/rack split (§2b-2) (at base, empty cargo, claim still held) before that stop ends the job. Container tier steps wait for the idle gate.
- **Pioneer-only.** `docs/database/equipment_modules.md` documents Sport Nav, Wide/Deep Sonar, Industrial/Heavy Drill as Pioneer-universal-slot items — Rover's 3 fixed slots only accept basic `nav_module`/`sonar_module`/`drill_module` (§2b), so never better tier for it. `PioneerUpgradeMixin` mixed into `PioneerController` only, never shared `VehicleController` base.
- **Tier tables** (worst → best, all in `lib/item_tiers.py`, the one home of every hardware ladder; `tests/test_item_tiers.py` checks each against `docs/database/`, so a new game tier fails the suite until listed). `best_unlocked_tier()` only steps to immediate next tier present in fresh `shop.get_catalogue()` read, never straight to top, so one swap = one affordable purchase:
  - `SONAR_TIERS = ["sonar_module", "sonar_module_wide", "sonar_module_deep", "sonar_module_seismic"]`. Commission and the default auto ladder use `pioneer_upgrade.SONAR_UPGRADE_TIERS` (stops at Deep). `_sonar_ladder()` allows the Deep → Seismic step (7,500 cr) only while `_seismic_wanted()`: Petroleum Survey + Advanced Oil Extraction unlocked (`deep_oil.SEISMIC_RESEARCH_IDS`), `deep_oil.open_work()`, and no other Pioneer has Seismic mounted (`fleet.vehicles()` → each live `modules()`). A Seismic Pioneer keeps it (no swap back, so newly found formations never flip it).
- **Deep oil (`lib/deep_oil.py`, `vehicle_survey.deep_oil_targets()`)**: `RESERVOIRS_PER_MAP = 3` reservoirs hide under inert formations (`GeologicalAnomaly`, `kind() == "inert"`, ids `geological_anomaly_N`). Only a Seismic scan (both researches) sets `seismic_status` `"potential"` (a reservoir, certain) / `"dry"`; other tiers leave `"unscanned"`, so ordinary scouts never route there. A Seismic survey of a non-dry formation (0.5 h, 3 Wh) turns a reservoir into a rich 16 t/h Oil Well with the same id; a dry one is free. `prospect()` reads it all from journal sites: `found` = oil sites with a formation id, `remaining = 3 − found − potential`, `odds` = remaining / unscanned. `targets()` = potential + unscanned while `remaining > 0`. With Seismic mounted, `survey_known_pois()` adds these as a third candidate pool (key `site_<id>`); `scan_and_survey()` surveys every inert site in the sweep not known dry (the scan's site objects may predate the sweep's own status write).
  - `DRILL_TIERS = ["drill_module", "drill_module_industrial", "drill_module_heavy"]`
  - `BATTERY_HOLDER_TIERS = ["battery_holder_small", "battery_holder_medium", "battery_holder_large"]`
    (`_BAY_COUNTS`: 1/2/3 bays)
  - `CARGO_RACK_TIERS = ["cargo_rack_small", "cargo_rack_medium", "cargo_rack_large"]` (1/2/3 bays)
  - `PORTABLE_BATTERY_TIERS = ["portable_battery", "heavy_portable_battery"]` (50Wh/100Wh)
  - `PORTABLE_BIN_TIERS = ["portable_bin", "heavy_portable_bin"]` (25u/50u)
- **Credits**: every auto swap (module, holder/rack + bay fill, Heavy density top-up) goes through the cash manager, consumer `pioneer_upgrade:<name>` (§2l); a denied grant retries next idle cycle.
- **Swap ordering (`_upgrade_function_module()`/`_upgrade_containers()`)**: `unmount` old → `shop.buy` new → `mount` new → `shop.sell` old — deliberately holds old + new in Inventory briefly instead of selling first, so failed purchase rolls back clean (`mount(slot_index, old_id)` restores vehicle). Failure *after* buy (mount rejects, or container mid-sequence purchase runs out of credits) left as logged, non-destructive stop state for operator, not force-rolled-back — nothing silently lost, at most deferred one cycle.
- **Battery Holder swaps always recharge to ~100% first** (`_ensure_full_charge_for_sale()`) before uninstalling any Portable Battery — `shop.sell()` refunds battery's retained charge% with 50% floor (`docs/components/shop.md`), so full charge maximizes refund. Cargo Rack swaps skip this; Portable Bins not charge-valued.
- **Density policy**: every Battery Holder/Cargo Rack bay — newly added by size upgrade (`_fill_container_bays()`) or already installed at base tier (`_top_up_container_density()`, independent of any size upgrade that cycle) — gets **Heavy** Portable Battery/Bin once unlocked, falls back to base variant only while Heavy locked.
- **Sport Nav deliberately excluded from auto ladder** — manual one-shot operator action: `request_sport_nav(vehicle_name)` sets shared `{vehicle_name: True}` archive dict (`SPORT_NAV_REQUEST_KEY = "vehicle.sport_nav_request"`, same shape/rationale as `vehicle_claims.RECALL_KEY`), surfaced as the `+ Sport Nav` button in the detail pane of `vehicles_panel.py`'s FLEET card (Ground tab, selected Pioneer; `lib/vehicles_card.py`).
  `handle_sport_nav_request_if_active()` consumes it once idle at base, if `nav_module_sport` unlocked + affordable. Basic Nav is exclusive (`mount()` returns `capability_already_mounted` beside it); Sport Navs stack only with each other. So with Basic Nav mounted it swaps 1:1 in that slot via `_swap_function_module()` (unmount, buy, mount, sell old; remount on buy fail). Without Basic Nav, an extra Sport Nav goes into the first free `universal` slot. Request flag always clears after one attempt, success or fail — stuck request (no free slot, locked research, insufficient credits) no retry loop; operator clicks again when ready.

### §2b-2 Pioneer Holder/Rack Split (`lib/pioneer_split.py` math + `PioneerUpgradeMixin._rebalance_container_split()`)

A Pioneer with a Drill, or in the hauler role, splits its container slots (every mounted Battery Holder + Cargo Rack) between the two kinds for its own sites. Other roles keep their preset. Runs in `run_auto_upgrade_cycle()` (idle gate, §2b-1; a pull hauler passes it at the top of every `PullJob.prepare()` cycle), after the Sonar/Drill swaps and before the holder/rack tier steps, and in `run_module_upgrades_mid_job()` at every recharge-and-resume base stop. Only the split changes: function modules and slot count stay.

- **Miner sites** (`_split_sites()`, read from `journal.surveyed_sites()` every cycle, so new sites count): mineral sites with hardness ≤ mounted drill whose nearest outpost is home (`outpost_mining.nearest_outpost_id()`). Per site: `fixed_wh` = 2 × distance from `get_home_slot_coords()` × empty Wh/m at `cruise_throttle` (§2a model, live active-module count); `wh_per_unit` = `mine_wh_per_unit(ore, purity)` + distance × extra Wh/m of one carried unit.
- **Hauler sites** (`_haul_split_sites()`, every cycle): every place `pull_plan.pull_sources()` can fetch from, stock or not, rated from the `HOME_BASE` outpost (not the floating base, §2f, so the split does not churn between trips): every other outpost and every Mining Drill on a surveyed site (`drill_sites.drill_positions()`), minus those `logistics_requests.drone_served_source()` leaves to drones. Salt pumps and the Shop are left out. Per source: `drive_wh` = 2 × distance × empty Wh/m; `wh_per_unit` = distance × extra Wh/m of one carried unit; `fixed_wh` = `drive_wh`, or only the empty way back (distance × empty Wh/m) when the source outpost has a charging station (`pull_from_source()` recharges there after loading). Each trip is modelled as one stop, full racks.
- **Capacities** are rated at the best tier of each kind (top tier in the Shop catalogue, else best mounted): Wh per holder = bays × portable Wh, units per rack = bays × bin units (`PORTABLE_CAPACITY`: 50/100 Wh, 25/50 u; bays `_BAY_COUNTS`).
- **Units per trip** (`units_per_trip()`) = min(rack room, `((holders × Wh − MIN_EMERGENCY_RESERVE_WH) / SAFETY_MARGIN_MULTIPLIER − fixed_wh) // wh_per_unit`), the same budget as `max_mineable_units()`, from a full battery.
- **Objective** (`split_cost()`, sites as `(fixed_wh, wh_per_unit[, drive_wh])`, `drive_wh` defaulting to `fixed_wh`): (sites no unit reaches, mean `drive_wh / units_per_trip` over the rest), lower wins. Drive Wh per delivered unit; dig Wh per unit is the same for every split, and drive time scales with drive Wh, so this also minimizes drive time per unit. `best_holder_count()` tries 1..slots−1 holders; ties go to more holders.
- **Hysteresis**: converts only when the best split reaches more sites, or the current one pays ≥ `SPLIT_MIN_GAIN = 1.15` × the best one's drive Wh/unit.
- **Conversion**: the surplus kind, lowest tier first, one slot at a time through `_swap_container()` (empty bays sold, old container sold, best-tier new container bought and mounted, bays filled with Heavy portable once unlocked). Holders → racks first charges to full (`_ensure_full_charge_for_sale()`). Each slot asks the cash manager (consumer `pioneer_upgrade:<name>`, §2l); a denied grant stops the pass, next idle cycle continues. Shop sells parts back at full price (batteries by charge, §2b-1), so a conversion costs only the price difference.

### §2f-1 Dynamic Pioneer Roles: Refit and Job Switch (`lib/role_demand.py`, `lib/pioneer_refit.py`, `PioneerController.next_job()`)

An idle Pioneer refits to a role that wants more vehicles instead of being sold. Parts:

- **Role demand** (`role_demand.publish()`, `orchestrator_automation.py` every `ROLE_DEMAND_TICK_INTERVAL = 600` ticks, one `PlanReads` per pass): `fleet.role_demand` (archive_ipc.md) holds per role `band` (highest priority band of its open work, `lib/priority.py`; 0 = none), `wanted` (Pioneers the work can use) and `keep` (the floor a refit away stops at).
  - hauler: per founded outpost `outpost_tier_deficits()`; `band` = the highest top band, `wanted` = outposts at that band, `keep = KEEP_HAULERS = 1`. `drones` = drones carry the freight (`drone_yield_enabled()` and `drone_haulers_present()`): `wanted` capped at `SALT_HAULERS = 2` (pump salt; the deficits count drone-servable sources too).
  - builder: pending and paused construction jobs whose kind no fresh `construction.hold` holds; `band = BUILD`, `wanted` = jobs capped at `MAX_BUILDERS = 2`, `keep = KEEP_BUILDERS = 1` always (one stands by for the next blueprint).
  - scout: `NEED` while `autoplay.survey_requests` has a request, `STOCK` for unscanned POIs or unsurveyed sites neither blocked nor biomass (`survey_requests.scout_work()`; deep-oil formations excluded, a refit stops at Deep Sonar); `wanted` 1 while any, else 0; `keep` 1 while any work or any unscanned POI that is not known biomass is left (research-blocked and out-of-reach ones count, `scout_work()`'s third count), so one scout stands by until the survey is complete.
  - miner: no refit into miners yet (`band`/`wanted` 0); `keep` = founded outposts with a Smelter.
- **Role slots** (`fleet.role_claims`, `fleet_claims_common.try_claim()`, stale after `CLAIM_STALE_TICKS`): every Pioneer holds one `"<role>:<i>"` slot of its role, claimed at `run()` below `MAX_ROLE_SLOTS = 16` and renewed every `ROLE_SLOT_REFRESH_TICKS = 3000` from `next_job()`, so the fresh slot count of a role is its head count. A switch claims a slot `i < wanted`: two idle Pioneers never take one opening. `publish()` drops stale slots and the slots of Pioneers without a `fleet.status` entry (`drop_gone()`).
- **Job switch** (`PioneerController.next_job()`, every loop cycle): keeps the job unless the Pioneer has published an `IDLE*` state for `REFIT_IDLE_TICKS = 3000` (`READY_*`/`SURVEY_COMPLETE` are between-trip states, not idle; a scout with nothing left to scan publishes `IDLE_SURVEY_COMPLETE`, `SurveyJob.idle()`), its last refit attempt is `REFIT_COOLDOWN_TICKS = 12000` old, its cargo is empty, it holds no mission and is not recalled. Candidates (`role_demand.switch_candidates()`), best band first: none while its own role is at or under `keep`; else roles with a band above its own (any band when its own role has none) and `wanted` above their slot count; a role whose preset has a locked part (`refit_spec()` None) is skipped for the next. A demand record older than `ROLE_DEMAND_STALE_TICKS = 3000` counts as none. A Pioneer whose role has no work at all joins the haulers, over their `wanted` and also with no hauler work: hauler is the fallback role (refit, never sell; autoplay sells the surplus). With `drones` on the hauler entry the fallback only fills haulers up to `SALT_HAULERS` (head count), and builders never take it: autoplay sells the builders above `keep`. An idle hauler with nothing better stays a hauler. A parked Pioneer runs `next_job()` on its script-parking re-check (`script_parking.WAKE_AFTER_TICKS["pioneer"]`).
- **Refit** (`PioneerRefitMixin.refit(role)`, inside a `swallowed()` guard in `next_job()`): `build_spec()` for the role's preset (§2k-2); a Shop must exist; park in a service area; top the battery off (`_ensure_full_charge_for_sale()`) and park again; `plan_refit()` keeps per part category as many mounted modules as the preset has, best tier first (a lower tier stays, the upgrade cycle re-tiers it; a Seismic Sonar counts as the best sonar; the Nav Module always stays) and sells the rest per slot (`vehicle_recall.sell_slot()`: bays, then the module; a refused sale fails too; `not_at_service_point` parks again once). Abort before any sale: the base is restored, the role unchanged. A failure part-way fits the old role's preset back from what is left, through the same job path. Then a `fleet.commission` job `refit_<id>_<tick>` in state `fitting` with a lineage entry is advanced by `fleet_commission.py` every pass, apart from the one Pioneer commission it works at a time, and buys the missing parts as for a new Pioneer, and `fit_loadout()` fits them. Fitting blocks until every part is in; the job cannot be cancelled. Its buys use the cash consumer `pioneer_refit`, which may spend into the reserve other capital consumers leave (production_logistics.md §2l). A non-hauler moves its base back to `HOME_BASE`. Fitted but its job cannot run (a scout without Sonar): the Pioneer hauls. A restart mid-refit resumes the fitting (`fit_commissioned_loadout()`).
  - **Service area** (`in_service_area()`): the outpost footprint padded `SERVICE_PAD_M = 2` m: `x` in `[ox - 2, ox + 22)`, `y` in `[oy - 22, oy + 2)` from `outpost.coords()` (`FOOTPRINT_M = 20`). Farther than `FOOTPRINT_M` from its base, the Pioneer first moves its base to the nearest founded outpost, then calls `return_to_base()` up to `SERVICE_PARK_TRIES = 3` times.
  - **Name**: renamed to `commission_name()` for the new role only while its name is one the code gave or the game's id (`is_code_name()`); an operator's name stays.
- **Role names**: the Constructor role is `builder` (shorter display names: `H_builder_14`). `pioneer_commission.ROLE_ALIASES` maps the former `constructor` for archive jobs and lineage written before (`canonical_role()`), and a Pioneer renames a code-given `X_constructor_N` to `X_builder_N` at script start (`migrate_role_name()`).
- **Work queue**: the FLEET card's Roles tab (`vehicles_panel.py`, `lib/roles_card.py`) lists `fleet.role_demand` per role, highest band first: band, fresh slots held / `wanted`, `keep`; the detail pane shows the role's outposts by band and the Pioneers holding its slots. Read-only.
- **Autoplay**: no scout retire rule; idle scouts and builders refit, hauler being the fallback. Haulers retire only above `max(MAX_PIONEER_HAULERS, hauler wanted)`. Once drone yield is on and a hauler drone flies: haulers above `SALT_PIONEER_HAULERS` (pump salt), builders above `max(keep, wanted)`, and with both salt haulers there, scouts above `max(keep, wanted)` (the last one once the survey is complete) (autoplay.md §11l "fleet"). Miners keep their retire rules until Stage 3 (`docs/plans/dynamic_roles/README.md`).

### §2k Fleet Hardware Upgrade (`lib/fleet_upgrade.py` coordinator + `lib/drone_upgrade.py` drone side)

Background task in headless `builder_automation.py` (every `FLEET_TICK_INTERVAL`, panels.md §7), **gated by `upgrades_active()`** = operator switch on AND mining-drill phase reached (`upgrade_phase_reached()`: any mining drill on a surveyed site per `drill_sites.drill_positions()`, same condition as `4_controlpanel/.criteria`; stored once as `fleet.upgrade["phase_reached"]`, monotonic) — earlier, expanding beats upgrading. Switch off → swaps not started yet (Depot `ordered`; drone `ordered`/`requested`/`ready`/`announced`) are cancelled, a parked drone resumes work, orders withdrawn; swaps past the point of no return still finish. In-place module upkeep obeys the same gate. Upgrades Drone Depots in place and swaps miner/hauler drones for the **best unlocked tier** (Fabricator recipe unlocked, or item already in Inventory). **One swap at a time fleet-wide, Depots first**; within a kind the **lowest tier first** (small → large directly; Medium only deployed while Large is locked). Scouts never touched (chassis or modules). Operator switch + status line on the FLEET card's Drones tab (`vehicles_panel.py`) (`fleet.upgrade["enabled"]`, default on). All state in one archive dict `fleet.upgrade` (layout in `drone_upgrade.py`, plus `phase_reached`); each coordinator pass advances at most one state and writes back → restart-safe. Drone undeploy refused `MAX_UNDEPLOY_ATTEMPTS = 5` times → entry `blocked`, drone back in service (operator deletes the entry to retry).

- **Depot upgrade** (in place, game build e1986ce): `ordered` (kit → `fabricator.orders` at `UPGRADE`, wait for it in Inventory) → `computer.upgrade(kit, depot)` → done. The Depot keeps its id, name, stockpile, script, home pins and docked drones (the game only swaps the typeId and raises `bays`/stack slots); the old kit returns to Inventory. `DEPOT_UPGRADE_WAIT_STATUSES` (`not_enough_power`, `under_construction`, `inventory_full`, `item_not_in_inventory`) wait and retry; any other refusal → `blocked`. A Depot already at the target size (upgraded by hand; the game would answer `wrong_machine_type`) or gone → entry dropped. A legacy deploy/drain/undeploy swap entry is dropped with `retiring_depots`.
- **Drone swap**: `ordered` (chassis → `fabricator.orders` entry) → `requested` → drone answers at the top of its loop (`handle_upgrade_request_if_active()`, after recall): finishes cargo/claimed target first, charges to `UPGRADE_MIN_SOC = 0.98` at its drone_service, docks at its home Depot, writes `ready` + its script variables (`params`: `HOME_DEPOT` override) and holds (`UPGRADE_HOLD`) → `announced` (waits `ANNOUNCE_SAVE_WAIT_TICKS = 1800` so the announcement reaches the save file before the new slot exists — autosave ~30 s real) → `swapping` (re-verify docked at a Depot + cargo 0 via `fleet.drones()`/`get_component(id).cargo`; stop, undeploy → modules back to Inventory; `deploy(chassis, outpost)` or adopt a new drone of that kind not in the pre-swap snapshot; write `lineage[new_id] = {from, role, engine, kind, params, fitted: False}`; move `drone.home_depots` pin, drop `drone.recall`/`drone.mission`/`fleet.status`/upgrade-order entries of the old id) → `attach` (start retried until `fleet.status[new]` appears) → `fitting` → done when `lineage[new].fitted`, then `computer.rename(new, old display name)` (`old_name`, captured at `ordered`). Candidates need role `miner`/`hauler` in `fleet.status` (published from `DroneController.role`) and a heartbeat ≤ `DRONE_ALIVE_TICKS = 600` old.
- **New chassis fitting** (`fit_loadout_if_new()`, `DroneController.run()` loops it every 30 s **before** `detect_role()`, which refuses a bare drone): couples thruster (slot 0, from `lineage.engine`), then `FIT_LOADOUTS[role][kind]` from Inventory, best tier present; empty slots ordered. `fitted` once thruster + energy + (extractor for miner / Bio Scanner for scout / Cargo Pod for hauler / Shield Plating and Cargo Pod for aftermath). Replacement drones also inherit `params` for any script variable left at `None` (`inherited_params()`), so a hand-pasted default script behaves like the old drone.
- **`LOADOUTS`** (one category per module slot; energy = `battery_pack` electric / best `oil_tank_*` heli; cargo = best `cargo_pod_*`; role = `portable_bio_extractor` (miner) / `shield_plating` (aftermath)): miner small `role, energy` · medium `role, energy, cargo` · large `role, energy, cargo, cargo, cargo`; hauler small `energy, cargo` · medium `energy, cargo, cargo` · large `energy, cargo, cargo, cargo, cargo`; aftermath medium `role, energy, cargo` · large `role, energy, cargo, cargo, cargo` (no small: no slot left for a Cargo Pod). One `energy` is the minimum: **`fit_slot_plan()`** adds energy slots (beside the first, each replacing the last `cargo`, keeping one) until `drone_energy.energy_modules_needed()` reaches **`TARGET_RANGE_M = 4000`** m (`loadout_range_m()`: capacity × `LAUNCH_MIN_SOC` − reserve, full throttle, × `SAFETY_MARGIN_MULTIPLIER`, plated burn for aftermath; capacities in `ENERGY_MODULE_CAPACITY`). Result: 1 Battery Pack (plated too), 2 Small Oil Tanks, 1 Medium/Large. Commission specs, new-chassis fit and upkeep all use it; heli conversion couples only that many tanks. **`FIT_LOADOUTS`** = `LOADOUTS` + scout (role = `portable_bio_scanner`): small `role, energy` · medium `role, energy, energy` · large `role` + 4× `energy`; used only for commission specs and first fit, so scouts are never upgraded or topped up. Module slots (small 2, medium 3, large 5) come from `drone.modules()`.
- **In-place module upkeep** (`maintain_modules_at_depot()`, right after a successful unload while docked and empty — `drone_hauler.deliver()`, `drone_cargo.unload_and_leave()`): Cargo Pod / Oil Tank → better unlocked tier once in Inventory (else ordered under the drone's id); then energy modules beyond `TARGET_RANGE_M` go back to Inventory, smallest first (`_surplus_energy_slots()`; a stripped slot's pending tier order is dropped); empty slots filled with whatever category `LOADOUTS` still lacks. **Engine type changes only electric → heli**, two ways, both gated on `heli_ready()` (`research_heli_drones` done, Heli Thruster and some Oil Tank craftable or in Inventory, some drone_service `service_can_refuel()`): (1) the Drones tab "-> heli" button (`fleet.upgrade["heli_requests"]`, cleared on retire) makes `convert_to_heli_if_requested()`, at the start of the same upkeep, swap the thruster and every Battery Pack for the best Oil Tank in Inventory, ordering missing parts under the drone's id meanwhile; (2) the "heli on unlock" switch (`fleet.upgrade["heli_on_unlock"]`, off by default) makes `commission_engine()` answer "heli" for new commissions (`build_drone_spec(engine=)`) and chassis swaps (`fleet_upgrade`), which `fit_loadout_if_new()` then fits heli. Existing drones never convert on their own. Old thrusters and packs return to Inventory; `FLEET_PART_KEEP` parks the surplus in a Warehouse. Slot contents come from `drone.modules()` (`_read_slots()`: `{index: module_id | None}`, 0 = thruster); `couple()`/`uncouple()` update it within the same call, so nothing is stored.
- **Drone hardware stays in Inventory**: `storage.INVENTORY_ONLY_ITEM_IDS` (Depot kits, Service Station kit, chassis, thrusters, pods, tanks, battery pack, bio modules, plating) are never warehoused and are reclaimed if found in a Warehouse — `deploy()`/`couple()` take from Inventory only.
- **Script attach**: scripts can't attach scripts (`run_control.apply_variant()` needs an operator-saved variant, and variants don't carry across drone sizes — TODO.md). `devtools/scripts_sync.py` fills the new slot (§9: replacement and commissioned drones get their params without prompting); the coordinator's `run_control.start()` retry starts it even without `--auto`.

### §2k-2 Fleet Commissioning (`lib/fleet_commission.py` coordinator + `lib/pioneer_commission.py` Pioneer side + `lib/drone_commission.py` drone presets)

Operator-triggered launch of new Pioneers and drones. The FLEET card's Commission tab (`vehicles_panel.py`, `lib/commission_card.py`, §7) queues a job per click; headless `builder_automation.py` runs `FleetCommissionCoordinator.step()` every `FLEET_TICK_INTERVAL`, and every pass (`FAST_SLEEP_S = 1.0` s apart, storage swaps skipped) while `commission_fast()` holds: a head job in its kind's `FAST_STATES` (Pioneer `queued`/`deploying`/`attach`; drone also `fitting`). The card logs each order and cancel at info level (`[COMMISSION] Ordered d<N>: ...`). Autobuild queues Pioneers only (`early_buyer`, `production_logistics.md` §2m). Each job carries `prio`, the order-book band of its kit (`job_prio()`, `lib/priority.py`): `MANUAL` for a card click (also jobs without the field), `BUILD` for autobuild. Automatic fleet upgrades order through their own requesters at `UPGRADE`. No gate beyond `version_mismatch()` (the whole automation block).

- **State**: one archive dict `fleet.commission` = `{jobs: [...], lineage: {vehicle_id: ...}, target_home, drone_outpost, status, seq}` (layout in `pioneer_commission.py`). Jobs carry `kind` (`pioneer`, the default for jobs without one, or `drone`; ids `p<seq>`/`d<seq>`). Per kind the head job = first not `blocked`; one Pioneer job and one drone job are worked per pass, each advanced until a state waits (unchanged or `blocked`), at most `MAX_ADVANCES_PER_PASS = 5`, written back after every state → restart-safe; a drone whose kit is already in Inventory goes `queued` → `attach` (script started) in one pass.
- **Pioneers are deployed at their `home_base` outpost** (`computer.deploy("pioneer", home_base)`; build e1986ce places it inside that outpost, fitting happens there). The card's `home:` picker (`target_home`, None = home) sets the job's `home_base`, which also becomes the new Pioneer's `HOME_BASE` (§2f/§2g: every role works for its HOME_BASE).
- **Pioneer states**: `queued` (spec from `PIONEER_PRESETS` at the best unlocked tier of each part, fresh Shop catalogue; a locked part → `blocked`) → `buying` (the chassis kit alone, once the cash manager grants it, consumer `pioneer_commission`, §2l, planned against the whole job's cost; parts follow after the deploy, so a nearly full Inventory doesn't stall the job) → `deploying` (Pioneer id snapshot stored first, next pass adopts a new id not in it or calls `computer.deploy("pioneer")` at home; `deploy_limit`/`location_not_found`/`not_deployable`/`locked`/`wrong_biome_for_machine` → `blocked`, `no_kit` → back to `buying`; writes `lineage[new_id] = {role, job, spec, home_base, fitted: False, missing: {}}`) → `attach` (`run_control.start()` retried until `fleet.status[new_id]` appears or lineage says fitted; `devtools/scripts_sync.py` fills the new `pioneer_N` slot with `HOME_BASE` from the lineage, §9) → `fitting` (the Pioneer takes each part from Inventory as it lands; the coordinator buys `lineage.missing` in batches clipped to `inventory.space_for()`, Inventory full → waits, each batch under its own grant; after a buy it waits `FIT_SETTLE_PASSES = 2` more fitting passes (`lineage.passes` vs `job.bought_pass`) so a report from a pass that checked Inventory before the buy never buys twice) → done when `lineage.fitted` **and** the Pioneer's `fleet.status[new_id].home` (every vehicle publishes its `home_base`) is the job's home_base; a mismatch keeps the job open with "set HOME_BASE" in the status line.
- **Display name**: right after the deploy (or the adopt after a restart), `commission_name()` renames the new vehicle `<home tag>_<role>_<id number>`: `pioneer_14` mining for `outpost_3` becomes `O3_miner_14`, home is `H` (`H_hauler_5`). The id number keeps names unique. A refused `rename()` keeps the game's name (debug log only). Ids never change, so slots, claims and archive keys are unaffected. A drone swap (§2k) carries the name to the new chassis.
- **Drones are crafted** (Shop-only parts aside, see `crafting` below), and deployed at the outpost the card's `at` picker names (`drone_outpost`, None = home; only outposts with a Drone Depot are offered). That outpost becomes the drone's `HOME_DEPOT` (haulers still float between jobs, §2k). Roles `DRONE_ROLES` = hauler, miner, aftermath (scouts stay hand-built); engine `COMMISSION_ENGINE = "electric"`.
- **Drone states**: `queued` (`build_drone_spec()`: best chassis of `DRONE_CHASSIS_TIERS` the Fabricator can craft or Inventory holds, `electric_thruster`, one module per `FIT_LOADOUTS[role][chassis]` slot at its best obtainable tier (craftable, held, or sold by the Shop); nothing obtainable → `blocked`) → `crafting` (parts the Fabricator can't craft but the Shop sells go in `spec["buy"]` and are bought here first, through the cash manager, consumer `drone_commission`, §2l; the rest of the kit is a `fabricator.orders` entry at the job's band (`job_prio()`) under requester `COMMISSION_REQUESTER = "fleet_commission"`, listed in `production.STANDING_ORDER_REQUESTERS`; re-synced every pass from the crafting job, withdrawn when none. The same entry also orders the craftable kit parts of every drone job still `queued` behind the head job (`_backlog_parts()`, a spec built each pass) at `BACKLOG_PRIO = UPGRADE`, so the Fabricator works ahead while a kit is hauled and deployed) until Inventory holds all of it; parts a remote fab site built come home on site supply's home pull request (§2i-1 consumer site) and unload straight into Inventory (`storage.best_unload_target()`, §2c); the status splits `crafting (…)` (not built anywhere), `hauling home (…)` (`in_flight(home)`) and `built, awaiting haul home (…)` (`SourceCache.network_stock()` − Inventory, nothing in flight), and warns once per job after `HAUL_HOME_WARN_TICKS = REQUEST_STALE_TICKS` (6000) of the last case: home needs a Pioneer pull hauler based there or a Drone Depot for floating drone haulers → `deploying` (waits while a fleet_upgrade drone swap is `announced`/`swapping`, since both adopt "a new drone of this chassis"; drone id snapshot, then `computer.deploy(chassis, outpost)`; `drone_station_full` waits, `missing_drone_station` and the Pioneer blocking statuses → `blocked`, `no_kit` → back to `crafting`; writes `fleet.upgrade.lineage[new_id] = {from: None, job, role, engine, kind, params: {HOME_DEPOT}, fitted: False}`) → `attach` (as for Pioneers) → `fitting` (the drone couples its kit via the unchanged `fit_loadout_if_new()`, §2k; its `inherited_params()` give it `HOME_DEPOT` even with a default-filled script) → done when that lineage says fitted. fleet_upgrade's own swap adoption skips drones that already have a lineage entry.
- **`blocked`**: skipped by later passes; the card's cancel button drops it. Cancellable states `CANCELLABLE_STATES = ("queued", "buying", "crafting", "blocked")`. Bought or crafted parts stay in Inventory and are reused by the next job. A job whose deployed vehicle vanished (`attach`/`fitting`) → `blocked` (`vehicle gone`); Pioneer lineage without a live vehicle or job is pruned.
- **`PIONEER_PRESETS`** (one part category per chassis slot, mount order; tiers from `pioneer_upgrade.py` §2b-1, nav is always `nav_module`, Sport Nav stays manual): hauler `nav, battery×2, cargo×5` (a start only: §2b-2 re-splits it) · miner `nav, drill, battery×4, cargo×2` (a start only: §2b-2 re-splits it) · scout `nav, sonar, battery×6` · constructor `nav, constructor, battery×4, cargo×2` (early jobs carry 1–2 item kinds of ≤ 20 each, so range beats cargo). Bays get Heavy Portable Battery/Bin once unlocked, else the base one (same density policy as §2b-1). Role then follows from `detect_role()` (§2b).
- **Fitting (`LoadoutFittingMixin.fit_commissioned_loadout()`)**, first thing in `PioneerController.run()`, before `detect_role()`: no-op without a lineage entry or when fitted. `fit_loadout(spec)` publishes `FITTING`, then passes: mount each unmounted spec module into the first free slot (`capability_already_mounted` counts as mounted), then install the fill into every empty Battery Holder / Cargo Rack bay; after each call polls `modules()` up to `FIT_POLL_TRIES = 10` × `FIT_POLL_S = 0.5` s. A part not in Inventory → `lineage.missing` (coordinator buys it), and each pass bumps `lineage.passes`; `not_at_service_point` or a refusal → retry after `FIT_RETRY_S = 10` s. Done → `lineage.fitted = True`.
- **Rovers fit themselves too** (`RoverController.fit_rover_loadout()`, start of `run()`): each `ROVER_LOADOUT` kind (nav, sonar, drill) with no module of that kind mounted at any tier goes through the same `fit_loadout()`; parts come from `lib/early_buyer.py` (§2m) or the operator, never from the commission queue.
- **`pioneer`** (the chassis kit) is in `storage.INVENTORY_ONLY_ITEM_IDS` so the rebalance sweep never moves it out of Inventory before the deploy.

### §2k-4 Fleet Decommissioning (`lib/fleet_decommission.py` coordinator + prepare steps in `vehicle_recall.py` / `drone_claims.py`)

Operator-triggered retirement of a Pioneer, Rover or drone, never automatic. A **retire** button in the FLEET card's detail pane (Ground tab: selected Pioneer or Rover; Drones tab: selected drone not in a chassis swap, §2k) calls `request_decommission()`: entry `requested` + recall flag on. Pressing it again (label **cancel**) or switching recall off drops the entry and clears the recall. Both cards narrow the battery bar by the button width (`RETIRE_BTN_W = 64`) so the row fits.

- **State**: one archive dict `fleet.decommission` = `{machine_id: {kind: "pioneer"|"rover"|"drone", state, attempts, reason}}`. States `requested` → `ready` → gone; `blocked` after `MAX_UNDEPLOY_ATTEMPTS = 5` refused undeploys (recall cleared, machine back to work; retire again to retry).
- **Machine side** (`_prepare_decommission()`, called from `handle_recall_if_active()` once home): Pioneer at base unloads cargo (`unload_cargo()`, HOME_BASE), charges to `DECOMMISSION_MIN_SOC = 0.98` (Portable Batteries sell for their charge %, 50% floor), then strips itself (`_strip_and_sell_parts()`: each portable `uninstall()`ed, then its holder/rack `unmount()`ed, every part sold right after it lands in Inventory; the Nav Module stays mounted for `get_position()`/`is_at_base()` and is sold by the coordinator with the kit — `undeploy()` refuses with `inventory_full` when Inventory lacks a slot per returned part, e.g. 27 for a fully fitted Pioneer), then marks `ready`. A Rover does the same but skips the charge (integrated battery, no sale value). `shop.sell()` takes the lowest-indexed matching slot, so a spare of the same item may be the unit sold. Drone docked at its recall Depot unloads into it (`unload_cargo_at_depot()`), then marks `ready`. Cargo left aboard (storage full) → retried next cycle.
- **Coordinator** (`FleetDecommissionCoordinator.step()`, `builder_automation.py` every `FLEET_TICK_INTERVAL`): on `ready`, re-checks cargo 0 (drone: still docked at a Drone Depot; else back to `requested`), snapshots a vehicle's remaining parts (chassis kit from `VEHICLE_KIT_IDS` + the Nav Module + anything else the strip left), stops the script, `computer.undeploy()` (hardware → Inventory). Refused → script restarted, back to `requested`; `inventory_full` (`RETRY_STATUSES`) is not counted toward `MAX_UNDEPLOY_ATTEMPTS`.
- **After undeploy**: Pioneer/Rover parts sold at the Shop, each capped at its Inventory gain from the undeploy (spare stock of the same item is never sold). Drone chassis and modules stay in Inventory (not sellable; reused by commission/upgrade). Then the machine's archive state is dropped: `vehicle.recall`/`drone.recall`, `vehicle.mission`/`drone.mission`, `fleet.status`, `logistics.pickups`, `mining.reserved_yield`, `fabricator.orders[id]`; drone: `drone.home_depots` pin, Depot stage, `fleet.upgrade` `drones`/`lineage` entries; Pioneer: sport nav request, `fleet.commission` lineage. An entry whose machine vanished gets the same cleanup.
- `fleet_upgrade.py` never picks a drone with a decommission entry for a chassis swap.
