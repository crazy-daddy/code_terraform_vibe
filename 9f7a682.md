## 2. Interpreter changes: no script impact

Checked against `scripts/` and `autoplay/`:

- **Comparison and `__repr__` calls spread over ticks** (`sort`, `sorted`, `min`, `max`,
  `heapq`, `in`, `print` on your own objects). New `implicitCallMayEndTick()`: a new implicit
  call may end the tick once one call has finished in this slice and the step budget is used
  up. Never inside a synchronous callback (`suppressStepBudgetYields`/
  `synchronousCallbackDepth` > 0). We define no `__lt__`/`__eq__`/`__repr__`.
  **`lib/atomic.py` still holds.** Headless probe on 9f7a682 (sample save
  `20261008_7e5e168/1631_t2294802`):

  | Case | Ticks |
  | --- | --- |
  | 1,000-iteration loop, direct call | 7 |
  | Same loop inside one `map()` callback | 1 |
  | `sorted()` of 40 objects with `__lt__`, direct | 3 |
  | Same sort inside one `map()` callback | 1 |
  | `sorted(key=heavy)` over 40 items, direct | 6 |
  | Same sort inside one `map()` callback | 1 |
  | `sorted()` of 400 objects with `__lt__` inside one callback | `StepLimitError` (10,000 cap, as before) |

- `*`-unpacking your own object inside a `sort`/`map`/... callback no longer kills the
  script: we don't unpack objects with `*` in callbacks.
- `Counter`, `deque`, `OrderedDict`, dict, list search, `functools.cache`, `heapq`,
  `itertools`: Python-conformant when user code they call prints, pauses, raises or mutates.
  These are error-path and edge-case fixes (generators re-raise into the host iterator, the
  `dictionary mutated during iteration` error is new, `list.pop()`/`insert` check the argument
  before the length). Code that relied on the old lenient behavior now raises, as in CPython,
  where our unit tests already run it.
- `x in iterator` now consumes the items it checks, as in CPython.
- Slices: `LN` clamps the step to at least 2 instead of 1 (internal bound, no Python-visible
  change for valid slices).

## 3. API and docs changes

- [x] `Holder.index` (`self.battery.holders()`): the chassis mounting slot for
      `swap_batteries()`. We call neither `holders()` nor `swap_batteries()`.
- [x] Geothermal orders: only fragments listed in `BioOrder.required_genes` need splicing,
      and the others can be delivered raw. `lib/bio_geothermal.py` already splices only listed
      fragments and passes the rest through with `discard()`.
- [x] `run_control` from the Playground now really starts and stops scripts. Recovered edits no
      longer count as `editor_busy`. We call `run_control` only from machine and card scripts.
      Fewer `editor_busy` refusals can only help `fleet_upgrade`/`script_restart`.
- [x] `gps.planet().get_name()` and display names are localized now (new languages: Greek,
      Polish, Traditional Chinese). No script compares a display name, an item name or a recipe
      name with an English literal. Scripts use ids.
- [x] Renames: `vc_mandible_claw` is now shown as "Crab Pincer". Recipe display names say
      "Iron Ingot"/"Titanium Ingot". The ids are unchanged, and no script uses these names.
- [x] Variants: the new **⋯ > Update outdated copies** command (`applyVariantToScripts` mode
      `outdated`) updates only machines that already use the variant. UI only, with no script
      API.
- [x] External editing: a script's file must match the script name exactly, capitals included.
      The game now warns about a file whose name differs only in capitals. `scripts_sync.py`
      writes files under the exact script ids and never changes their case. The scripts
      folder also gets `ty` checker settings.
- `docs/database/` recipe and research diffs that flip `*(Not yet unlocked)*` to
  `*(Unlocked)*` come from the save the manual was exported from.
- Battery Charger is now tagged `consumer` in the power grid's `roles`; its draw was already
  modelled. No script reads `roles`.

## 4. Machine power datasheets

Every component page now gives exact power figures (draw while working, idle draw, and draw
per tier). Most of them replace "Variable".

- [x] **Bug (predates this build): `autoplay/lib/build_providers.py` `TIER_DRAW_FACTOR`**.
      The table says Mk II ×1.5 and Mk III ×3. The game multiplies the Mk I draw of
      `oxygen_generator`, `pressure_generator` and `temp_heater` by `[1, 5, 20, 100]` per tier
      (simworker `Tne` via `jg(tier, tierUpgrade)`). A second factor `yg[tierUpgrade]` (×1.5 at 1)
      exists, but nothing sets `tierUpgrade` above 0: a pack upgrade resets it to 0, and the
      live save has 92 machines, all at 0. The fe9a45c simworker has the same table. The new datasheets
      agree: O2 8/40/160/800 W, pressure 7/35/140/700 W. The upgrade `power_block` therefore
      underestimates the extra draw: Mk I→II as +4 W instead of +32 W (O2), and Mk II→III as
      +12 W instead of +120 W. Fix: `{1: 1.0, 2: 5.0, 3: 20.0, 4: 100.0}`. Also update
      cheatsheet/autoplay.md §11 (`GENERATOR_DRAW_W` / `TIER_DRAW_FACTOR` row) and
      `tests/test_build_providers.py`.
- Other figures worth checking against our assumptions when power work comes up: Fabricator
  Mk I 25-220 W (Mk II ×1.5, Mk III ×3), Smelter 20-45 W (same multipliers), Habitat
  40 W + 2 W per 1,000 individuals (cap 64 W; Mk II 144-168 W), Biomass Mixer 10 W + 8 W per
  non-empty essence input, Mining Drill 10/35/100 W only while mining (0 W with a full
  stockpile), pumps and Steam Condenser scale with throttle even when blocked, Drone Service
  Station 3 W + 30 W per charging bay + 20 W per rescue. Machines without a running script
  (generators) or with `enabled` off (Sprinkler, Grow Lamp, Plant Terraformer, Dispenser)
  draw 0 W. The Waste Processor still draws 5 W when disabled.
