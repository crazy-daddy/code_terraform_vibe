## 1. Fluid flow follows declared connections (not in the changelog)

`redistributePerFluidNetworks` was rewritten. Old: every source endpoint of a pipe network fed one
pool, and the pool went to every sink endpoint, except sinks that also held fluid (a non-empty
tank was never a sink). New: flow runs only along declared source→sink pairs (`port.connect()`
from either side), shared by max-flow over those edges (`Sbe`, `X0`). A tank that holds fluid is
now a sink too, so tank→tank chains and tanks on a shared pipe fill and drain at the same time.
A network is `stalled` when a source holds fluid but no edge moved any.

Caps, taps and pumps (`routeSourceToTarget`) are unchanged apart from helper renames.

## 3. `computer.upgrade(item_id, machine)` (Ship Computer research)

only for Drone Depots (`drone_station_kit_medium` from small, `drone_station_kit_large` from small
or medium). It keeps the id, name, cargo, scripts and connections and returns the old kit.
Outcomes: `ok`, `locked`, `not_upgrade_item`, `not_found`, `under_construction`, `not_at_outpost`,
`item_not_in_inventory`, `wrong_machine_type`, `tier_too_high`, `tier_not_ready`,
`not_enough_power`, `inventory_full`.
